# 实验大结果默认写外接盘

自 2026-10-08 用户授权起，后续 AI 新建实验的大结果优先写已经登记的外接盘。必须留本机的资料继续留本机。这个安排改变文件放在哪里，不改变策略、输入资格、实验预算、计算方法或交易授权。

“已冻结”是指某次实验已经把输入、方法和文件位置固定下来，后续要按同一份材料复现。不要为腾空间修改这类记录。

## 放置规则

| 内容 | 默认位置 | 处理要求 |
|---|---|---|
| 新实验的预测表、普通 CSV/JSON/Parquet/数组、图表、音视频和大型结果 | 已核外盘 `LeiSignal-新实验结果/<task-id>/<唯一运行>/result` | 开始前检查固定设备和内外盘余量；不得覆盖旧运行 |
| 新运行的临时普通文件和标准输出/错误日志 | 同一外盘运行目录 | 启动器将子进程临时目录和日志放外盘，不额外复制到本机 |
| 小报告、registry/INDEX、研究尝试记录与锁、定义和规则 | 项目既有位置 | 保持报告页面和实验接续；估计实际新增量，不能假设完全不占内盘 |
| 当前源码、Python/Node 环境、运行依赖、活动数据库、会话和工作树 | 本机 | 不因为大就迁移；不能把数据库、环境塞进普通结果目录 |
| 现有冻结 raw、合同绑定输入和已封存历史结果 | 原精确路径 | 不改名、不整批移走、不改指纹；归档副本不能代替原消费路径验收 |
| 已迁移并登记的媒体/固定模型 | `storage` 返回的可用只读路径 | 先核 `available=true`，重要复现按恢复清单核内容 |
| 确认闲置、无依赖且可恢复的普通文件 | 核验后的外盘归档 | 精确盘点、归档读回、源未变和无占用核对后，才移除本机副本 |

设备身份继续只读复用 `configs/storage-policy.v1.json`，不能仅凭卷名或目录存在判断。新输出规则在 `configs/research-output-policy.v1.json`。本机必须为小记录保留至少 5 GiB；外盘保留 10 GiB，并另外覆盖此次预计新增结果和日志。容量不足就拒绝新写入，不降低条件或回退本机。

## 后续 AI 的默认执行入口

所有后续 AI 调用本节列出的输出型实验入口时，默认经过统一启动器，省去手工选择内盘输出目录。启动器自动为原命令补外盘的新 `--out` / `--output`，原脚本内容和它们的科学检查保持原字节，避免破坏旧合同绑定的代码指纹。

从项目根执行（下面仅展示调用格式，不授权运行新研究）：

使用该实验原定的 Python 解释器调用统一入口，不为迁移换运行环境或重装依赖；示例中的 `python3` 需对应原实验环境。

```sh
PYTHONPATH=src python3 -m lei_signal.research.output_storage \
  --task <已登记任务编号> \
  --entry scripts/run_factor_lab.py \
  --estimated-bytes <预计外盘结果和日志总字节> \
  --internal-bytes <预计本机小记录新增字节> \
  --plan-only -- --workflow-contract <已授权合同路径>
```

先读取这次计划的真实路径和容量结果。确实获准执行该研究、计划通过后才执行；若已用该路径绑定原生 `--storage-plan`，保存标准输出 JSON，并在执行时同时指定 `--route-plan <这份路径计划>`、去掉 `--plan-only`，以免重新生成不同目录。只查看容量后重新生成新路径的普通调用可直接去掉 `--plan-only`。不要为测试存储而启动市场实验。启动器不增加科研权限，原合同/预算/来源检查仍由原入口执行。

| 原入口 | 覆盖范围 |
|---|---|
| `run_factor_lab.py` | 原输出型协议、benchmark、attribution、workflow draft/contract；只读声明审查直接用原入口 |
| `run_factor_library_v0.py` | `prepare` / `run` |
| `run_factor_evidence_reliability.py` | 原输出型协议 |
| `run_b1_dual_ma_description.py` | 原输出型协议 |
| `run_momentum_research_prototype.py` | 原输出型模式 |
| `run_research_data_snapshot.py` | `import` / `acquire`；`verify` / `diff` / `bind` 不强塞输出 |
| `prepare_momentum_qualified_inputs.py` | 新派生输入输出；仍保留原来源和资格语义 |
| `check_factor_unit_readiness.py` | 新资格包 |
| `check_research_input.py` | 新输入检查包 |
| `verify_research_definitions.py` | 新定义核对包 |

原生工作流的显式 `--storage-plan` 成果仍归原负责人维护。统一启动器不替代它的逐角色计划，也不修改其实现；如已采用该版本，应传入与本次实际目录绑定的有效计划，不能传旧输出路径的计划。需要准确预知输出时，先使用 `plan_output` 得到唯一计划，再把该 `plan` 传给 `execute_new`；不得重复生成另一份目录然后沿用旧绑定。

新手写实验在建目录前使用 `plan_output(root, task_id, estimated_bytes, internal_bytes=...)` 选择外盘新位置，并让具体写入程序核这个位置。没有登记的入口或固定输出路径的历史 raw 脚本会拒绝统一启动，先核其全部读写路径与负责人，再做独立新入口适配。不要猴子补丁全局文件写入，也不要用软链接搬整个 raw。

## 实际保护范围

- 不启动旧实验、不改正在运行进程的输出路径；此规则适用于之后的新调用。冻结复现命令和明确要求原路径的小记录继续沿用原安排。
- 原脚本直接调用仍遵循其原参数；本轮没有声称每一个历史脚本或第三方程序已自动改写。后续 AI 默认必须使用本说明，不能拿旧示例中的内盘大输出路径作为新默认。
- 启动器预检身份、路径和预计容量，使用外盘日志/临时目录，运行期间检查挂载/设备；断盘仅停止它刚启动的子进程，保留部分结果，不触碰其他实验或服务。
- 容量计划是估计，不是硬配额；外盘强制拔除仍有操作间的竞态，调用后的其他写入也可能使盘写满。失败保留现场，不把部分文件当成功结果，不在内盘补写大结果。
- 本机只新增小位置索引 `data/cache/research-output-index`；报告注册与科研账本保持原权威。启动器退出 0 仅说明子进程返回成功，不表示因子有效、研究已归档或全部结果已复核。
- 本规则不会自行删除缓存、设置保留期限、创建定时任务或恢复通知。

## 本轮验证位置

默认路径、错盘/无盘/不足、输出参数冲突、只读子命令和旧源码不变测试在 `tests/unit/test_research_output_storage.py`、`tests/integration/test_research_output_routing_cli.py`。真实设备容量与小文件验证以及本轮清理恢复清单保存在外盘个人资料归档第五批；不把私人原文件、数据库或大日志提交到 Git。
