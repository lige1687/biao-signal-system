# Agent 工作方式：按需执行与成本核对

2026-10-04，用户批准本项目采用。共同要求在根 AGENTS.md；本文件只在选择工作流、接续长任务或比较成本时读取。适用于读取本项目规则的模型，用户当次指令及现有权限边界优先。

## 1. 根据实际任务选择流程

| 当前任务 | 执行方式 | 必要交付 |
|---|---|---|
| 问答、翻译、润色、单次定位 | 当前聊天直接完成，不启动研究或设计流程 | 回答及需要的来源 |
| 方案已明确的局部修改 | 直接修改；仅有无法推断的关键缺口才提问 | 实际改动、相关验收、未验证项 |
| 长任务目标、预期效果或完成边界未定 | 先按下文逐步追问；必要时使用相关设计／规划技能 | 明确目标与验收边界；已有执行授权时转入执行 |
| 明确资料或数据研究 | 使用 research-closure 及对应项目研究入口，复用旧结论 | 约定的证据和归档；不得省略研究登记 |
| 跨阶段、会话或设备的长任务 | 复用一个任务进度文件；恢复先核对实际产物 | 当前状态、证据、阻塞与最小接续动作 |

brainstorming 的通用“所有项目都先批准设计”描述，在本项目按上表适用范围解释；用户已经给出的方案和授权不反复确认。隔离工作区沿用用户已有偏好与平台工具，仓库外写入、删除、强推等既有确认要求仍适用。仅因为某个技能可用，不启动无关的设计、审批、委派或报告流程。

### 长任务：逐步问透，再连续执行（2026-10-04 用户明确）

用户希望 AI 在长任务前主动追问目标、想要的效果及自己尚未想到的问题，问清完成边界后持续做下去，直到完成或真正受阻。适用于目标或取舍仍有关键缺口的长任务；已给清楚目标与验收的任务直接执行，普通问答和局部小改动不强制访谈。

1. **先掌握事实，再问决定。** 先读相关文件及已有决定，只把影响结果、范围、风险或验收且无法合理推断的问题交给用户。能自行查清的代码、现状、数据和工具事实由 AI 查；用户回答尚未到来时，不能把默认选项当作答案。
2. **一次一个关键问题，按回答推进。** 先问为什么做、希望使用后有什么变化，再逐步追问成功与失败例子、不同目标的取舍、使用情境、限制及不包含的内容。主动揭示盲点，不要求用户一次写完所有需求。每问附具体选项或推荐答案及理由，也说明代价；不诱导用户接受 AI 的偏好，不重复已解决的问题。
3. **问到足以行动即收束。** 明确最终交付、可核对的完成标准、允许范围、不可破坏的条件和真实暂停条件即可；预算沿用已有约定及实际限制，不擅自增加。不得为覆盖所有想象中的情况无限追问，也不得要求用户决定每个可逆的实现细节。效果含主观判断时说明哪些需用户验收，AI 自检不能代替用户认可。
4. **把问清的内容接到执行。** 用简短摘要保留上述约定，跨阶段任务复用现有进度文件。仍缺会改变方向、验收或权限的决定时，等用户回答；用户已有执行授权且关键问题已解决时，直接执行。只有讨论或方案授权时先交付讨论结果，不能把需求回答当成新增执行授权；不额外重复已完成的设计批准。
5. **持续核对，卡点只问缺口。** 每次准备结束前对照原完成标准；还有必要、已授权且可执行的工作就继续，包括等待必要结果、修复和验证。进度汇报后接着做；不以“下一步是……”代替执行，不自行降低验收标准。真正受阻时说明卡在哪、尝试及证据、需要用户补什么，并继续不依赖该缺口的已授权工作；得到回答后沿原目标恢复，不重开整轮访谈。

参考 grill-me 的需求追问思路；本项目采用用户要求的逐题推进方式。本轮核对的公开 grill-me 入口转到 grilling，当前公开版本按轮提问；它负责需求澄清，执行授权和持续目标仍按本项目约定。未安装外部技能，也不因引用它自动委派代理。来源：[grill-me 入口](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md)、[grilling 内容](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)。规则指导运行中的行为，跨轮自动续做另见第 3 节。

## 2. 控制进入上下文的内容

- 先定位目录、文件、关键词、字段和日期，再读取命中的相关内容；不要先把整仓库状态、全量日志或整份大表返回给模型。
- 原始数据保存在原位置，用本地计算完成筛选、合计和核对；返回必要结果、失败摘要及可定位的证据路径。不要把截断输出当成完整检查结果。
- 一个技能涉及多个工作流时，只读取该工作流需要的引用；已读内容和有效结论在本任务内复用。
- 策略相关改造仍须读取规定的权威源；精简一般流程不豁免策略、数据来源、研究合同、权限及冻结约束。
- 同一任务保留必要背景；转到独立任务时，只传目标、范围、已验证结果、输入位置和验收条件，不复制整段无关历史。

## 3. 让长任务有可以核对的终点

有清楚的最终结果，但实现路径需要多轮调查时，可以由用户明确设定 Codex Goal。设置前确认当前入口支持该功能，并写清结果、验证证据、允许范围、不能破坏的约束及真实阻塞条件。普通小任务不需要 Goal。

可复用的目标描述：

> 完成〔具体结果〕，以〔可检查的证据〕验收，使用〔允许的资料和工具〕并保留〔约束〕。每轮检查还缺什么，在授权范围内继续必要工作；只有完成验收、真实阻塞、实际预算／运行限制或我要求停止时结束，并保存未完成状态。

这是描述模板，不会创建 Goal。只有用户明确要求创建持续目标时才调用对应工具；不得把普通“继续执行”自动变成 Goal、定时任务或无限循环。Goal 的支持和实际续做能力需以当前工具结果验证，不能仅凭文档保证离线、额度耗尽或程序退出后仍运行。

## 4. 验证和成本按同一交付比较

沿用项目模型分工，用户指定优先。较低思考档位只有在任务边界清楚且有可靠验收时才适合比较；失败先定位原因，需要时再升级，不自动更换当前模型或购买额度。多代理必须有可独立交付的问题，总成本包括派发、上下文传递、复核、失败和返工。

验收证据覆盖当前改动且仍有效时复用；改动使其失效、新失败或具体风险出现时才重测。命令退出成功、代理自称完成和状态写入成功均不能代替读回实际结果。

需要比较费用时，在已有任务进度或研究记录附一小段，不为普通小任务新增成本文件：

| 同一任务／验收 | 模型及档位 | 合格完成数／尝试数 | 用量及计费依据 | 失败、重试、返工 | 总耗时 | 结论 |
|---|---|---|---|---|---|---|
| 填实际任务和证据 | 填实际执行设置 | 所有失败也计入尝试 | 可取得的输入、输出、缓存、思考用量；取不到写未知 | 填实际次数与原因 | 填实际值或未知 | 质量相当后再比较 |

真实费用可得时，按总费用除以合格完成数比较；套餐没有逐任务账单时，只报告可取得的用量、耗时与完成率，不伪造美元成本。字符、文件字节、回答长度和工具调用次数都是辅助指标，不直接等于 token 或费用。输入、缓存、输出、思考 token 不按同一价格相加冒充费用。

缓存或批量处理属于实际 API 接入层优化，只在接口、支持范围及计费口径核实后实施；普通 MD 指令不自动开启它们。此规则不授权付费实验、接入新服务、读取密钥或改变运行预算。
