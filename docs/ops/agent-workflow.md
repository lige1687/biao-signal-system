# Agent 工作方式：按需执行与成本核对

2026-10-04，用户批准本项目采用。共同要求在根 AGENTS.md；本文件只在选择工作流、接续长任务或比较成本时读取。适用于读取本项目规则的模型，用户当次指令及现有权限边界优先。

## 1. 根据实际任务选择流程

| 当前任务 | 执行方式 | 必要交付 |
|---|---|---|
| 问答、翻译、润色、单次定位 | 当前聊天直接完成，不启动研究或设计流程 | 回答及需要的来源 |
| 方案已明确的局部修改 | 直接修改；仅有无法推断的关键缺口才提问 | 实际改动、相关验收、未验证项 |
| 长任务目标、预期效果或完成边界未定 | 先按下文逐步追问；必要时使用相关设计／规划技能 | 明确目标与验收边界；已有执行授权时转入执行 |
| 明确资料或数据研究 | 使用 research-closure 及对应项目研究入口，复用旧结论 | 约定的证据和归档；不得省略研究登记 |
| 跨阶段、会话或设备的长任务 | 复用一个任务进度文件；恢复先核对实际产物 | 当前状态、证据、阻塞与最小接续动作 |

brainstorming 的通用“所有项目都先批准设计”描述，在本项目按上表适用范围解释；用户已经给出的方案和授权不反复确认。隔离工作区沿用用户已有偏好与平台工具，仓库外写入、删除、强推等既有确认要求仍适用。仅因为某个技能可用，不启动无关的设计、审批、委派或报告流程。

### 长任务：逐步问透，再连续执行（2026-10-04 用户明确）

用户希望 AI 在长任务前主动追问目标、想要的效果及自己尚未想到的问题，问清完成边界后持续做下去，直到完成或真正受阻。适用于目标或取舍仍有关键缺口的长任务；已给清楚目标与验收的任务直接执行，普通问答和局部小改动不强制访谈。

1. **先掌握事实，再问决定。** 先读相关文件及已有决定，只把影响结果、范围、风险或验收且无法合理推断的问题交给用户。能自行查清的代码、现状、数据和工具事实由 AI 查；用户回答尚未到来时，不能把默认选项当作答案。
2. **一次一个关键问题，按回答推进。** 先问为什么做、希望使用后有什么变化，再逐步追问成功与失败例子、不同目标的取舍、使用情境、限制及不包含的内容。主动揭示盲点，不要求用户一次写完所有需求。每问附具体选项或推荐答案及理由，也说明代价；不诱导用户接受 AI 的偏好，不重复已解决的问题。
3. **问到足以行动即收束。** 明确最终交付、可核对的完成标准、允许范围、不可破坏的条件和真实暂停条件即可；预算沿用已有约定及实际限制，不擅自增加。不得为覆盖所有想象中的情况无限追问，也不得要求用户决定每个可逆的实现细节。效果含主观判断时说明哪些需用户验收，AI 自检不能代替用户认可。
4. **把问清的内容接到执行。** 用简短摘要保留上述约定，跨阶段任务复用现有进度文件。仍缺会改变方向、验收或权限的决定时，等用户回答；用户已有执行授权且关键问题已解决时，直接执行。只有讨论或方案授权时先交付讨论结果，不能把需求回答当成新增执行授权；不额外重复已完成的设计批准。
5. **持续核对，卡点只问缺口。** 每次准备结束前对照原完成标准；还有必要、已授权且可执行的工作就继续，包括等待必要结果、修复和验证。进度汇报后接着做；不以“下一步是……”代替执行，不自行降低验收标准。真正受阻时说明卡在哪、尝试及证据、需要用户补什么，并继续不依赖该缺口的已授权工作；得到回答后沿原目标恢复，不重开整轮访谈。

参考 grill-me 的需求追问思路；本项目采用用户要求的逐题推进方式。本轮核对的公开 grill-me 入口转到 grilling，当前公开版本按轮提问；它负责需求澄清，执行授权和持续目标仍按本项目约定。未安装外部技能，也不因引用它自动委派代理。来源：[grill-me 入口](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md)、[grilling 内容](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)。规则指导运行中的行为，跨轮自动续做另见第 3 节。

### 目标、验收与停止：执行时怎样落实（2026-10-04）

适用于 Ray 及其他读取项目规则的 agent；不依赖某个模型名。长任务开工先在已有计划或任务记录写一句“用户最后能得到／做到什么”，注明已授权范围和不可破坏的条件，再把必需结果绑定到证据。需求已有明确答案时直接整理执行，不重开访谈；普通单轮小任务不强制建立文件。

| 必需结果／完成标准 | 怎样检查 | 证据位置或读回结果 | 状态 |
|---|---|---|---|
| 写具体可观察的效果，不只写“完成开发” | 写对应操作、核对或测试 | 写实际产物／输出路径、链接及结果；开始时可留待取得 | 待做／执行中／已验证／受阻／待用户验收 |

用户给出的完成标准保留原意；实现细节可自行调整，不能为了通过而删除失败项、缩减交付或改弱测试。标准确实需要改变时说明原因并取得用户决定；负面研究结论也可以完成，但必须交付约定证据，不能把任务偷偷换成更容易的问题。

执行时反复使用同一个判断：

1. 核对还缺哪些必需结果或证据，选择当前可执行的一项，完成操作并等到必要结果。
2. 读回实际结果。验证失败就保留失败位置、原因、退出状态及有关输出，定位后修复，再核对受影响项；不把“已启动”“已提交”或代理自述作为通过证据。复用仍覆盖当前改动的有效核查。
3. 还有已授权且能推进的必需工作就接着做，进度汇报后也继续；准备结束前再检查整份验收。全数满足才交付完成；主观效果或约定由用户确认的项目保留待用户验收，不代替用户确认。剩余用户决定可以是真实暂停条件，但须先做完不依赖它的必要工作。
4. 真正受阻时写清哪项未满足、具体失败证据、已尝试的合理办法、现有授权内为何无法绕开，以及用户最少补什么即可恢复。实际额度／运行限制及用户要求停止也可暂停，保存状态；复杂、耗时或不知道下一步先查什么不能单独作为停止理由。进程退出后的续做条件见第 3 节。

重要的用户操作改动，以实际使用路径验收。例如保存计划要核对输入、保存、重新打开及正确展示；只验证接口成功不能证明整条路径可用。文档修改、格式转换或与页面无关的小改动不强制浏览器流程。

写入超时、网络断开或响应失败后，先按目标位置／已取得的记录标识读回状态，再决定是否重试。确认已成功就复用结果；状态不明且重复执行可能新增记录、发送消息或产生其他副作用时，先解决状态缺口，不盲目重放。核对状态不扩大执行权限。

### 复用现有检查，保留可修复的反馈

按当前 checkout 实际存在的工具选检查，不把仓库不同分支的能力混为一谈：

| 约束或结果 | 现有检查入口 | 能证明的范围 |
|---|---|---|
| 提交是否混入其他任务、是否触碰冻结路径 | 核对本任务准确路径与 Git 差异清单；发布时只收录获准路径 | 路径核对属于人工／agent 核查，尚无统一自动拦截器 |
| 差异中的空白错误 | `git diff --check -- <本任务路径>`；发布提交另检查提交差异 | 只检查所选差异，不证明功能正确 |
| 文件归置 | 当前 checkout 有 `scripts/check_repo_hygiene.py` 时运行；按已有规约解释结果 | 检查目录白名单和特定跟踪项，不保证全部权限红线 |
| Python 代码质量及行为 | 按 `pyproject.toml` 复用 Ruff 和相关 pytest 检查 | 检查实际运行覆盖的代码；纯文档改动不额外跑全套代码测试 |
| 用户实际可见结果 | 相应操作的读回、界面使用或已有流程验证工具 | 核对本次完成标准；不能用静态检查替代 |

程序检查失败时保留检查名称、文件／行或验收项、实际错误和修复后结果，不能只返回“检查失败”。检查工具不支持的约束明确保留人工核对，不声称已强制执行。新增自动检查应针对已确认缺口单独实现和验证；本次复用检查流程，没有新增通用控制器、自动测试守护程序或模型行为评估。

采用依据：[长任务验收](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)、[实际结果评估](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)、[检查与修复](https://aider.chat/docs/usage/lint-test.html)、[程序约束](https://openai.com/index/harness-engineering/)。详细适用性审查在本地 `docs/experiments/agent-practices-community-increment-2026-10-04.md` 归档，未随规则发布；写入失败后读回是针对本项目副作用风险的适配判断。实际成功率和成本改善尚未测量。

### 同一份规则供不同 AI 入口使用（2026-10-04）

用户授权合入 main，并要求所有 AI 可用。根 AGENTS.md 是共同规则的唯一完整来源，入口按客户端而非模型名区分；客户端把规则载入上下文后，其所选模型沿用该上下文。适用范围是本仓库，不自动覆盖其他项目、普通网页聊天或未加载仓库规则的接口。

| 使用入口 | 仓库入口及条件 |
|---|---|
| Codex | 原生读取根 AGENTS.md；使用包含本次 main 更新的 checkout，覆盖文件和更具体的规则仍按客户端层级处理 |
| Claude Code | 根 CLAUDE.md 的 @AGENTS.md 导入共同规则；客户端须允许项目指令加载 |

| Gemini CLI | 项目 .gemini/settings.json 的 context.fileName 包含 AGENTS.md 和 GEMINI.md；保留默认 GEMINI.md 名称支持，只改变项目上下文发现，不改模型、权限或用户全局设置 |

其他设备、旧分支和已有会话先同步包含本轮修改的 main，再按客户端方式刷新或新建会话。可以用客户端的上下文列表、加载记录或可见的实际读文件结果核对；AI 自称“已加载”不作为唯一证据。仓库入口检查与逐客户端运行验证分开记录；本轮不启动付费模型任务，也不保证任何模型始终遵守指令。跨轮续做仍需第 3 节的持续目标或等效执行机制。

## 2. 控制进入上下文的内容

- 先定位目录、文件、关键词、字段和日期，再读取命中的相关内容；不要先把整仓库状态、全量日志或整份大表返回给模型。
- 原始数据保存在原位置，用本地计算完成筛选、合计和核对；返回必要结果、失败摘要及可定位的证据路径。不要把截断输出当成完整检查结果。
- 一个技能涉及多个工作流时，只读取该工作流需要的引用；已读内容和有效结论在本任务内复用。
- 策略相关改造仍须读取规定的权威源；精简一般流程不豁免策略、数据来源、研究合同、权限及冻结约束。
- 同一任务保留必要背景；转到独立任务时，只传目标、范围、已验证结果、输入位置和验收条件，不复制整段无关历史。

## 3. 让长任务有可以核对的终点

有清楚的最终结果，但实现路径需要多轮调查时，可以由用户明确设定 Codex Goal。设置前确认当前入口支持该功能，并写清结果、验证证据、允许范围、不能破坏的约束及真实阻塞条件。普通小任务不需要 Goal。

可复用的目标描述：

> 完成〔具体结果〕，以〔可检查的证据〕验收，使用〔允许的资料和工具〕并保留〔约束〕。每轮检查还缺什么，在授权范围内继续必要工作；只有完成验收、真实阻塞、实际预算／运行限制或我要求停止时结束，并保存未完成状态。

这是描述模板，不会创建 Goal。只有用户明确要求创建持续目标时才调用对应工具；不得把普通“继续执行”自动变成 Goal、定时任务或无限循环。Goal 的支持和实际续做能力需以当前工具结果验证，不能仅凭文档保证离线、额度耗尽或程序退出后仍运行。

## 4. 验证和成本按同一交付比较

沿用项目模型分工，用户指定优先。较低思考档位只有在任务边界清楚且有可靠验收时才适合比较；失败先定位原因，需要时再升级，不自动更换当前模型或购买额度。多代理必须有可独立交付的问题，总成本包括派发、上下文传递、复核、失败和返工。

验收证据覆盖当前改动且仍有效时复用；改动使其失效、新失败或具体风险出现时才重测。命令退出成功、代理自称完成和状态写入成功均不能代替读回实际结果。

需要比较费用时，在已有任务进度或研究记录附一小段，不为普通小任务新增成本文件：

| 同一任务／验收 | 模型及档位 | 合格完成数／尝试数 | 用量及计费依据 | 失败、重试、返工 | 总耗时 | 结论 |
|---|---|---|---|---|---|---|
| 填实际任务和证据 | 填实际执行设置 | 所有失败也计入尝试 | 可取得的输入、输出、缓存、思考用量；取不到写未知 | 填实际次数与原因 | 填实际值或未知 | 质量相当后再比较 |

真实费用可得时，按总费用除以合格完成数比较；套餐没有逐任务账单时，只报告可取得的用量、耗时与完成率，不伪造美元成本。字符、文件字节、回答长度和工具调用次数都是辅助指标，不直接等于 token 或费用。输入、缓存、输出、思考 token 不按同一价格相加冒充费用。

缓存或批量处理属于实际 API 接入层优化，只在接口、支持范围及计费口径核实后实施；普通 MD 指令不自动开启它们。此规则不授权付费实验、接入新服务、读取密钥或改变运行预算。

依据：[OpenAI 技能及提示词指导](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)、[Codex Goals](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)、[Anthropic 成本指导](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)。这些官方建议不能代替本项目真实任务的质量与费用核对。
