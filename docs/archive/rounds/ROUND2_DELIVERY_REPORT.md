## 4. 复核后语义收尾（逐条）

### 4.1 周线完成语义：从「下一根日线出现」改为「本周最后一个交易日收盘」

旧实现用「出现了下一周的日线才认为上周结束」规避完成判定，代价是周线**系统性延迟一个交易日**。
新增 `src/lei_signal/data/calendar.py`，用**交易所日历**（提前公布，属合法 point-in-time 信息）判定
「今天是否本周最后一个交易日」。

设计取舍已写入模块 docstring：默认 `WeekdayCalendar()` **不内置节假日表**。
内置一份手写节假日表一旦写错，会把「本周最后交易日」判早，导致周线在真正收盘前就被判完成——
那是**错误结论**，比「晚一天」严重得多。默认日历只假设周一至周五，宁可保守。

### 4.2 结构生命周期：完整状态链而非仅终态

`structure_lifecycle` 表此前只记录最终状态。收尾后记录完整迁移链，并按分支固化三条门禁：
完整链（candidate→confirmed→invalidated）日期精确、纯候选只有单条迁移、
候选期直接失效**不得**凭空补一条 confirmed。

### 4.3 事件生命周期字段真正落库

`valid_until` / `lifecycle_id` / `ended_event_id` 此前只存在于内存对象，未进 SQLite。
收尾后落库并有列级断言。

### 4.4 结束事件不得参与收益统计

`END_SUB_RULES`（生命周期结束事件）此前会被前瞻收益统计当成信号采样，
等于把「信号结束」也算了一次收益 —— 系统性污染。收尾后从 `build_forward_outcomes` 排除。

### 4.5 持久化失败必须可见

原实现对 `sqlite3.Error` 精确抑制，写库失败时界面**看不出任何异常**，用户以为数据已存。
收尾后 `analyze` 返回持久化状态标志：成功 `True` / 失败 `False` / 未请求 `None`，并在界面呈现。
三种状态各有独立测试。

### 4.6 界面口径对齐

- 结论区**分离**机会阶段与风险状态（此前混成一句）。
- 研究明细页**只展示方向调整后**的列（此前 bearish 信号展示原始 MFE/MAE，符号是反的，直接读会得到相反结论）。
- 阶段历史图同时承载机会与风险两条线。
- 研究页接入 `build_risk_transitions()`。

### 4.7 上传路径持久化

`_analyze_upload`（用户上传 CSV/Parquet）此前不写缓存也不写库。收尾后与主路径一致。

## 5. EMA20 早期转强「分档绑定」（本轮核心决策）

### 5.1 问题

第一版把 EMA20 早期转强**只绑定已确认结构**，候选结构上的转强被整段丢弃。
先量化再决策——8 个种子 × 800 根 K 线跑真实管线：

| 指标 | 实测值 |
|---|---|
| 结构总数 | 740 |
| **从未确认的结构** | **233（31.5%）** |
| 检测→确认滞后 | 中位 3 天 / 均值 6.5 天 / P90 18 天 |
| EMA20 × 已确认结构事件 | 5483 |
| **EMA20 × 候选结构（被丢弃）** | **437** |
| 放开后事件增量 | +8.0% |

即：近三分之一的结构永远等不到确认，其上的转强信息被无条件丢弃；
而已确认结构的确认本身平均滞后 6.5 天。**信息确实有价值，但不能直接当买入信号。**

### 5.2 采纳口径（用户决策）

> candidate 底部允许绑定 EMA20 早期转强，但只进入 `early_watch`，**不视为结构确认或买入信号**；
> 后续结构确认、共同确认、长周期改善沿用同一 `structure_id` 逐级升级。
> 触及 C 永久失效；转黑只关闭转强生命周期。

### 5.3 实现

新增 `src/lei_signal/rules/ema_reclaim_tiers.py`，四档单调阶梯：

| 档位 | 强度 | 严重度 | 是否买入信号 |
|---|---|---|---|
| `early_watch`（候选结构） | 35 | WATCH | **否** |
| `structure_confirmed` | 60 | IMPORTANT | 是 |
| `joint_confirmed` | 75 | IMPORTANT | 是 |
| `long_trend_improved` | 85 | CRITICAL | 是 |

同一观察实例共享一个 `lifecycle_id`，档位**只升不降不重复**；
升级事件与开启事件**共享同一 `valid_until`**（升级不得截断开启事件的有效窗口）。

### 5.4 顺手发现并堵掉的一个泄漏

阶段阶梯中 `EARLY_STRENGTH` **排在 `STRUCTURE_CONFIRMED` 之上**。
若 `early_watch` 沿用原有通路，未确认结构会被点亮成 `EARLY_STRENGTH`，
在界面上显示得**比已确认结构更高级** —— 与用户口径正相反。

修复：状态机拆出独立的 `early_watch_by_structure_day` 索引与 `per_structure_watch` 闩锁，
`early_watch` **只写理由、不抬阶段**。

### 5.5 研究层分档证据（合成数据 seed 303，仅证明分档必要性，非收益预测）

| 档位 | 20 日方向调整收益 | 样本 |
|---|---|---|
| `early_watch` | **−1.91%** | 41 |
| `joint_confirmed` | −0.71% | 27 |
| `structure_confirmed` | −0.15% | 275 |
| `long_trend_improved` | **+0.90%** | 297 |

`early_watch` 表现最差 —— 把它混进买入基线会直接拉低统计。分档存储是必要的，不是形式主义。

### 5.6 界面呈现

`early_watch` 刻意**不进**结构诊断的「✅成立 / ⚠️不成立」核对表：那张表读起来像「条件达成」。
改为单独的中性提示块（`st.info`，非 `st.success`），文案强制包含
「尚未确认」「不计入结构确认」「不构成买入信号」「不会抬升阶段」，
结构 ID 排序稳定以便复核。

## 6. 测试强度证明：变异测试

复核明确批评过第一版「测试太弱」。收尾阶段的判据因此不是「测试通过」，
而是**「把实现改错，测试是否会红」**。共 12 组变异，**全部被捕获**：

| # | 变异 | 结果 |
|---|---|---|
| M1 | 退回「只绑定已确认结构」 | 捕获 |
| M2 | 升级时重开 `lifecycle_id` | 捕获 |
| M3 | 允许档位降级/重复 | 捕获 |
| M4 | 去掉触及 C 的终止 | 捕获 |
| M5 | 转黑不再关闭转强生命周期 | 捕获 |
| M6 | 让 `early_watch` 抬升阶段 | 捕获 |
| M7 | 生命周期按事件而非按实例结束 | 捕获 |
| M8 | 界面 `info` 改 `success`（中性提示变成功态） | 捕获 |
| M9 | 删除空集早退（无观察档时仍渲染） | 捕获 |
| M10 | 去掉结构 ID 稳定排序 | 捕获 |
| M11 | 不过滤未激活结构 | 捕获 |
| M12 | 删除文案中「不构成买入信号」否定语 | 捕获 |

每组变异后源码均从备份还原，还原后 `diff` 校验为空。

另有 5 项语义不变量在 5 个种子上全量验证（0 违规）：
`early_watch` 只绑定未确认结构、同 `lifecycle_id` 档位严格单调且共享 `valid_until`、
C 点失效后无新事件、纯 `early_watch` 永不到达 `EARLY_STRENGTH`、无 `valid_until is None`。

## 9. 仍未完成 / 限制（如实披露）

1. **真实数据验收未覆盖**：受行情源限流与缺失真实快照影响，端到端验证使用固定 provider 与合成 golden fixture 完成。真实 159915 回放需补齐快照后启用。这是本分支不宜直接合并的**首要原因**。
2. **分档收益证据来自合成数据**：5.5 节的分档收益差异基于合成序列，只能证明「分档存储有必要」，**不能**作为任何档位的收益预期。真实数据上的分档表现未知。
3. **默认交易日历不含节假日**：`WeekdayCalendar()` 只认周一至周五。逢节假日短周，周线完成判定仍会晚于实际收盘（保守方向）。接入真实交易所日历后可消除。
4. **`early_watch` 的研究口径尚未回测校准**：当前强度 35 / 严重度 WATCH 为人工设定，未经参数寻优。
5. **上一版被否决的教训未做成流程约束**：目前靠人工变异测试保证测试有效性，未接入自动化变异测试工具（如 `mutmut`）到 CI。
