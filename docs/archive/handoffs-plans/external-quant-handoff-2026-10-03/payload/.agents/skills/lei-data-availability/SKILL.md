# 当时可知的数据

服务于研究的数据资格层。先读取项目 `AGENTS.md`、
`configs/strategy-documents.v1.json` 和 `docs/research/current-standards.json`；
研究任务仍由 research-closure 和本项目已有研究入口管理。

## 核对一条完整的时间链

对本轮真正使用的字段，记录来源、资产身份、经济含义、单位、描述期间、
公开时间、供应商实际可取得时间、版本及证据。区分：

- `period_end`：描述哪个期间，不代表当时已经公布。
- `published_at`：该版本公开的时刻。
- `available_at`：本轮规定的数据路径实际可使用的时刻。
- `retrieved_at`：现在下载的时刻，不能冒充历史到达时间。

公开可知研究和指定供应商可用研究是不同问题，按合同声明所用时间。
若必须经过供应商，公开和供应商到达两项约束均须满足。统一时区，
比较精确时刻；来源只有日期时，保留时间未知，依据本轮决策时点和来源
证据说明可用范围，不编造盘中时刻或统一增加一天。

## 拼接与版本

1. 同一资产、指标和描述期间内，只选 `available_at <= decision_at`
   的版本；是否允许相等由本轮执行约定决定，不能假设同时发布就能成交。
2. 多个描述期间时，先确定本轮需要的期间，再选当时可知的版本。
   较晚公布的旧期间修订不能冒充最新期间。
3. 历史原值与修订值分别保留。只有当前值加一张发布日历，无法重建
   历史版本；不能标成历史预测资料已合格。
4. 如使用 pandas `merge_asof`，两侧按各自时间键升序排序，用资产/指标
   分组和向过去查找；重复时间、时区、单位及版本优先级先处理。
   禁止最近值匹配、向未来找值或用后来的值补早期空缺。
5. 追加未来资料后重算历史输入，确认过去决策对应的字段值和资格不变。
   这项检查不比较未来收益标签，因为标签本就要等未来发生。

## 接到现有工具

先读 `src/lei_signal/research/input_preflight.py` 的 `inspect_input`、
`src/lei_signal/research/data_quality.py` 与用途检查，复用实际覆盖的入口。
技术研究的时间检查见 `workflow_inputs.py::prepare_observations`；
字段存在不等于所有外部版本已经自动检查。缺少关键证据时说明受阻用途，
仍可保留注明修订性质的历史描述，不给它预测或交易资格。

基本面和消息面在本系统只解释背景，不能借本技能加入技术判定或硬过滤。
宏观、情绪、宽度等不支持的用途不能强塞进技术研究入口。

输出简短的字段资格表：字段、所用时间及版本、证据、适用用途、未知项。
需要演练首次发布与修订时，读 [模拟案例](references/cases.md)。
