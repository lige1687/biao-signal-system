# 用过去资料检验后来的判断

服务于研究的验证层。读取项目 `AGENTS.md` 与
`docs/research/current-standards.json`，从已有合同确认问题、对象ID及版本、
观察时间、预测目标、实际代码和原累计预算。核验、状态或历史说明问题
不强制拟合模型；本技能不启动另一套研究流程。

## 审阅时间划分

- 对“用过去预测后来”的问题，训练观察必须位于检验开始以前。
  同日各ETF用整日期切分，不能随机拆行让同一市场日进入两边。
- 一条观察的未来结果也必须在实际拟合时已经知道。按实际结果结束时间
  和到达时间处理，不把“5条记录”直接当成“5个交易日”。可变退出时间、
  停牌及缺价需要逐条核时间。可用结果结束不等于供应商已经送达。
- 现有日线入口要求 `date <= train_end` 且 `label_end < eval_start`。
  这是该入口的日期口径；若拟合时刻更早，还要核结果是否已到达。
  未成熟结果按冻结合同剔除或拒绝，记录数量与原因。
- 不将检验之后的记录重新拼进训练。某些历史分组比较允许训练含后来
  记录，那只能回答相应历史问题，不能称为当时可执行的预测检验。
- 时间空档应从结果跨度、观察依赖和执行时点说明理由；不套用固定
  百分比、统一天数或“至少保留一半资料”的通用通过线。

## 只用当时的训练资料确定方法

标准化、缺值填充、异常值边界、字段选择和参数选择只在训练资料确定，
再原样用于对应检验期。按当日全体资产计算的排名是另一个问题：
资产集合和值必须在当日已知，不能借此读取未来日期；区分每只资产历史
排名与同一天资产间排名，也不能把所有日期混在一起做分组。

保留所有试过的版本、失败和已经看过的时期；换文件名或AI不让旧资料
变成全新验证。按当前问题比较简单参照、已有信息与新增信息，
不将固定IC（排名与后来结果的对应程度）或收益门槛作为全部研究通过线。

## 复用实际入口

先读 `docs/research/research-workflow-usage.md`，以及
`src/lei_signal/research/workflow.py::preflight` 和本轮实际评价器。
用既有 `--workflow-draft` → `--workflow-contract` → `--register-report`
完成适用的新技术研究。旧冻结实验保留原规范，未支持的研究不绕过拒绝。
已有日期切分与结果成熟检查应直接复用；本技能没有新增统计引擎。

交付一张边界表：本轮拟合时点、训练/检验日期、结果成熟条件、剔除数、
预处理拟合范围、已见资料与剩余未知项。工程检查通过只证明指定边界，
效果结论须来自本轮真实比较。

需要核对“训练不含未来”和同日两ETF划分时，读 [模拟案例](references/cases.md)。
