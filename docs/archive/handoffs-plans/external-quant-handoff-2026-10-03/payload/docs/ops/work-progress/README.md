# 阶段进度与多设备交接

用户于 2026-10-02 要求：每完成一个阶段，将当前计划、已完成内容、正在做的任务、负责设备、相关提交和下一步更新到仓库进度文档；代码只推到各自工作分支；大数据包、数据库和密钥不进 Git。

## 更新规则

每个有边界的任务在本目录维护一个稳定文件名。阶段完成时更新当前摘要并追加阶段记录；开始、暂停、移交或发现关键阻塞时也更新。进度文档随同该任务代码提交到负责人的工作分支，接手设备先拉取对应分支，再按记录继续。

不同任务维护各自文件，避免抢写同一份总表。这个入口只维护导航；跨分支的状态需要读取各分支最新进度文件，不能用某台电脑的旧副本宣称其他任务已完成。计划、已派发、运行中、交付待验收和验收完成分开记录；不知道的设备标识、运行状态和提交写“未确认”。

每份进度至少包含：

| 字段 | 应记录什么 |
|---|---|
| 更新时间与任务范围 | 实际更新时间、任务名称、当前阶段及授权边界 |
| 当前计划 | 阶段顺序、目标和完成条件 |
| 已完成内容 | 实际交付、验证结果、对应证据路径 |
| 正在做的任务 | 当前执行内容与状态；未启动的不能写运行中 |
| 负责设备 | 本地/远端设备标签、负责人、对应工作分支；设备标识未知时说明 |
| 相关提交 | 写入时已存在的准确提交 SHA、用途及推送情况 |
| 下一步 | 负责方、最小行动、前置条件与阻塞事项 |

包含进度文件本身的提交可通过 `git log -- <进度文件路径>` 定位，下次阶段更新再补其 SHA；不要为在同一文件里写入自身提交号而连续制造补写提交。

## Git 与资料边界

代码和进度只推到各自 `codex/` 工作分支，不自动推到或合入 `main/master`。只暂存本任务的准确路径，提交前核对改动范围、文件大小和禁止入库项，避免把共享工作区其他任务的文件一起带入。

大数据包、运行数据库、备份、密钥和私人账户资料留在对应设备或经用户授权的外部存储。进度只记录不含凭证的相对位置、来源、版本、完整指纹及取得方式；缺资料明确写出，不能用文件名或摘要冒充数据已移交。不要把含令牌或密码的连接地址写进文档。

`.gitignore` 防止常见本机资料被误加，但不会移除已经跟踪的文件。若发现既有入库问题，先报告范围，按用户要求处理；本约定不授权删除数据、改写历史或强推。工程阶段记录也不能替代研究报告、冻结证据、实验登记或系统待升级台账的权威状态。
