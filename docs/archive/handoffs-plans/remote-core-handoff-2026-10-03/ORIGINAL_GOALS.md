# 原始目标、后续改变与验收方式

最初是让只有GitHub资料的另一台电脑承担核心系统研究、决策及架构问题，避开其他负责人正在做的工作。原远端采用Opus 5.5。正式有界任务是T2—T10及模块A机会母体审计；T1保留其他负责人。

本负责人交付的是独立事实验收、接受程度、可执行返修及生产修复立项建议；不重做全部研究。准确要求原件在 `docs/research/proposals/remote-astra-2026-09-30/ACCEPTANCE-PROMPT.md`，队列原件在 `docs/archive/handoffs-plans/remote-astra-queue-2026-09-30/`。内容和版本被manifest绑定。

## 后续改变

- 用户要求阶段记录六字段、各自工作分支推送；后来要求优先于更早“能合入的先合master”。本任务没有合主分支。
- 用户明确由量化/数据/是否有用决定候选技术条件；旧验收把四项选择全交给用户的说法已过时。AI应提出并冻结可比较的候选，完成授权范围内必要实证，允许负结果或证据不足，不追求更好数字。
- 仍需明确区分候选研究与正式策略：两份桌面原文及确认指纹、规则账本、定义登记表、生产、旧封存不可因研究建议直接改动。资料费用或受限资料不是技术选择本身，需要授权取得。
- 最新请求是交接和最低恢复检查，暂停新增研究，不扩展功能、不上线、不重跑封存研究。

## 最终业务增量与验收

验收成功是关键计算能重现、错误和边界可定位、返修有证据，不是策略赚钱。

后续候选规则的业务增量定义：对同一产品、同一当时可知的共同机会，把只改变一个候选条件后的动作与基准比较；保留未触发、取消、未成熟项；报告日期/标签/风险依据变化，并在合格输入与获准合同下比较费用后收益和下跌风险，同时检查是否超过已有简单价格/趋势信息能解释的部分。少数机会平均改善不能冒称稳定增量；固定价格路径的描述不能冒称完整账户收益。

当前：新候选效果、费用后账户改善、实时交易收益、线上指标均**未测量**。T6的8.5%—11%仅假设可成交及后续近似缩放的估算，不是已经证明的利润改善。

本次交接验收：原文/代码/证据实际存在且指纹匹配；真实未提交状态与缺口被记录；独立目录可恢复最低依赖、读取真实冻结输入并运行最小合成规则检查；从远端核实准确提交和文件。Linux/Windows没有实测就不承诺通过。
