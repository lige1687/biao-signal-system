## 要帮助用户做到什么

用户与下一位AI读完一个案例后，能自己写清：想判断什么、拿什么比较、哪些信息当时已知、什么结果会否定想法、为什么现在应停止或还缺哪份证据。对应用户“主要是学习他们的思路，实验过程”“为了我们更好的研究流程和因子效果”。

本聊天C是研究方法学习，B是日常ETF决策辅助，与其他任务字母命名无关。经典研究的分类和方法是学习来源；本地实验是练习材料。学习成果、因子效果、真实资金效果分别记录，目前新增教学的学习效果和线上收益均未测量。

## 三种做法与建议

|做法|能交付什么|代价与限制|
|---|---|---|
|推荐：一个完整案例，逐步判断与揭示|复用学习页，覆盖提问、比较、结果、反例、停止与迁移；用户可实际试学|需少量页面和内容结构调整；先完成一个案例再判断是否值得扩展|
|研究故事阅读稿|最快把思路讲完整，用户和AI都可读|容易读懂故事却不会自己作判断；现有内容已部分覆盖|
|多案例交互训练平台|可留答案、自动评分、追踪学习|数据、评判和维护成本更高；当前没有证据支持先建这一整套|

推荐第一种。首例使用本任务已经封存的波动研究，案例草稿已写完；不重跑。双均线和同期解释保留为关联阅读，第一版不同时制作多个新练习。

## 第一版具体体验

用户在原路线进入“案例演练：误差少了4.57%，值得采用吗”。依次阅读六个节点：用途→目标与时间→公平比较→先看原模型→查看强简单对照与反例→限定结论和停止。每一步先显示事实与问题，点击“看研究判断与理由”才展开答案；下一步证据不提前显示。可直接跳过作答，不强制考试。

每个节点解释“为什么这样安排，换一种做法会误判什么”。既有九条内容仍可直接查阅；演练不是强制阅读顺序。末尾展示简短研究问题卡，用户可填写给AI，AI需先找旧证据、核权限与输入，再决定是否需要新实验。

第一版不存个人答案、不评分、不接自动研究任务；页面交互只保留当前浏览状态。研究卡写明需要的输入、比较和停止条件，但不把一张卡当执行授权。失败结果与未知项正常展示。

## 验收与停止条件

工程验收：两个已上传条目在路线可达；旧路线和条目仍可读；案例证据未展开前不提前出现；按钮可用键盘操作；报告链接指向准确报告；数字和限制与封存报告一致；加载错误如实显示。用现有学习库检查和局部浏览器检查，不跑大实验。

内容验收：每一步具备已知事实、问题、理由、常见误判和证据出处；明确哪些是作者方法、哪些是本库实验、哪些是教学安排；将误差改善与收益改善分开。不能把教学展示次序冒充真实研究时才临时补对照。

学习验收：用户针对不同的简短问题，能写出目标、已有信息、新增信息、简单对照、当时可用时点、否定条件与停止条件；能指出“胜过弱对手”不足以支持采用。实际试学前只报告内容/工程验收，不声称用户学会、研究更快或因子更有效。

若用户更需要研究故事而非逐步练习，按其选择缩减；若学习页同块有其他实现者，先协调；若来源缺失或旧结果不支持某句话，删去该断言或标未知，不重跑来补教材。第一例完成且收到学习反馈前，不扩建多案例平台。
