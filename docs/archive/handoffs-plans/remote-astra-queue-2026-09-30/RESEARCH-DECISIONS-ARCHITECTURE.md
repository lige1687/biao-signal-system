## T7：调研与方法决策——机会很少、还互相依赖时，怎样知道一个条件有没有帮助？

**实际障碍**：完整回调中的位置、首次计数、结构起点、确认及止损相互依赖。删除一个条件后机会本身可能改变；相邻交易也可能共享同一段涨跌。机械按交易条数认定证据充分，可能给出错误结论。

**先读**：T2 的条件依赖表；当前规范索引指向的研究问题方法、增量证据和原则；`docs/experiments/research-information-gain-review-2026-09-28.md`、`docs/experiments/research-design-correction-2026-09-30.md`；`docs/research/factor-evidence-reliability-usage.md`；文献库 README 和 `classic-research-process-2026-09-29.md`。已封存结果只用于去重和理解障碍，不重跑。

**调查与判断**：仅围绕 T2 下一问题比较最多三种方法，例如同一次候选机会上的决策比较、完整规则的账户比较、按不重叠机会检查结果稳定性。方法名不是结论。解释每种究竟回答什么、需要哪些数据、什么时候会误导；区分原作者方法、本库延伸和未验证设想。优先复用已读原文；新增检索每个明确子问题最多六次来源请求，最多精读三份高度相关原始方法资料；近期相关者优先，不为追新加入无关论文。不以摘要冒充全文，不把未找到反证写成不存在反证。

**交付**：一张方法选择表；一张最多三篇的方法卡；选定一种主要方法及为什么放弃另外两种；把它落实为一个下一实验的草案：机会如何形成、删条件后的身份怎样追踪、哪些价格当时可知、简单对照、主要结果、证据不足时怎样报告、停止条件。给四个可运行人工例子，覆盖同机会、机会改变、相邻结果高度重叠、单笔极端结果。不得发明通用最少样本数、改变已冻方法或为了得到好结果筛除失败机会。

**停止**：一个问题的合同已明确，或关键策略含义待确认且可清楚定位，便结束。没有真实行情统计，不填虚构收益或“有效概率”。

## T8：路线决策——下一笔资料工作先解决哪一个真正的阻塞？

**实际障碍**：另一台电脑有部分旧真实价格和已封存账户记录，但最新六 ETF 研究 raw 不全。文件存在、字段齐全与正式研究可用并不是一回事；同时原有数据盘点之后已有补充核验，不能继续按旧缺口安排工作。

**先读**：本包输入清单；`docs/research/proposals/etf-data-audit-2026-09-19/README.md` 及后续 `docs/research/proposals/etf-source-verify-2026-09-20/b-final.json`、`data-staleness-fix-2026-09-20/a-final.json`；已有源核验验收摘要（完整 raw 缺失则不声称重新验收）；当前 `input_preflight.py`、`qualification_bundle.py`、`symbol_identity.py`、`trading_calendar.py`。宽基/ETF优先；个股未来适配不能被永久排除，但本题不扩取个股样本。

**调查与判断**：对 T2/T4 所需字段先分清“仓库已有且可复查”“已完成但远端没有完整证据”“确实未证明”。比较三条路线：移交现有合格小包、按许可补公开资料、用户授权后才采购或提供资料。关注历史身份、分红拆分、未复权成交价格、小时确认、当时可得时间；只评估本题实际需要的内容。产品身份/费率旧核验不等于小时历史或公司行动已证明，日线代理也不能补真实小时缺口。来源价格或规则会变；需要引用时现场核官方说明，查不到就写未知，不猜付费价格。

**交付**：针对每一个研究障碍的最小字段、时期、对象、来源、许可、资料资格与验证条件；三路线的成本/风险/可执行性比较；明确首选路线和拒绝其余路线的理由。给独立于当前异常放量、六线聚散、A01个股资料和情绪工作的下一批最多三个问题的先后顺序：每题会改变什么决定、先决条件、现有证据是否已回答、什么事实会令其停止。对真实历史缺口不能用今天仍存续标的、指数或假数据顶替。

**停止**：形成一个最小资料合同和研究顺序即可。不再大范围重复产品源盘点，不下载行情，不购买、不调用本机数据服务。缺失远端证据是移交问题时要直说，不宣称本地主负责人从未完成。

## T9：决策与架构——后来的新数据怎样改变已有判断，又不会事后改规则？

**实际问题**：现有历史多次被研究过，历史小优势不足以证明未来也成立。需要把“先固定判断、随后观察新数据、最后按约定决定是否继续研究”说清楚。这里的冻结观察指先保存当时的定义与预期，再等待之后产生的数据核对；它不是冻结交易、自动下单或把旧历史重新标成新资料。

**先读**：`docs/research/factor-evidence-reliability-usage.md` 中未支持生命周期的边界；当前研究原则、增量证据规范、定义登记表；`src/lei_signal/research/workflow.py`、`factor_access.py`、`definitions.py` 及研究工作流最终验收。先核现有冻结实验和运行记录可以复用什么。本题不审页面接入、Agent目录/证据卡或技术体系阅读页，这些已有负责线。

**分析与决策**：比较“保留观察协议和周期性人工核对”与“增加最小观察记录层”两种方式，推荐一种。根据已有失败与证据不足记录，选择最多一个既有、定义确定的技术对象作为协议示例；不新增公式，不复跑旧结果，不因候选不好看而换对象。观察期、成熟结果、资料修订、缺失与策略定义变化怎样处理须可执行；不得凭空保证某段时间或样本数后必然可判有效。

**交付**：一份未来观察合同草案，含准确对象ID/版本、起始时点、固定假设、简单对照、允许观察的结果、费用口径、核查节奏、结束/暂停条件、改变判断的证据条件。资料质量、研究价值和生产采用分别表达；收益证据不足允许继续观察或停止，不自动进生产。给最小记录接口和五个合成状态案例：等待结果、结果已成熟、输入被修订、定义出现新版本、观察预算中断。演练不得读未来市场结果。说明怎样保留原件、如何开启新版本而不覆盖旧状态；若现有机制已足够，交复用方案而不增加系统。

**停止**：一个明确协议和状态演练完成即可。不得建立自动任务、采集新行情、写OKR或生产状态，也不批准任何真实交易；实际观察启动另由主负责人绑定完整数据和权限。

## T10：跨电脑架构——移交最小资料后，别人怎样真正复查同一个实验？

**实际问题**：已有精确指纹、冻结协议与部分代码快照，但旧脚本可能写死绝对路径，最新 raw 也不能全部放进公开仓库。怎样少传资料，同时保证别人复查的是同一次实验，而非当前代码重新算出的另一件事？

**先读**：本次 GitHub 同步说明及 manifest、本包输入清单、两份原文副本的 manifest；`src/lei_signal/research/data_snapshot.py`、`qualification_bundle.py`、`workflow_inputs.py`、`workflow.py`；研究工作流使用说明及工程最终验收。抽查一个 GitHub 已有的旧协议/源码锁，只读取，不修改冻结路径或绕过输出目录保护。

**分析与决策**：比较公开仓库内小包与授权后单独传资料两种办法，选择满足本问题的最小交接。区分三件事：旧报告数字核对、按冻结旧代码复现、新协议当前代码重算。准确说明每种需要的数据与权限；不能把当前代码跑通称为旧实验完全复现。沿用现有 manifest 和合同，不另建调度系统。

**交付**：最小移交包清单和机器可读示例：冻结协议/来源版本/实际指纹、相对路径映射、旧代码归属、依赖版本、对象/日期/单位、资料许可与公开范围、预期输出、误差约定及缺项状态。原冻结合同作为原件保留，相对路径映射只作移交层，不改其历史哈希。写一个仅用合成资料的校验演练，覆盖完整包、文件缺失、内容被修改、代码版本错误四种情况，实际运行并保存输出。列出应进入公开仓库和需单独授权的内容；密钥、账户库、私人聊天与来源许可不明的原文不入公开包。

**停止**：合成四例和一次已有包只读审查足以回答便结束。真实资料未授权移交就记录缺口；不打包所有历史、不推送新真实 raw、不修改生产来源路径、不迁移旧实验。
