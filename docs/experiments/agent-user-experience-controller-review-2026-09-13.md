## 3. U1：把直接提问和按钮操作接成同一条流程

**事实与用户影响**：两个入口的 `handleBacktest` 仍保留 `parseBacktestModule(message)` 为空就回答“请说明要补测的模块：A/B/C/D”。主控用真实函数、合成回复输入“帮我补测一下”，两个入口均复现。报告场景 4 主要测了点击按钮打开面板，不能替代直接提问路径。

**附带同类问题**：ATR 拦截返回的草稿仍含“补测”字样。实际 `parse_request` 对“我想讨论：换成 ATR 止损再补测对比一下（先聊思路，不做数值比较）”仍判为 `backtest_request`，再发送会再次被拦截。提供“继续讨论”必须能真正继续。

**最小修复**：

- 直接说补测与点击“准备补测”都调用同一个准备入口。需要先建立问题时沿用原链路，之后打开中文面板，不再追加要求用户手敲模块的文字。
- 原话已选的方法可预选，未选的不代选；提交复用一套创建、请求身份、任务登记和轮询函数，避免新旧路径各维护一份。
- ATR 不支持说明保留；提供能够实际进入讨论的草稿/入口，既不循环拦截，也不偷换退出规则。可以最小修正草稿及调用方式，不扩展通用意图系统。

**接受条件**：两入口分别实际输入“帮我补测一下”，完成中文选择，只产生一个对应任务；ATR 拦截后点击继续讨论并发送，可以得到讨论回复且零补测任务。不要用改成“点击准备补测”替代原场景。

## 4. U2：面板显示、当前选择和实际提交必须一致

**已实测**：浏览器先选 B → B 专用退出 → 改选 A → 点击创建。B 专用选项消失，但摘要仍显示它，实际 `onSubmit` 参数是 `{"module":"A","exit":"b3_dual"}`。这是前端传错组合；本轮没有向真实后端提交，不能说引擎执行了它。

**同一组件的边界**：真实组件渲染中，预选值不在能力清单里仍允许提交。选项加载时也会临时用静态 A/B/C/D 与退出列表代替能力结果。静态词典应只命名，不能决定可提交能力。

**现有窗口漏显**：两个 `openSetupPanel` 都传 `windowLabel:null`；即使原问题已有窗口，面板仍显示“未单独指定”。现有 `evidence_card.history_and_scope.comparison_config` 可作为核对入口，必须复用原问题已有选择；不新算窗口或重新挑选运行。

**最小修复与接受条件**：

- 能力加载中、失败或为空时，不提交未经确认的选项；给清楚的等待/重试状态。
- 切换方法时验证当前退出仍有效；失效则清空并要求选择，或明确展示合法默认。提交再核对当前组合，不发送隐藏的旧选项。
- 原问题的已选窗口如实显示；确实没有或无法读取时区别说明，不统一称“未指定”。
- 固定浏览器验证：B 专用退出切 A；能力延迟/失败；已有窗口与未选窗口。核对页面摘要和实际请求参数。

## 5. U3：旧任务的迟到消息不能写入新会话

**已实测**：两个 `submitSetup` 发送请求后，主控模拟用户已切到新会话，再让原请求返回。两个入口都把 510300 的旧任务消息追加到新的 518880 会话。工作台虽捕获 `gen`，但只在轮询时检查；控制台在响应后才取世代，已经错过切换。

新增面板提交只依赖 React 状态判断忙碌，没有复用原同步请求锁。工作台还会在正文和右侧资料同时呈现同一回答，应避免两个入口对同一提交产生独立请求。主控没有声称重复任务已实测发生，这是需一起验证的原任务书要求。

**最小修复**：请求发出前冻结会话/问题/对象与世代，响应、错误、结束处理都先核对上下文；已创建的后台任务可登记并在原会话恢复，但不得插入新会话。复用同步提交锁与稳定请求身份，不只依赖组件下一次渲染。

**接受条件**：两个入口分别做“提交 → 延迟响应 → 新会话/切标的 → 返回”；新会话无旧任务消息，原任务仍可查。旧回答动作保持原问题对象；正文和资料区连续点击只产生一次创建请求。禁止仅以“草稿含代码”代替此验证。

## 6. U4：中文解释保持原含义，详情按钮真正展开依据

这些是本轮新文案和控件的问题，属于体验范围，不要求改算法。

- `agentUx.ts` 将退出2解释为“见到顶部迹象就主动收，落袋更早”，但既有引擎需要先有顶部构造，再满足对应退出条件。不能用“落袋更早”承诺相对结果。
- B 专用退出提示写“跌回密集区**或**20日线拐头即离场”，与引擎中两条件同时满足、另有排列被破坏的独立条件不一致。按实际规则解释，保留关键区别。
- “20 日线和成本区”容易被读成筹码成本区。使用准确且可读的“20 日均线与 20 个交易日前的价格”等表述，必要时展示具体既有条件，不改退出计算。
- 工作台“查看依据详情”只设置正文 `selfExpanded`，依据卡自己的 `<details>` 不受控；控制台只滚动到回答顶部，也没有展开依据。按钮文字承诺的是查看依据，应展开本回答的依据区域，且两入口行为一致。
- `supporting` 分支改造后未再显示 `window_note_cn`/`differences_cn`，不能因结果可用就删掉附带说明。原任务书要求明细后置而非删除，应放回可展开详情。只呈现已有字段，不重新判定适用性。

**接受条件**：用原规则的条件作对照检查显示文字，不运行收益实验；注入一张含附带说明的支持卡与一张不匹配卡，在两个入口点击“查看依据详情”，实际看到对应说明。
