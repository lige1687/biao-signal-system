# Jev 开发任务模型路由盲测

## 一句话结论（大白话）

Jev很适合做“任务应该交给哪个模型、用多深思考”的第一层判断：17条拿到答案的项目任务全部选中预设路线，小任务没有浪费Astra，策略和高风险任务也没有降级；但一次网络失败和一次概率舍入校验问题说明它只能提供建议，必须由固定规则兜底，暂时不能直接控制自动派发。

## 要解决什么

用户提出把Jev用于项目开发路由，例如决定一个任务走什么模型和什么思考模式，并考虑做成Skill。用户随后要求先看效果，并告知TypeSafe密钥在本机指定文档中。

本轮只做路由盲测：不创建Skill、不修改项目路由、不派发子代理。测试任务和期望路线在首次调用前冻结，Jev只看到任务文本和路线定义，看不到期望答案。

## 路线设计

为了避免分别选择模型和思考强度后拼出不合理组合，本轮直接给出七条合法组合：

| 路线 | 适用任务 |
|---|---|
| 当前任务直接做，低思考 | 只读检查、一个命令、单点改字 |
| Spark低思考 | 小脚本、固定格式转换、机械测试补齐 |
| Terra中等思考 | 方案明确的普通功能、少量跨文件接线和重构 |
| Sol中等思考 | 冻结实验执行、一般故障调查、证据整理 |
| Sol高思考 | 多轮未定位的疑难问题、复杂证据核对 |
| Astra高思考 | 策略定义、论文方法、实验设计、体系边界 |
| Astra超高思考 | 真实资金与关键时点裁决、跨层对抗性终审 |

真正执行前仍需检查模型当次是否可用。尤其Spark是否可调用不能由Jev决定；不可用时应走预先写好的回退，而不是静默换模型。

## 结果

| 项目 | 结果 |
|---|---|
| 固定任务 | 18条 |
| 获得模型选择 | 17条 |
| 与预设完全一致 | 17/17 |
| 小任务r01—r05 | 5/5正确，无Astra浪费 |
| 策略/方法r14—r16 | 3/3选择Astra高思考 |
| 高风险终审r18 | 正确选择Astra超高思考 |
| r17真实资金风险 | 网络错误，无模型答案，不重试 |
| 正常答案耗时 | 0.744—7.103秒，中位0.915秒 |
| 总输入/输出 | 14,724 / 1,313 tokens |

精确命中值得肯定，但测试题是根据项目现有分工编写的，任务描述相对清楚，不能把17/17理解成面对含糊真实需求也会满分。

## 两个工程问题

第一，r12已经正确选择Sol高思考，但API返回的七项概率经过两位小数舍入后合计0.99，原校验器容差过严，将它判为结构错误并停止。补充协议保留原失败记录，之后把容差放宽到0.02；没有重跑r12。

第二，r17请求在16.6秒后发生网络错误，按协议没有重试。另行单题提交尚未尝试的r18并成功，但r17保持缺失。因此预先要求的“r14至r18五条全部返回且不得降级”没有完整满足。

这两个问题直接决定未来Skill的形状：Jev不应拥有最终派发权；校验和网络失败必须回到项目固定路由表，不能反复调用，也不能擅自提升或降低模型。

## 低把握答案

虽然所有可读选择都正确，有两条值得特别关注：

- r07实现只读表格页选择Terra中等，但最高概率只有0.64；
- r11汇总研究结果选择Sol中等，最高概率只有0.48。

模型选对不代表它很确定。后续设计应保留“低把握时由主控按固定规则复核”，阈值需要用更难的真实任务再定，不能根据这两条现场拍脑袋。

## 是否符合预期

方向符合，而且比新闻分类更适合Jev。它的输出天然是有限路线之一，不需要生成长文本；在本轮中准确区分了调度成本、普通开发、研究执行、复杂排错、策略判断和资金风险。

但本轮只足以进入Skill设计，不足以自动执行。推荐的初版Skill应是“路由顾问”：

1. 明确规则能直接决定时，不调用Jev；
2. 模糊任务才让Jev在合法组合中选择；
3. 校验模型可用性、用户指定和项目红线；
4. 网络失败、结构异常或低把握时使用固定回退；
5. 输出建议卡，由当前主控决定是否实际派发。

## 证据与安全边界

输入、路线定义、三阶段协议、逐条原始响应和合并结果保存在 `docs/experiments/raw/jev-model-routing-pilot-2026-09-22/`。密钥只从用户指定的本机文档读入进程并放入Authorization头，没有打印或写入仓库产物；扫描未发现密钥值落盘。

## 最小决策卡

- 测什么：项目任务到“模型＋思考强度”的选择。
- 得到什么：17个有效选择全部命中；1个任务因网络失败无答案。
- 用户意义：值得设计Skill，但只能做顾问，不能直接自动派发。
- 下一步：设计固定回退、低把握复核和模型可用性检查，再用含糊真实任务做反例测试。

## ARCHIVE

2026-09-22封存本轮路由盲测。结论为通过能力方向验证、工程可靠性有条件；不授权自动派发、修改模型、消耗额外额度或生产接入。
