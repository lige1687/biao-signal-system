## 固定收口二：用户事实先核语义与问题归属，再进记忆

独立输入/结果：

| 输入 | 实际错误 |
|---|---|
| 如果我有一万元，能不能买？ | budget=10000 CNY，标成用户明确提供 |
| 朋友有一万元闲钱 | 同样进入用户预算 |
| 我手里有一万元闲钱 | detect_stance=holding |
| 我已经不持有了 | holding_cleared=false，旧持仓可能继续继承 |
| 问题1声明持有但没有回答；问题2切510300；回答明确question_id=2 | `_user_background(...,'510300.SS')` 把问题1认领成510300持仓 |

根因已定位：金额守卫只检查附近单位与否定，没有假设/归属；“手里有”不区分现金与证券；纠正词表遗漏正常否定表达；记忆按“后面最近assistant”认领，忽略现成的精确question_id。

固定实现原则：

1. 用现有 `AgentMessage.message_id/question_id` 和冻结对象绑定事实。无精确归属的旧消息标未知、不可继承；不得跨过下一条user去猜归属。中断、重试、多回答都按同一问题处理。当前symbol未知不能收集全部对象背景。
2. 区分真实声明、假设、否定、第三人和引用；现金不是持仓。不能确定就不持久解释为用户事实，可保留为本轮讨论假设。
3. 明确否定清除对应旧背景，其他事实保留。处理同一条“不是一万，是五千”时新值和清除顺序一致，`user_budget/user_background`不能互相矛盾。
4. 成本未建设提取能力时，不要固定说“你没给成本”。用户本条已经说成本却被模板否认也不诚实；可以说“这段系统直出未核实成本”。

固定矩阵：上表五例 + 原持有/预算用途继承正例 + 不同对象 + 问题中断后下一问成功 + 一个问题两次回答 + 本条更正金额。至少用临时库构造真实message_id/question_id，核对准备材料与落库回答，不能只用无身份的手写历史列表证明记忆正确。

这些均属原C2/C3边界，不新增交易、模型、因子能力。C1已通过部分不重新设计；不再新增真实模型请求。
