# 带日期的共享资金账本：限定工程核验（2026-10-08）

## 一句话结论（大白话）

人工账本现在会核对“钱什么时候能花、刚买的份额什么时候能卖”，并阻止漏记已知拆分、使用过时净值入金和未经允许的当天买卖。初版三个错误已实际复现、修复并通过独立检查；拆分前后资产保持390元。它补齐的是研究模拟中的时间与资金约束，没有证明投资更赚钱，也没有接入真实账户。

## 问题、原范围与比较基准

沿用原2026-10-04共享账户规范v0.2，不改变策略含义、参数或真实账户偏好。原账本已有共享现金、费用、分红、拆分和入金核算，但手动 `settle()` 没有日期，卖出款直接变成可用现金；独立日期检查函数未被账本强制调用。原16项合成检查已封存，本轮没有执行原目录中的测试。

本轮只做带日期的合成执行层：唯一受支持入口 `apply(event)` 依据事先给定的人工日历、允许开盘、到账时刻及每批份额释放时刻检查事件，再一次性更新账本。拒绝不改变资金或持仓。完整策略买卖安排、真实价格/费用和公司行动资料资格不在本轮交付内。

服务层为资金研究执行层。两份权威策略文档实际指纹、当前规范索引及原六份工程资料指纹均保存在 [source-manifest.json](raw/weekly-portfolio-dated-execution-2026-10-08/source-manifest.json) 和 [standard-bindings.json](raw/weekly-portfolio-dated-execution-2026-10-08/standard-bindings.json)。原小工程文件准确快照在 `source-baseline/`；没有复制完整行情包、真实成交或账户数据库。

## 实际增加的检查及量级

| 情况 | 原来或初版的问题 | 第二版的限定结果 |
|---|---|---|
| 已有100份可卖，又买100份 | 手动结算可能立即放开全部份额 | 当天及人工休市日仍只可卖100份；到明确释放时刻才可卖200份 |
| 自由现金0，卖出所得200元 | 卖款可能在同一开盘被再次使用 | 同一开盘买入拒绝；实际到账且后来允许开盘才可用 |
| 自由现金100元、待用卖款200元 | 可能误锁原有现金或提前借用卖款 | 原100元仍能用，另外200元未到时不能用；释放不增加资产 |
| 100份×2元，已绑定二拆一 | 初版跳过拆分直接卖出只留下100元 | 漏行动即拒绝；处理拆分后卖100份，剩余100份与100元卖款合计200元 |
| 前日每单位净值0.3，入金100元 | 初版漏收盘后用0.2，错误变成1500单位 | 漏日账即拒绝；补齐后约1333.333333单位、资产400元，净值仍约0.3 |
| 买入当天15点释放 | 初版可未经例外依据当天卖出 | 按上海日历日期，在买入时拒绝同日释放；跨时区写法不能绕过 |
| 两批各100份、应收10元，二拆一 | 需要区分拆分与后来价格变化 | 总份额200→400、报价1.9→0.95、应收10不变，资产390→390，原释放时刻保留 |

同一开盘多个不同编号的合法成交允许；重复事件、倒退时间、缺开盘、禁买、提前支付、漏必要行动与行动顺序不明均拒绝。分红支付只是应收转现金，不凭空增加资产。入金使用最近应完成日账的单位净值；缺价格不能自行补造。

这些金额来自人工构造反例，用于检验程序算账，没有真实收益对比或因子性能结论。

## 验证、独立审查与失败保留

执行者使用Sol6.1/medium，关键资金与日期设计及独审使用Astra/high；实际模型费用未知。初版23项通过后，独审仍发现上述三个严重漏检，故没有把通过数量当作完成。三个旧错误均用保存的初版源码重新复现。

修复过程中首次27项运行有1项错误：旧合成夹具绑定了分红却直接成交，新检查正确拒绝；失败日志保留，合法路径补入必要行动。最终只运行7组新增日期检查与4组修复反例，共11组通过。另保存60步资金变化，其中31次预期拒绝前后账本一致；保存结果的20项独立算术检查通过。这些检查集合存在重叠，不相加为独立样本量。

非作者另用内存事件序列独立核对三个原错误、合法相邻情景、跨时区日期、同刻行动顺序和拆分390元守恒，没有重跑原16项或整套11组。四份第二版源码在审查前后指纹不变。主负责人重新核原六文件、快照及25个初版资料指纹，原始失败完整保留。

净值的十进制运算在28位有效数字下出现1e-28末位舍入差，第一次精确等于0.3的断言失败保留；最终明确只对这个派生净值使用1e-27舍入界限，单位数量和资产仍按原算式核对，不改变账本或资金条件。实际修复资料约0.33MB，超过最初0.25MB估计，主要是保留初版与失败；容量检查仍有约5GB，未删除任何资料。
