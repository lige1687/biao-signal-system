## 3. 必须修订的问题

### F1：STD 不是窗口里出现一个缺失值就全部算不出来

原报告 §3.3 写“窗口内有 NaN 则 pandas 结果为 NaN”。这一描述错误，会使另一个 AI 复算出不同结果。

本地保存的 [ops.py](/Users/yongbiaoli/Desktop/lei-signal-lab/docs/experiments/raw/qlib-alpha158-definition-review-2026-09-12/upstream-ops.py) 中，有限正窗口的 Std 使用 pandas 的滚动标准差，`min_periods=1`。独立执行当前环境 pandas 2.3.3 的同类调用：

```text
输入价格：[10, NaN, 12]
窗口：3，min_periods=1，默认 ddof=1
最后一个窗口的 std：1.4142135623730951
除以当前价格 12：0.11785113019775793
```

应改为：计算会跳过窗口中的缺失值；样本标准差需要至少两个有效值。`min_periods=1` 不意味着一个有效值也能计算 `ddof=1` 的标准差。当前价缺失时，最终除以当前价的结果仍缺失；全缺失或仅一个有效值也缺失。常数价格在至少两个有效值时标准差为 0。

这证明原报告的缺失规则不成立；它是 pandas 依赖行为核验，**没有运行 Qlib 表达式引擎**。当前价为 0、无穷值等其他输入资格不在此小例的通过范围内。

### F2：CSZScoreNorm 与按训练区间拟合的 ZScoreNorm 混淆了

原报告 §5 在声明未读处理器实现的同时，断言 `CSZScoreNorm` 按 `fit_start/end` 拟合。补查同一固定上游引用的实现后，这个断言不成立。

`CSZScoreNorm` 按 `datetime` 分组，对同一日期不同产品的值进行标准化；它没有实现独立的训练期 `fit`，构造参数也不是训练起止时间。另一个类 `ZScoreNorm` 才会按指定训练区间保存均值和标准差。二者不能因名称相似而混用。[固定上游 processor.py](https://github.com/microsoft/qlib/blob/79633dd9506ea689e5400dea0197717b5b3d74b7/qlib/data/dataset/processor.py)

可替换为：Alpha158 默认学习处理包含 `DropnaLabel` 和作用于 `label` 的 `CSZScoreNorm`；后者做同日跨产品标准化，不应描述成从训练期估计一组固定参数。本次仅确认该类的分组方式和拟合接口，未运行处理器，也未穷尽其调用的标准化函数边界。

仍应保留原报告正确的限制：默认标签是未来收益，不得进入当时的交易信号。标签经标准化后也不会因此变成当时可用的数据。

### F3：STD 与本地收益率波动的区别，不应写成“量纲不同”

原报告 §2、§3.3、§4 把差异归为“量纲不同”。这里更准确的说法是：二者都消除了价格货币单位，通常均以小数表达，但输入、统计含义和时间尺度处理不同。

- Qlib STD：衡量窗口内价格水平的分散程度，再除以当前价。
- `mixed.rv20@1.0.0`：先计算相邻有效价格的收益，再计算最近 20 条收益的样本标准差，并乘以 `sqrt(252)` 年化。

年化方式不同不能成为把一个直接换成另一个的依据；同样，以不同数据算出不同数字，也不证明哪个更有用。

### F4：MA 的数学关系成立，但五条数据不是 distance50 的复算

对于同一个 N、同一组合法价格观察，且当前价和均值均为非零有限值：

```text
D_N(t) = P(t) / SMA_N(t) - 1
Q_N(t) = SMA_N(t) / P(t)
Q_N(t) = 1 / (1 + D_N(t))
```

这是一条数学关系，不是已接入的运行兼容性证明。Qlib 默认 MA5–60 也不是本地 distance50/200 的现成替代品。

原 §4 和手算记录中的五条价格，应标为“通用 N=5 教学小例”，不得写成 `trend.distance50@1.0.0` 已执行或已逐值对齐。窗口相同之外，还须对齐：含当日规则、有效观察集合、预热、缺失处理、价格与公司行动口径。仅有相同数量的行不保证这些条件都满足。

### F5：本地跳近月动量的分子不是当前价格

原 §3.1 的公式正确，文字“当前价在分子”错误。

应严格保留：

```text
mixed.momentum.raw@1.0.0 = I(t-21) / I(t-252) - 1
```

分子是往前 21 条有效报价对应的经济价格指数，不是 `I(t)`。不要改定义去迎合 Qlib。

“方向相反”也要限定：同一对价格端点的反向价格比，与正向涨幅是反向单调关系；本地与 Qlib 的端点、窗口本来不同，不能据此宣称两者实际排序一定相反。

### F6：撤回未检验的互补性判断，以及没有绑定输入的修复要求

原 §6 说 STD 和 rv20“不互补也不互替”。本轮最多支持“不应直接互换”；有没有互补价值，需要另外的问题、数据和比较，当前应写“未检验”。无需为修订报告新增效果实验。

原 §8 引用了 memory 中的 `cache/timing`、512100/510500 复权断裂，但没有绑定本次可核验的输入路径、版本、日期和证据。这不能作为本次已确认问题或强制修复要求。应删除该具体断言，或明确标成“其他任务提供的未核验线索”，有真实来源再单独引用；不要求本轮追加行情调查。

后续真实行情验证，应检查**它实际使用的输入**是否合格；不能把全部公式研究都绑定为“必须等待整个数据基础工程结束”。明确标注的合成数学小例不需要等待真实行情修复。

另需收紧两处边界表述：

- Slope 单个有效点的源码分母为零，可登记为源码发现的风险；未运行编译模块前，不将具体 NaN/inf 输出写成已经实测的结果。“每天”也应改为“每个观察序号”，避免把缺报价后的序号当自然日。
- 旧笔记可以复用，但“以后不必重新核上游”不能无限期适用。未来依赖、上游版本或拟接入用途变化，仍需检查相关差异。
