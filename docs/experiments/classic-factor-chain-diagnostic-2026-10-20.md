# 用经典因子检查研究链路：月度反转首轮诊断

资料核对与交付：2026-10-20，Asia/Shanghai。限定状态：历史价格诊断完成；规模、BP/EP真实因子研究尚未完成。未改生产或交易规则。

## 一句话结论（大白话）

经典因子适合作为检查研究链路的参照。本轮复用原600只历史股票队列，隔离1只复权标记冲突的来源后，在2015—2025年132个月得到“上月涨幅”与下月表现的平均排名相关系数−0.0628；把分数取相反数，结果正好变为+0.0628。它说明本次排序和方向计算对得上，也实际找到了来源检查的缺口；不能因此宣布全系统无错、复现了全A股原论文或已经能赚钱。

最重要的反例：2017年的相关方向为正；五组价格变化并不逐组递减。历史财报与市值的完整时点对齐仍未通过，不能用这次价格因子的结果给BP/EP背书。

## 1. 本轮测谁、测多久、怎么计算

固定名单来自2014年底2595只A股，按原先固定的代码哈希选600只；不根据今天是否仍上市重新选名单，也不补入2015年以后上市公司。本次读取并核对原600份价格文件、名册、交易日历与输入清单的指纹，未下载行情或财报。sz.001914因返回复权标记冲突整只隔离，原600只的资格分母仍保留，未补另一只。

- 决定日期：2014-12至2025-11的各月最后交易日收盘后。表现月份：2015-01至2025-12，共132个月。
- 原始分数：本月最后交易日收盘价÷上月最后交易日收盘价−1；反转分数是其相反数。要求两端当日有实际交易、正数价格，决定日不是ST。
- 后续表现：次月第一个交易日收盘至再下月第一个交易日收盘。真实端点2015-01-05至2026-01-05。保留一天执行延后，因此不能当成文献月末收盘组合的完全复现。
- 每月先给股票排序，再计算这个月分数名次与后来表现名次的相关程度（Rank IC），最后对132个月平均；没有把不同月份的全部股票混在一起求一个相关值。
- 每月合格442—577只，中位540.5；有后续报价441—577只，中位540。79,200个股票月份里，70,509个符合信号资格，70,498个有结果；股票月份不是同等数量的独立证据。
- 995个结果使用至少一个停牌端点的账面报价，11个未来报价缺失；不替换、不重新分配缺失股票权重。价格是供应商复权报价，完整分红、退市清算、可成交与费用未核清。

范围是旧历史队列的诊断，不能代表全市场动态股票池，不能外推ETF或原LEI完整交易系统。此前已经研究过这段价格史，本轮不称新的独立验证。

金融假说是短期交易压力或过度反应可能随后回补；竞争解释包括规模、流动性、市场急剧反弹与报价处理。本题用反转作诊断参照，尚未区分这些原因，也没有把观察到的相关当成已经证明的机制。

## 2. 因子性能：数值与反例同时看

Rank IC是排名相关系数，范围−1到1，没有收益率单位。

| 诊断 | 实测结果 | 解释与边界 |
|---|---:|---|
| 原始上月涨幅，月均Rank IC | -0.062779 | 本段历史总体偏向短期反转 |
| 反转分数，即上月涨幅取相反数 | 0.062779 | 相同信息换方向；不是新增因子信息 |
| 保留连续12个月联系抽样得到的95%不确定范围 | [-0.085150, -0.040259] | 历史不稳定程度的估计，不是未来成功概率 |
| 2015—2019 / 2020—2025 | -0.065931 / -0.060153 | 两段总体方向一致，不能抵消具体年份反例 |
| 2017年 | 0.002755 | 这一年总体没有呈现预期的反转方向 |
| 月内随机打乱未来结果的一次检查 | 0.003611 | 接近0；一次人工打乱不能证明不存在泄漏 |
| 单月最小 / 最大 | -0.479651 / 0.247197 | 已用独立标准库排名算法复算两个月；60个月绝对值超过0.1 |

单月很高的相关值要检查，但不能自动判为未来数据泄漏；总体均值接近文献经验也不能自动判为正确。

## 5. 这次实际发现的链路缺口

**P0：只检查请求参数，漏核返回资料。** 旧`lowfreq_discovery.py::_quotes`要求请求adjustflag=2，但实际读取的字段未包含返回adjustflag。本轮新检查在统计前拒绝sz.001914；原文件1,560行标记3。旧封存结果中该股票有132个资格记录、311个方法选择记录，说明这不是一个从未使用的孤立文件。哪些旧数值受影响、影响多少尚未量化；必须先解决这段历史的复权语义，再决定是否需要有理由的纠错复验，不能盲目重跑全部旧实验。原文件、旧模块与旧结果保持原状，本轮只在新诊断中隔离。

**P1：已接入数学核，还没有自动形成同口径经典复现包。** 当前通用分组工具只有中位数二分；本轮在研究脚本补五组诊断，没有宣称已经接入所有正式入口。现有Rank IC合同要求固定交易间隔，而历月实际有15—23个间隔；本轮按实际间隔分组调用原接口，最后仍按原132个月平均，没有把每月硬写成20天。连续/二元预测CLI没有被伪装成此次月度横截面研究入口。

**P1：来源时间声明不能替代来源审查。** 人工演练把未来结果直接当分数、却谎报为过去可知时，现有接口仍算出IC=1；如实声明晚到，4条全部排除。这说明接口能检查已声明的时间关系，不能自动辨认上游伪造的来源。新脚本未来价格变化不会改变过去分数的演练通过；真实供应商历史到达时间和财报修订仍须另核。

**P1：旧复现入口依赖的文件版本会漂移。** 本轮现有检查80项通过、1项失败。失败的旧经典CLI在统计前发现`ai-execution-contract.md`与旧合同指纹不同，正确停止；不是计算出了错误市场结果。本轮保留失败，没有修改旧冻结指纹来凑通过。后续精确复现应装配原版本依赖，不能用当前规范文件冒充旧快照。

**P1：基本面数据的可用时间尚未形成完整证明。** 已有BP来源核验确实完成6个公布后价格锚点，但只支持这些点；5份年报部分可用、3份固定案例缺合格原件。现有批量财报解析主要是资产、收入、成本和经营现金，不能当成净利润、普通股权益和股本已经齐全。规模缺历史总股数及相应未复权价格/市值；BP缺普通股权益及版本；EP还需利润归属、负盈利规则和滚动12个月口径。报告期末、公告时间、供应商到达时间、后来更正时间必须分开。

## 6. 如何把经典因子作为固定验收用例

同一套用例分三层，分别判定，不能用一个“通过”概括：

1. **必需计算检查。** 人工小例有准确答案：并列名次、正负方向、日期错位、缺值不补零、未来数据变动不能改过去分数、财报发布之前不可见、更正版本只能在更正之后使用。必须先过，再算真实样本。
2. **原文对照。** 固定论文版本、市场、历史成员、时期、分红/股本/复权、财报版本、形成与持有期、权重和费用；能完全匹配才比较原表数值。资料不同就叫本地适配，并列差异。本轮属于后者。
3. **真实诊断。** 看逐月相关、整体与分年、分组趋势、缺失/停牌集中位置和具体反例。对不合理的大值开展源码与来源复核；不以预想的IC区间或完美单调作为调参目标。

用户提到的−0.04到−0.06不能设为全A股通用及格线。本轮核查的原始资料没有给出这种普遍保证。`0.1`与`0.1%`还必须区别：后者是0.001，相差100倍；建议IC统一写小数，并注明无收益率单位。

French短期反转使用过去一个月表现的低组减高组，但它是美国、按市值与过去收益分组的组合收益定义，并不规定A股Rank IC范围。[原始构造说明](https://mba.tuck.dartmouth.edu/pages/faculty/Ken.French/Data_Library/det_st_rev_factor.html)

《Size and Value in China》使用2000—2016年资料，在其设计中排除最小30%股票，并采用公告日在月末之前的最近财报、含非流通股的总股本计算市值。这些原文条件说明“规模”“估值”不能只凭名字复现；也不是要求本系统不加判断照搬该剔除规则。[原论文](https://doi.org/10.1016/j.jfineco.2019.03.008)，原件Appendix A.1、PDF第16页，已复用本地保存版本。

BP/EP后续验收还应核：分母是否与股票类别和股数一致；季度数据若是年初累计，滚动12个月利润须按“本期累计＋上年全年−上年同期累计”组合，并逐个确认这些值在当时已公开、口径一致。这个公式本身不证明本系统已经实现或数据合格。禁止把财年12月31日当公告日，或用后来重述值倒填旧决定。

## 最小决策卡

- **改善了什么：** 用真实132个月材料校对方向、月份、分组与来源；找到请求和返回复权标记未核一致的具体缺口。
- **付出什么代价：** 隔离1只来源、保留缺失/停牌边界；一次核心失败和一次有理由的修复跟进。当前证据仍依赖供应商报价及已看历史。
- **保留还是暂停：** 保留这份月度反转诊断作为可复核基准；不采用为交易策略。规模和估值效果暂不能判定。
- **恢复条件：** 下一项优先修复后续输入的返回字段资格检查，并核sz.001914原数据语义及旧用途影响；价值/规模只有在历史市值、财务字段及当时版本齐备后再开始效果复现，不为贴近文献结果改参数。

归置验收：成果树旧检查器最初报`.git`工作树文件、`COORDINATION.md`与`docs/coordination`三处既有白名单差异；当前主树规则只解决其中第一项。本轮登记窄范围后，复用已有成果的准确三路径修复，成果树全库检查通过；主树未改。失败与修正前后SHA留在hygiene-receipt，不靠删除资料凑通过。
