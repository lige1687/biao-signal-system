# FactorHub API 与 MCP 复用检查

版本：1.0.0；日期：2026-09-14；性质：有限只读供应商检查，不是因子有效性实验。
采用研究原则 v1.1、AI 执行合同 1.0.1。授权：用户提供本地凭据位置，要求检查 API 对系统的价值及可避免重复建设之处。截图为接入说明，不视为安装或改全局配置指令。

## 一句话结论（大白话）

有价值，但本轮证明的是“部分 A 股数据可取、可作候选来源”，不是“买到完整因子研究能力”。最值得复用数据供应和现成 AI 调用包装；自己的定义、时间资格、IC 重算、研究偏差检查和资金归因仍要保留。实际测试的 ETF 行情/分红为空，因子 scores 返回汇总绩效而非逐股票评分，不能据接口名字认定能力齐全。

## 1. 实际检查与边界

- 13 次带 Key 的 HTTPS GET：12 次 HTTP 200，最后一次 HTTP 429（请求过快），立即停止，无重试。HTTP 200 包含空表，不全算数据成功。
- 无回测 POST、购买、账户模拟、模型拟合、依赖安装、MCP 配置改动、生产/对象登记表/OKR 修改。
- Key 只在进程内从用户指定文件提取，通过 `X-API-Key` 发往 `https://factorhub.cn`，未打印或存入产物。未向包仓库、搜索或模型配置发送 Key。
- 查询来源：官方 API 文档及其公开前端说明；PyPI 0.1.0 wheel 静态读取，未导入执行；实际 API 响应。未核查供应商底层数据库或原始数据授权链。
- 请求输出留在本次工具执行记录；本报告保留路径、参数与观察摘要。未保存完整响应原件，不能宣称具有完整可离线复现的输入快照；未来正式接入必须补齐快照。

## 2. 逐项实测

统一前缀 `https://factorhub.cn/api/v1/`。日期参数均为 YYYYMMDD。

| # | GET 路径/参数 | 观察到的结果 | 能与不能证明的事 |
|---|---|---|---|
| 1 | factors?page=1&page_size=2 | total=208，返回2条 | 有因子目录；未读取全部208个定义 |
| 2 | factors/MOM001/metrics | 汇总绩效，含 ic_mean、alpha、beta | 有平台计算结果；未返回估计窗口、完整模型卡或样本，不能独立复算 |
| 3 | factors/MOM001/nav?start_date=20260101&end_date=20260109 | 空净值数组 | 指定范围无返回；原因未知，不能说全部历史缺失 |
| 4 | calendar/trade-dates?exchange=SSE&start_date=20260101&end_date=20260109 | 5条，首条20260105，前交易日20251231 | 有日历候选；未与交易所公告独立对账 |
| 5 | market/daily?ts_code=600519.SH&start_date=20260105&end_date=20260109 | 5条 OHLCV，含 pre_close/pct_chg | 股票行情查询可用；未核复权与成交量金额单位 |
| 6 | 同上，ts_code=510300.SH | 空表 | 此ETF在该接口该范围未取到，不外推所有ETF不支持 |
| 7 | index/weight?index_code=000300.SH&trade_date=20260101 | 空表 | 历史成员覆盖未证实 |
| 8 | stock/dividend?ts_code=515300.SH | 空表 | 此ETF分红未取到；空表不能解释为没有分红 |
| 9 | market/indicators?ts_code=600519.SH&trade_date=20260109 | 1条，含ma_5/10/20/60、ret、volatility、停牌等字段 | 能省批量预计算的潜力存在；窗口、缺失和复权语义未核 |
| 10 | factors/MOM001/scores?start_date=20260105&end_date=20260109 | 返回与#2相同的汇总绩效结构 | 这条实际调用不是逐日逐股票评分；日期是否影响计算未获证明 |
| 11 | factors/MOM001/nav?start_date=20260907&end_date=20260911 | 空净值数组 | 第二段范围也未取到；不推断原因 |
| 12 | index/weight?index_code=000300.SH | 300条，首尾记录日期20260701 | 能取默认名单；未逐行核所有日期/重复/权重总和，不能当9月14日或任意历史的合法名单 |

请求计划中后续的行情重复读取/MA5独立手算和指数行情调用，因429提前结束，**没有执行**。不把计划当核验。没有计算或验证本地IC，没有重算供应商绩效。

## 3. 截图中的 MCP 能省什么

检查 `factorhub-mcp` PyPI 最新发布版本0.1.0的wheel源码（只读，未安装）：

- `client.py` 通过 httpx 请求同一个 REST API，`server.py` 转成工具和JSON文本；它不是本地因子计算引擎。
- 实际工具10个：list_factors、get_factor_scores、get_factor_nav、get_market_daily、get_index_daily、get_valuation、get_stock_info、get_stock_list、get_trade_dates、run_backtest。
- 官网 API 文档列出的 MCP 工具更多，名称也不完全相同；不能假定截图那条 pip 命令安装后即获得官网全部工具。
- 包内 get_factor_scores 的说明是因子绩效指标，client 路由 `/factors/{code}/scores`；本轮真实响应与其包内说明相符，但与网页“所有股票评分和排名”的说法不同。
- 可节省 AI 工具描述、参数转发、认证传输的重复包装；尚未验证安装兼容性、运行安全或工具调用端到端。
- 若正式采用，应隔离环境固定版本，密钥走环境变量或密钥存储，启用只读工具白名单。run_backtest 本轮不授权；不将 Key 写入仓库或聊天。

## 4. 对 LeiSignal 的建设取舍

| 层次 | 复用判断 | 自己仍需承担 |
|---|---|---|
| 日历、股票行情、股票基本资料、公司行动、分类 | 优先评估供应商供数，没必要为每类数据自造采集器 | 身份/单位/来源、完整性、限流缓存、快照、历史修订、实际覆盖；本轮只验证其中部分 |
| 常规技术数值 | 定义一致且逐值对上后可用预计算值，不必重复做大规模计算服务 | 小型独立公式校验不能省；双均线道路状态、EMA起点、宽度共同分母等本地语义不能被同名指标替换 |
| AI 获取数据 | 可以复用MCP包装，非主线前置 | 固定工具版本、只读权限、凭据保护、错误与空表处理 |
| 因子候选目录 | 可作灵感和外部比较对象，不必自行搜集全部名称 | 精确公式、使用范围、版本、依赖、注册和证据等级 |
| IC与分组诊断 | 可参考成熟工具，但本次scores不能代替输入明细 | 用同日各标的信号与未来实际收益重算；宽度是市场共同状态，不能复制给ETF后硬算同日排名相关 |
| 是否过度贴合历史 | 不能由平台给一个高IC或显著结果替代 | 尝试史、按时间划分验证、未来收益窗口交叠、未见行情跟踪；可以复用统计实现，不自造一整套统计库 |
| 策略归因 | 平台单因子alpha/beta不能解释我们的具体账户 | 真实持仓/交易/现金/分红/费用对账；固定其他规则比较决策差；适配收益模型及不确定性 |
| 交易可执行性 | 平台回测最多是另一个对照，当前未测 | 本地入场/退出/回补、资金竞争、成本、成交约束与生产授权 |

我们的差异化不是重新实现所有均线函数或另写HTTP库，而是让“自有规则→可追溯计算→适配检验→完整交易判断”贯通。通用研究能力建设不等待本供应商接入，不转向以个股选股代替宽指/ETF主战场。

## 5. 采用结论与下一步（非新增执行授权）

当前决定：**保留为候选，不作为唯一数据源，不接入正式策略。**

最能改变判断的是向供应商核清：

1. 是否有逐日逐股票的原始因子值/排名API？与当前scores有何区别？公式、预处理和历史版本在哪里？
2. ETF行情、复权、分红拆分是否另有接口，覆盖哪些产品和区间？
3. 历史指数成员是否有完整变更/生效记录？月度日期含义是什么，为什么默认返回7月？
4. 行情/因子的原始来源、可得时点和修订政策；能否保存研究快照及内部AI处理？
5. 发布包为何只有10个工具，官网较新工具对应哪个受支持版本？秒级限流、分页和单次行数上限是什么？

取得回答后，下一次只选一条明确数据链做少量、按供应商限速的资格验收。没有必要现在批量下载208个因子、安装整个平台或重写当前长任务。
