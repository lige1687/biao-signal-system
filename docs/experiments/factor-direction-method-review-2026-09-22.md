# 因子基建、研究方向与方法复查（2026-09-22）

## 一句话结论（大白话）

基础建设有价值，原先规定的研究方法也基本正确；当前需要调整的是工作重心：最近越来越容易用“多核验几张卡、更多测试通过”代表前进，而“这些东西将帮助我们选什么、何时参与、投入多少、少承担什么风险”尚未形成同样清楚的交付。建议暂缓自动续开逐卡补证批次，先整理已有用途和证据，围绕一个实际问题明确最小缺口与下一步取舍。宽度用于仓位管理已有研究基础，应先接续旧证据，不能重新当成一个全新想法。

本轮是方向和方法审查：只读当前代码、登记表、既有报告与服务端目标台账；没有重跑历史收益、预测统计或真实行情实验。下述优先级属于主控建议，不是策略有效性结论。

## 2. 做对的部分应保留

- 定义有精确版本，缺价、包含当前值、确认时间等含义开始被真正核对；B9/B10选择新版本承接含义变化，保留旧结果，做法正确。
- 人工价格与独立计算能发现真实错误。B14没有因为测试全绿就把波动历史位置标成通过，最后保留未验证，这是有效的复核。
- 程序区分资产之间的排序、单个对象的状态、全市场共同状态。`factor_lab/diagnostics.py` 对共同宽度误请求资产排名相关时明确拒绝；不能说当前系统已经把一切因子都拿去做同一种统计。
- 研究原则已明确仓位管理可以有价值，不要求每个模块独立创造额外收益；完整资金、简单对手、现金、费用、长期落后及恢复时间的要求也已存在。
- 已有失败与负结果保留，研究和生产分开。此次审查没有理由推倒重建一套新平台。

## 3. 需要调整的六处

### 3.1 工作排序逐渐偏向“容易验完”，缺少实际问题的结束标准

B12补宽度B200与200期距离，B13补50/200期均线、站上、上穿六项，B14补站在200期均线以上及波动位置。这些工作消除了计算和接线缺口，但增加的市场信息与可行动取舍并不随卡数等比例增加。多张卡复用同一价格序列和计算函数，不能算多份互相独立的市场支持。

尤其是，[单标的交易规格](../trading-spec-v1.md) §4的核心均线组是20/60/120期EMA与SMA；当前 `candidate:lei.dual_ma.bull_state@draft-1` 仍在研究适配层作为候选。50/200期作为简单参照和基础组件合理，但它们接通不等于LEI双均线及其决策价值已经研究完。

建议：下一批先回答“这项工程将解除哪个具体研究障碍，解除后交什么判断”；只有被这个问题需要的计算组件才优先补证。核心双均线、宽度仓位、选强与风险管理各自的优先级应据已有证据和资料可行性确定，不仅依据哪张卡容易升级。

主控自我纠正：上一轮我建议直接绕开RV卡继续补无歧义卡，范围安全，但作为长期排序理由不充分；不能把它继续当作默认推进方式。

### 3.2 宽度的读数、用途与政策需要分清，且应先承接已有研究

宽度指某个明确股票范围内，有多少合格股票处于某种趋势位置。读数本身没有唯一买卖含义。

实际已有：

- `breadth.three_tier@1.0.0` 将宽度映成三档比例；历史定义是低宽度对应较高投入、高宽度对应较低投入。
- `policy.breadth.csi300.w0` 至 `w3` 等对象已登记“三档周目标＋增持确认＋完整账户执行”。登记不代表这些旧消费者已完成统一入口迁移。
- [2026-09-09宽度与纯50日对手报告](breadth-price50-decision-2026-09-09.md)已经研究ETF资金安排，保留两项有限候选，同时写明历史名单、当时资料可得性及长期落后的限制。

因此，上一条聊天把仓位用途描述成以后才开始探索，遗漏了已有工作。需要研究的是“已有规则在哪里有价值、代价是什么、证据缺什么”，不是从零再造一套仓位方案。

也不能据用户建议直接推导“宽度高就多投”或“宽度低就少投”：既有逆向安排与顺趋势风险控制是不同假设，数据本身不决定方向。

未来若评价宽度的仓位价值，应在固定买卖逻辑、相同资金和成本条件下比较是否使用宽度调节仓位，并保留预先规定的固定较低仓位等简单对手。评价同时看跌幅、恢复时间、长期落后、错过上涨和费用。仓位减少后跌得更少，不足以单独证明宽度判断更好。

这一方法建议来自现行研究原则；本轮没有选择新的比例、阈值或运行实验。相同平均仓位不等于相同风险，也不能看完整段历史跌幅后反推“公平仓位”。

### 3.3 受阻分支与整个研究体系的关系需要更清楚

B4受阻涉及所冻结的输入与价格调整合同；A3涉及特定历史可得性材料；宽度还另有历史成员名单与共同计算范围问题。它们不是同一个缺口，不能统称为“还差一点数据”。

原目标明确固定14只ETF的全部历史资料不是通用能力开发的总前置条件。不过，真实用途必须满足自身资料条件，当前未获准的新真实运行和预测统计也不能通过改叫“仓位比较”绕过。

建议先做一张按用途划分的资料表：每项问题需要什么输入、已有材料能支持到哪里、哪一个缺口实际阻止下一步判断。对新研究问题，可事前界定有意义且资料可行的范围；不得为了让旧B4通过而缩掉困难样本或改写原合同。找不到可行路径也应给出明确暂停原因和重新启动条件，而不是无限补文档或无限查档案。

依据：[B4第二批结案](factor-b4-source-evidence-recovery-batch2-2026-09-20.md)、[原目标](factor-research-workbench-mandate-2026-09-14.md)、[四方向选择记录](../research/proposals/factor-next-phase-4dir-2026-09-19/p1-decision-package.md)。

### 3.4 独立计算有用，但尚不能充分覆盖共同假设错误

B14是具体反例：同一份RV20输入的严格排名计算一致，而原人工价格整体乘1.1后536个有效排名中506个改变，最大约44.5个百分点；乘7恰好不变。旧测试通过的是特定缩放与稳定夹具，并未证明一般数值稳定。

当前 `test_factor_lab_rv_rank_recovered200.py` 的缩放测试仍只检查乘7；其中一个期望值取自被测底层 `quote_features`，适合检查接线一致性，不能算第二份独立公式证据。独立证据另在原始实验目录，这两种证据必须分别说清。

建议把已知失败输入纳入后续日常可执行检查，明确记录当前预期暴露的限制，并在新版本检查时再次使用；不能靠改成更稳定的数据后只报通过。还应分别核公式语义、输入价格口径、可知时间、数值边界和完整路径，避免两套程序共同采用错误前提。

本轮维持RV旧版未验证的裁决，没有改测试或增加小数容差。依据：[B14报告及勘误](factor-b14-rv-rank-recovered200-controller-review-2026-09-21.md)、[Astra裁决](../archive/handoffs-plans/2026-09-21-factor-b14-rv-tie-astra-decision.md)。

### 3.5 自进化已有一个实际成果，但对重复错误与成本的反馈不足

已采纳的交付前结构预检是一项真实成果：6份冻结样例能暴露缺字段、占位文本，并允许合法的描述型卡。案例为 `approved`，检查步骤也写进了准入清单。

但其[采纳建议](raw/factor-c-m23-2026-09-20/method-recommendation.md)明确说未来返工率、工时节省、对新形态的误报漏报均未知；[成本记录](raw/factor-c-m23-2026-09-20/cost-record.json)主要填写“低”，没有可比较的实际数量。因此只能说建成并采纳了一种方法，不能说系统已经证明更便宜或更会研究。

同时，[B12](factor-b12-b200-distance200-controller-review-2026-09-21.md)与[B13](factor-b13-trend-backbone-controller-review-2026-09-21.md)都记录了更新登记状态时误改其他卡、由测试抓住再恢复的问题；B12还记录误把含真实资料读取的脚本当作纯结构校验。后者没有产生预测统计，也不作为本批升级依据，但确实超出了该批“只用人工数据”的执行范围，不能概括成全过程毫无偏差。

建议下一项方法改进优先针对这些已出现的重复错误：按精确编号核对预计修改集合与实际修改集合、执行前核对脚本会读取哪些资料。用有限新任务观察是否降低误改和返工，并保留必要复核；无须启动自动调参或新的通用调度平台。明确计划继续交Sol中等强度执行，含义与关键反例由主控审查，是合理的成本分工。

### 3.6 当前状态入口有相互矛盾的旧信息，会造成重复研究

本轮读取服务端权威台账发现：

- D子线v4的下一步仍写“Q2裁决待用户”，但其裁决包已追加2026-09-19选择通用能力优先的决定。
- C子线v10的下一步仍写预检执行中，而同一条的证据已记录完成并采纳。
- A子线v7的下一步仍含“B/C暂停”，后续B与C已分别继续。
- 父方向v9仍有P1未裁决的旧描述；使用手册列六张卡，但当前研究适配层已扩充。

这些是当前入口与后续记录未同步，不说明所有旧冻结文件都应改写，也不表示尚未人工结案的状态可以擅自改为完成。

建议只更新现行导航和既有条目的下一步，指向最新证据；历史原件保留日期。每一轮报告优先讲“哪个问题有答案、哪个问题仍缺证据”，把完成卡数和测试数放在附属记录里。本轮只指出差异，没有改台账、完成标准或授权。

## 4. 研究方法应按用途选择

| 实际问题 | 合适的验证 | 不能据此直接得出的结论 |
|---|---|---|
| 从ETF中选哪些 | 事前固定可选范围，检查当时排序与后来相对表现，并在需要时核完整账户 | 排名相关就能拿到净收益 |
| LEI道路或触发是否有额外价值 | 与简单趋势对手对照，明确确认和执行时间、失效与回补；一次只改变指定动作 | 均线、上穿各自通过人工计算就证明组合有用 |
| 宽度能否帮助安排投入比例 | 固定买卖逻辑下比较仓位方案，完整记录现金、风险、踏空、恢复与费用 | 把同一天相同宽度复制给多个ETF就得到多份独立证据 |
| 波动或其他读数能否提醒风险 | 检查对应风险及执行代价，需要时比较固定低投入比例等简单方案 | 必须能预测上涨才算有价值，或少跌就说明更聪明 |
| 解释已有策略结果 | 先核资金贡献，再做单动作对照，按需要解释共同市场风险 | 解释不了的部分全是独特能力 |

这些用途在既有规范中已有位置，不要求新增一套类型、状态或“因子平台”。旧研究中的有条件正结果与负结果都应保留；不能因为新工作线没有新增有效性证据，就说整个项目从未做过效果研究。

## 5. 建议下一轮的具体交付与结束条件

下一轮建议先交“一项实际问题的最小研究方案”，优先梳理宽度仓位这条已有证据链，同时核清它与LEI双均线技术交易的用途边界。第一步只整理现成材料，无须新跑策略：

1. 从既有定义、报告和消费者整理用途表：它回答什么、输入范围是什么、证据到哪一步、接在哪个决策位置；标出同源或重复对象。
2. 接续已有宽度资金研究：列出已比较过的简单对手、保留/暂停原因，以及当前仍真正阻止判断的资料缺口；不重复已完成的50日对手实验。
3. 明确一个问题、最小补证范围、固定对照、可接受代价的待定项和停止条件；先审资料可行性，才提出需要的真实运行范围。
4. 只安排能解决该问题或重复严重错误的工程工作，逐卡补证不再自动续批。

结束条件是给出一个有依据的选择：继续现有有限候选、只作风险提示、暂停某种接法、或资料不足暂不进入真实评价。无需宣布找到有效因子，也不以完成全部登记卡作为前置。

这仍服务于原有的自有因子库与受控方法改进目标；不会把项目改成固定14只资料搜集工程。真实实验、阈值/仓位规则变更和生产应用继续按各自明确范围处理，旧冻结合同不被本报告替换。
