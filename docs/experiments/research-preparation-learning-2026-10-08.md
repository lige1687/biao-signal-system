# 金融含义优先、旧错误复用与五个外部项目的接入判断

日期：2026-10-08。范围：研究准备与方法选择；本轮不计算因子收益。负责人：`theory-workflow-system-increment`。服务于技术体系的研究验证层，金融含义与范围仍由两份权威策略原文确定。

## 一句话结论（大白话）

已经把“先说清相信的现象和定义，再查过去相关错误”接入本地 AI 研究指引，并做成可实际调用的只读准备工具：读取完整定义、相关旧案例及来源，14项测试和5次实际调用检查符合预期。五个开源项目都有可借部分，其中来源追踪最适合现在使用，排名诊断和系统分层按具体问题采用，完整研究平台暂不迁入。这里证明的是准备步骤可用，还没有证明所有 AI 都会遵守、重复错误减少了多少或投资效果改善。

## 1. 用户要解决的问题与本轮增量

本轮沿用户最新要求收敛：金融含义是第一要义；AI 下次研究应读到已有错误和处理依据；外部项目应说明具体帮助与接入位置。没有把任务改成仓位研究，也没有重跑旧因子。

本库已经有唯一因子定义表、方法案例库、合同、来源检查和归档入口。发现的缺口是：原案例库中的12条记录主要靠 AI 自行定位；准确对象解析可以核版本，但不能自行判断“这个计算是否表达了想研究的现象”。新增工具复用这些资料，不再造一套定义表、错误库或研究控制器。

|已有能力|本轮补上的动作|边界|
|---|---|---|
|准确对象版本、继承定义及依赖解析|准备时一并展开完整定义、依赖和来源核对结果|公式文本被读取，不等于已独立验证算法|
|12条方法案例，包含被拒记录|按准确案例ID或主题检索，返回匹配原因、原状态、旧新做法及出处|文字匹配可能漏掉措辞不同的案例|
|现有研究合同及主控复核|把金融主张、定义反例、案例适用判断写回原位置|理由有文字不等于理由正确|
|已有失败归档|明确新错误要留下触发条件、最小反例、修复与影响；可计算错误加入对应测试|一次负结果不能变成永久禁止研究的规则|

## 2. 金融含义怎样落实到 AI 的准备动作

先写“我相信哪一种现象可能帮助判断什么”，再写公式和运行配置。AI 必须解释预期关系与适用背景，同时将尚未证明的解释保持为假设，不能从漂亮数字倒推金融故事。

沿现有研究卡记录六件事：相信的现象与背景；精确计算、方向与单位；窗口端点、价格及缺失处理；观察与确认信息何时可知；相邻定义的区别与区分例子；什么结果会削弱原判断。新想法尚未登记可以先讨论定义，正式研究仍走准确对象版本和原资料检查。

一个人工例子足以说明为什么不能省略这一步：100跌到96，跌4元、4%；200跌到194，跌6元、3%。按金额看回调变深，按比例看变浅。同一组观察在回答两个不同问题。这不证明哪个因子有效，却能在计算之前揭露定义分歧。例子与精确算式留在 [semantic-counterexample.json](raw/research-preparation-learning-2026-10-08/semantic-counterexample.json)。

对“回调越来越浅”，还须区分跌幅、均线触及层级与持续时间；低点若依赖后来确认，要明确确认日。金融含义清楚并不保证效果成立，它先保证研究确实在检验原想法。

操作说明已加入 [factor-validation-guide.md](../research/methods/factor-validation-guide.md) 的“挖掘前先讲清金融含义，再读取相关旧案例”。现有 AGENTS → 研究入口说明 → 方法指引链路继续可达。原指引全文保留，没有替旧冻结研究倒填新要求。

## 3. 如何让旧错误在下一轮真正发挥作用

新模块：[preparation.py](../../src/lei_signal/research/preparation.py)。示例：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m lei_signal.research.preparation \
  --definition-ref mixed.momentum.raw@1.0.0 --term 协议 --term 缺失
```

输出包含完整定义与依赖、来源路径和指纹、相关案例及原状态、命中原因、截断和缺失信息，以及金融含义审阅问题。未知版本会拒绝；未登记想法只输出准备资料。所有成功输出都明确 `execution_authorized=false`，工具不联网、不运行研究、不修改案例状态。

AI 的后续责任是读案例原证据，判断本轮适用与否，把理由和出处写回原合同的对应复核项。一个案例过去获批不代表本轮自动适用；被拒案例也必须保留。真正依赖的来源再由原合同绑定，原研究入口继续执行自己的检查。

经验复用需要完整循环：发生错误 → 留下可复现反例和原因 → 修复后核影响 → 下次准备时检索 → 在对应步骤验证。机器可检查的问题落实为测试；解释或方法选择的问题保留有适用条件的复核要求。日志本身不等于下一轮已吸取教训。

三类旧例说明边界：协议绑定错误需要核实际对象与输出身份；资料身份问题不能仅靠自洽日期或指纹排除；结论写得过满需要回到原证据判断。工具把这些证据带到准备阶段，但不能替代科学判断。案例库未读到和正常检索零命中已明确区分，二者都不允许解释成“没有风险”。

## 4. 五个项目具体能融入什么

|项目|对系统的具体价值|采用判断与限制|
|---|---|---|
|Alphalens Reloaded|补充观察分组成员更换率、前后排名稳定性，帮助判断因子排序是否频繁变化|现有排序联系与分组收益分析不重建。两个诊断在具体排序问题需要时做小适配；成员更换率不等于资金换手，排名稳定不等于预测好。默认未来收益极值过滤不能直接沿用。|
|OpenSourceAP/CrossSection|学习把论文、原定义、实现与反证放在一起追踪|最适合现在借其证据组织方式，接回已有定义与方法卡。此前 Mom12m、DownsideBeta 的表格和代码差异仍需按原论文核清；美国股票结果不证明本地ETF有效。|
|pysystemtrade|把信号尺度、信号组合、风险规模和执行缓冲分别处理，让因子的用途明确|借分层设计；具体公式仅在相应研究授权中比较。标准化分数不是概率，波动尺度不是止损距离，不搬入整套期货交易引擎。|
|Qlib|数据读取、处理器与模型资料范围的组织方式；特定模型问题可做薄适配|本地冻结、资料资格和评价已存在。原始、学习、推断资料类型不等于训练和评价日期划分，历史可知时间仍要由LEI检查。没有证明整套替换更划算。|
|RD-Agent|限定任务的执行、保存、失败留痕和恢复；已有小范围真实试跑可复用|此前固定接口调用本地均线核过65行，但未验证完整自动提出因子和研究反馈。保留停止步数与资源清理问题；按真实请求设限，不能把循环步数当硬预算。完整自动研究继续是候选。|

以上决定来自代码、已有真实试跑和本轮官方说明核查，不按星数或安装数量判断价值。Alphalens 的默认清理设置可能改变评价资料；CrossSection 的实现差异说明“有出处”还不等于“定义已对齐”。这些反例正支持金融含义和实现核对优先。

三个项目沿用 [上一轮固定源码审阅](literature-tools-fit-2026-10-08.md)，12份文件指纹本轮重新核过。Qlib沿用 [公式审阅](qlib-alpha158-definition-review-2026-09-12.md)，本轮补读官方 [数据组件](https://github.com/microsoft/qlib/blob/main/docs/component/data.rst) 与 [Handler说明](https://github.com/microsoft/qlib/blob/main/qlib/data/dataset/handler.py) 的相关摘录，没有执行Qlib引擎。RD-Agent沿用 [试跑审阅](rdagent-pilot-controller-review-2026-09-27.md) 和 [反馈失败记录](rdagent-model-feedback-review-2026-09-27.md)，补读 [官方介绍](https://github.com/microsoft/RD-Agent)。旧收费请求失败不代表当前所有模型永久不可用，本轮没有重新试收费调用。

各项目准确版本、输入输出、接入验收与阅读深度见 [project-fit.md](raw/research-preparation-learning-2026-10-08/project-fit.md)。未完整阅读的接口不宣称已核；本轮没有安装第三方项目或测得新增投资收益。

## 6. 本轮决策与适用边界

- 采用：本地准备工具及指引，用现有定义和旧案例支持研究前判断；不新增方法状态，不授予执行权限。
- 按需采用：外部项目的来源追踪、排名诊断和系统分层；具体实现需要实际问题、输入与验收，不为“接入”再搭平台。
- 不作效果宣称：没有因子性能或交易收益增量，故不生成虚构的因子性能表。本轮工程增量已在第1节逐项对照；减少重复错误的幅度仍未测量。
- 局限：关键字检索可能漏例，方法含义仍需 AI 审阅；工具尚未成为所有研究运行器的强制前置检查；成果目前仅本地，所有远端AI是否读取尚未核实。

本轮问题已经完成有边界的实现与核查。后续自然发生的研究可沿原失败记录观察是否正确引用案例、是否再次发生同类错误；无需为证明这套准备步骤重跑旧市场实验。
