## 3. 遗漏一：OpenAI风格流内错误没被识别

位置：`src/lei_signal/plans/llm.py::_request_completion_stream` 的OpenAI分支。

代码解析JSON后直接读choices，无choices就跳过，未检查顶层error。主控合成输入：正文“半句话”→ `{"error":{"message":"provider failed","type":"server_error"}}`：

- 直接结束连接：结果原因是no_completion_marker，丢了真正的服务错误原因。
- 后面还有 `[DONE]`：结果没有任何中断标记，半句话仍按正常完成返回。

这不是要求每个真实供应商都会这样返回，而是上轮固定“流内服务错误”契约的确定性反例：错误不能被后来的结束标记洗成成功。

执行方 `test_llm_stream_completion.py` 实际没有OpenAI流内error用例，用HTTP非200用例替代了它，二者不同。因此不能称“5场景×双协议全覆盖”。

最小修复：明确识别该分支支持的流内error结构、保留server_error_event原因，后续结束标记不得覆盖。新增error→EOF及error→DONE两例，并保留正常和额度截断对照。不要重写协议框架、扩大到其他供应商接入。

## 4. 遗漏二：刷新后只有标签，无法原问题重试

位置：`web/src/pages/AgentWorkspacePage.tsx` 历史加载映射、`TurnRow` 重试条件；以及提供历史重试身份所需的最小服务端投影。

当前历史映射只恢复 `answerIncomplete`，没有 `incompleteDone`、`requestBody` 和 `clientRequestId`。按钮要求 `incompleteDone && requestBody`；处理函数又要求原cid。独立渲染结果：

- 当时的失败卡：重试按钮可见。
- 同形状的恢复历史卡：未完成说明可见，重试按钮不可见。

历史提示改成“可重新提问生成”，普通重新提问是新问题，不能满足上轮“刷新/历史仍未完成→同身份重试”的用户路径。后端API单独拿测试里的cid重试通过，不能代替用户从历史页面取得原身份。

最小修复：历史接口提供可核实的重试身份，或提供原问题的专用重试入口；前端恢复并使用它，不能重新随机生成cid或用当前会话/当前标的猜原请求。不强求暴露整份内部请求。旧记录不可考时明确不可原问题重试，不伪造字段。

固定验收：中断→刷新→打开历史→真实点击重试→服务端模型桩累计调用2次→原问题数仍1→完成后再次恢复显示最终回答；旧部分原文保留。再验证已完成问题不会被旧部分记录上的重试入口重新生成。只需隔离服务和模型桩，不发真实模型请求。两个入口若共享同一历史流程可以复用证据，清楚说明实际入口。
