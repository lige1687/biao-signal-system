## 4. R2：包清单、元数据和冻结历史补件

### 当前结果包

CLI的 `f.name != 'manifest.json'` 会排除所有层级同名文件，漏掉嵌套输入manifest。应仅排除 `f == out/'manifest.json'`。现在漏件虽可由protocol.input_identity中的固定哈希间接核验，不构成已知数值错误，但“全文件双向一致”声明不成立。

计划要求的CSV旁置metadata未输出；observations有x_date却没有承诺的成熟时刻列。当前固定CN时刻可从x_date和冻结协议恢复，但不要宣称字段已写出。

修复未来CLI清单与metadata输出；当前run-02全部只读，在包外 `supplement/` 新增：

1. 全文件补充清单，包含嵌套input-package/manifest.json，绑定旧顶层manifest SHA及所有文件；不能改旧包。
2. states/observations旁置metadata，绑定各CSV SHA、对象、单位、布尔/缺失规则、时点语义；成熟时间以固定x_date+15:00 Asia/Shanghai映射规则注明“补充恢复”，不是原运行已经输出。
3. 规范、卡、任务书原字节及完整补件清单；从现存内容补存前须匹配原协议所声明哈希，不匹配就列缺口，禁止补造。

### 旧冻结原件与预算

freeze_build将两个版本写到同一 `freeze/code-snapshot` 并覆盖environment。现存b1_contract字节不匹配v1.0.0声明，匹配v1.0.1；即使v1.0.0协议文件保留，也不等于其代码冻结原件保留。先有限查本任务目录现存原件，有则核哈希引用；没有则如实记不可恢复，不从哈希编造旧源码。该版本在输入核验失败，未算真实结果；这不影响现存v1.0.1结果，但属于冻结纪律偏差。未来冻结目录按版本排他建立，不共用覆盖。

恢复核验实际失败一次、纠错后再一次，协议上限1次。记为2次及单项超预算，不写“1次目的”。首次真实CLI被计入2/2尝试预算是保守且可接受的，实际成功计算仅一次，两者分列。
