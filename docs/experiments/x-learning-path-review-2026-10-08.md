## 推荐的内容路径

`作者和问题 → 原帖及关键讨论 → 论文/博客/代码原文 → 中文学习卡 → 现有学习库 → 可选帖子草稿`

保留贴文方案最有价值的三点：围绕我们正在困惑的问题搜；把反驳和作者回应一起看；学习成果可以止于理解，不必自动变成因子实验。

建议第一版先覆盖趋势与退出、ETF组合风险、研究方法三个主题；10—15个来源、3组问题是建议起步配置，不是已建立的订阅。一次最多给3条，没好内容就不凑数。探索来源可以保留，进入本地研究前仍沿用原定义、资料资格、预算和授权。

学习卡保留：回答什么问题、最值得学的一点、原作者提供了什么证据、关键质疑、适用的市场与交易条件、我们已有资料是否重复、原始链接与真实阅读范围。帖子草稿再使用这些已核内容；研究候选由原研究负责人处理。

不要在第一版同时开展全量 X、YouTube转录、多平台运营及自动实验。先验证 X 加原文的这一条内容链是否能给用户持续提供愿意读的东西。YouTube能力未在本轮核查，贴文中的相关细节不作为本次已验证结论。

## 贴文方案需要补齐的三个地方

1. **检索出来的回复不等于全部讨论。** `conversation_id:`找同一回复串，引用讨论需另查`quotes_of_tweet_id:`。7天近期检索只返回窗口内符合条件的帖子；更旧内容、不可访问内容和未取完的分页均应明确标记。见[搜索介绍](https://docs.x.com/x-api/posts/search/introduction)与[操作符](https://docs.x.com/x-api/posts/search/integrate/operators)。
2. **读取后的状态会变化。** 原帖可能修改、删除或转为不可公开。若保存 X 内容，官方政策要求按其当前状态修改或移除，收到相关请求后的24小时要求有明确条件；不能把原帖全文永久写进不可撤回的知识档案。第一版优先保存ID、链接、阅读范围与学习整理，原文显示或存储另按接口条款设计。见[开发者政策](https://docs.x.com/developer-terms/policy)。
3. **内容发现与通知日程分别设计。** 后台每日收集和每次主动发消息是两件事。当前按需查看约定可继续使用；若以后需要学习简报，单独明确频率、渠道、是否无好内容时静默及付费上限，不沿用已暂停的日常交易通知。
