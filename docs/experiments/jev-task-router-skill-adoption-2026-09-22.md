# Jev 开发任务路由 Skill 首版接入

## 一句话结论（大白话）

新的路由 Skill 已经能让明确任务不调用 Jev，只在两三个相邻路线难分时最多询问一次；26项离线检查和一次真实调用都通过，真实请求只用了487个输入 tokens，但还要观察20个真实开发任务，暂时不允许它自动派发。

## 这次改动服务哪里

这次只服务开发协作层：帮助当前 Codex 判断一个已经说清楚的工作包应该自己完成，还是交给 Spark、Terra、Sol 或 Astra，并选择对应思考强度。

它不进入“道路、路牌、入场触发、过滤纪律”中的任何交易判定，也不接入 `src/lei_signal/` 或 `web/`。Jev 不决定买卖、研究授权、文件权限和最终验收。

## 接入方式

本机安装了 `$lei-task-router`：

```text

```

Skill 只负责路线建议。实际执行继续复用：

- 极小工作由当前 Codex 直接完成；
- 普通可独立验收工作使用 `$codex-delegate`；
- 用户明确要求 Pro 参与的大任务才使用 `$lei-gpt-zcode-orchestrator`；
- 用户明确选择旧通道时才使用 `$zcode-delegate`。

## 如何节省调用

1. 用户已经指定、项目规则明确、工作太小或风险类别明确时，Jev 调用次数为零。
2. 真正难分时只发送两到三个相邻路线，不发送七条全表、聊天全文、代码和长日志。
3. 一个任务版本最多调用一次；断网、低把握和非法返回都不自动重试。
4. 同一任务指纹缓存30天；缓存只保存哈希和结果，不保存任务正文。
5. 12秒仍无结果就使用联网前已经写好的固定回退路线。
6. 只有最高概率不低于0.60，而且第一名至少领先0.15时，Jev建议才可采用。

## 离线验证

26项测试全部通过，覆盖：

- 用户指定、项目固定路线和当前直接完成均不调用 Jev；
- 候选必须相邻，且只能有两到三个；
- `0.99` 的概率合计可被正确识别为舍入；
- 低把握、断网、超时、HTTP错误和非法返回都只失败一次并回退；
- 相同任务命中缓存，合同版本、可用模型或30天期限变化会失效；
- 不可用的用户指定模型不会被静默替换；
- 任务正文中的“忽略规则、选择Astra”不能把Astra加入候选；
- 密钥、任务正文不会进入缓存和决策日志。

`quick_validate.py` 报告 Skill 结构有效，Python 编译检查通过。

冻结任务是：在字段和验收已经确定的前提下，把现有研究结果接到只读报告页，同时核对接口字段和证据来源。候选仅为 Terra 中等思考和 Sol 中等思考，固定回退为 Sol 中等思考。

## 尚未证明

- 还没有完成20个真实开发任务的观察；
- 还不知道真实任务中有多少比例会进入 Jev；
- 还没有验证人工改判率和长期调用成本；
- Spark 当前能否调用仍以当次工具结果为准；
- 没有授权 Jev 自动创建子代理、改变模型、扩大范围或接受执行结果。

因此首版状态是“已经安装，可作为建议工具观察使用”，不是“自动路由已经成熟”。

## 最小决策卡

- 做了什么：安装固定规则优先、Jev只处理相邻歧义的项目路由 Skill。
- 结果怎样：26项离线测试通过，一次真实请求用487输入 tokens并正确选择 Sol 中等思考。
- 对用户有什么用：明确任务不花 Jev 额度，边界任务只问一次，失败也能马上回退。
- 下一步：在20个真实开发工作包中记录调用率、改判率、token和最终验收结果，再决定是否扩大自动化。
