## 方法：统一描述、关系检查、组合验证

### 1. 每个因子有一张准确的说明卡

内部和外部因子使用同一套身份字段；不把论文名、代码函数名、收益曲线名当作同一对象。

| 属性 | 为什么影响组合 |
| --- | --- |
| 精确公式、方向、单位、版本、原文和代码 | “盈利”可能是毛利润/资产，也可能是经营利润/权益；同名不等义，正负方向也必须核对 |
| 金融理由与竞争解释 | 延续、暂时卖压、估值补偿、经营支撑等机制为何可能互补；替代解释是什么 |
| 用途 | 选股票、决定何时交易、减少风险、分配资金、解释背景分别评价 |
| 市场和股票范围（Universe） | A股/美股/ETF、历史成员、行业、规模、成交条件分别绑定；不能按事后赢家选池 |
| 观察频率、预测期限、持有与调仓规则 | 周度反转与年度盈利不能直接相加原始数值，须先规定共同决策时点与使用方式 |
| 信息可取得时点、修订和缺失 | 财报所属年度不等于当时已公布；缺失不能当低分、零值或直接删掉后冒称全市场 |
| 已有表现、失败、费用、维护成本 | 已证伪用途保留，新增组合须说清为何值得重开；外部高回测收益不直接迁入本地 |

AI可以从资料中提取这些属性并附原文证据，程序核结构、身份和数据；未知属性不让AI补写。论文目录、已经算好的历史收益和可计算的逐股因子要分开标识。

### 2. 先判断哪些东西可以放在一起比较

同市场、同一批当时合格股票、共同日期、目标期限和成本口径对齐后再计算关系。A股和美股分别验证；跨市场资金配置还要统一币种、日历和可交易工具。公开作者收益可以用于公开组合比较，不能代替单股财报及可交易价格。

若不同因子覆盖不一样，同时报告共同覆盖和被排除部分；不能只留下数据最齐的幸存公司。原始价格加工家族先标为可能重复，但不按名字直接判无效。

### 3. 至少看四种关系，不只看一张相关热力图

| 关系 | 回答什么 | 使用限制 |
| --- | --- | --- |
| 同日股票评分的排名相关 | 是否反复把同一批股票排在前面 | 每个共同日期分别计算再汇总；不能把股票和月份混成长列产生假相关 |
| 实际持仓与权重重叠 | 最后是否仍买同一批股票、同一行业 | 需要真实选股与权重；名称不同不代表风险不同 |
| 完整策略扣费后的收益相关 | 两套方法是否经常一起涨跌 | 同资金口径、共同日期；没有费用就明确毛收益，不补造净相关 |
| 下跌期共同损失与恢复 | 平时看似互补，遇到压力是否一起亏 | 单月正负只是描述，不自动等于牛熊；当时可知环境另验证 |

扣掉市场参照后的收益差额相关可辅助解释，但不等于已消除行业或共同风险。正负方向对齐后，接近正负1都可能提示信息重复或相反表达；不能只挑数值最小、最负的一组。高相关也可能在关键情形有帮助，低相关可能仅是噪声。

可把关系相近的因子归成几组（通常称聚类），每组优先留下解释清楚、资料可靠、成本较低的代表，再从不同金融来源挑少量组合。关系和权重只用当时之前资料估计，在后面的未参与挑选时期检查；不看完整历史后再宣称早就可以如此分组。

### 4. 将“合并信息”和“分配资金”分开

**合并信息选股**：同一股票同时满足两项条件，或把方向一致、同日可用的排名按事先权重合并。比较单项A、单项B、简单平均，以及联合条件；同时看筛掉了哪些好机会。盈利＋资产增长的本轮公开联合分组是有限例子，尚不是本地逐股实现。

**给完整策略分配资金**：各策略已有股票范围、信号、调仓、退出、数量、费用和缺价规则，再比较固定等金额、按风险分配、带权重上限的方案。权重优化只是提出候选，不能保证后来更好；须与简单分配比较，并限制集中和换手。

按当时市场环境切换是第三个独立问题。不能把历史上各环境的最优方法拼成一条可实现曲线；先有实时能判断的环境定义，再计切换费用和错过上涨。

### 5. 用新增帮助决定保留，不按低相关直接采用

候选加入前后保持资金、日期和股票资格一致：多赚多少、少亏或多亏多少、错过多少上涨、多花多少交易和维护成本。相对最强简单单项与简单配置都列出；对应母指数另列，不用同池平均冒充。

全部试过的候选保留记录。只有完整规则和资料合格，才建立冻结版本；前向表示规则确定后才新产生的观察，不是从过去挑一段较新的历史。收益用途和风险用途各有明确判断，不统一强制一个相关系数或收益阈值。

## Skill 和系统接口应放在哪里

现有 `lei-lowfreq-research` 的 `references/strategy-combinations.md` 已明确资金配置、联合选股、环境切换；`research-closure` 管理有边界的研究和负结果；`lei-data-availability`、`lei-causal-validation` 按需要核资料时间和后期验证。无需另装一个把它们全部重复的“自动赚钱Skill”。

建议沿原工作台的“比较与组合”增加一条受控流程，作为原负责人的补充需求：

1. 选市场、股票范围、用途和持有期限，查询已有精确因子版本及外部参考。
2. 展示能比较的组合与不能比较的理由，合格共同数据才生成上述关系表。
3. 给每个提案附金融理由、已有信息、待检验的新帮助、最强反例、完整规则缺口和负责人。
4. 生成沿现有研究入口的有限合同，执行结果和负结果回到同一条记录；未有完整策略时不自动送入前向，更不自动交易。

这条流程可以由一个薄的Skill调用既有查询和研究工具，但**Skill文字本身不能代替实际数值矩阵、组合构造程序或历史资料**。本轮没有新增Skill或服务接口，没有把提案写成已经实现。通用搜索工具只能找资料，无法凭因子名称计算相关性。

## 取舍、增量与停止条件

| 问题 | 现有能力 | 这次明确的增量 | 当前决定 |
| --- | --- | --- | --- |
| 能否统一知道内部和外部因子 | 已有唯一登记和部分检索 | 准确身份、属性、资料资格和覆盖清单先统一 | 沿已有目录补齐，避免第二套库 |
| 能否由低相关形成好策略 | 个别历史实验已有相关及曲线 | 分清评分/持仓/收益/压力四种关系，并核新增帮助 | 低相关只作提案理由之一 |
| 是否需要外部框架 | 有本地入口和部分Alphalens适配 | 外部目录、诊断、研究组织、资金优化、AI编排各归合适步骤 | 窄组件比较优先，未决定迁移或安装 |
| 是否现在启动批量挖掘 | 另有工作台负责人实施 | 方法与接口位置已说明，未重复开发 | 沿其暂缓安排，不因本次询问启动 |
| 收益、净超额是否改善 | 本轮未新增实验 | 无可报告的效力量级 | 未评价；不能把方法归档叫策略变好 |

本轮问题是方法与工具选择，来源和本地现状已足以回答；不需要为了回答“有哪些方法”再运行新收益实验。后续实施必须沿现有工作台负责人和准确文件范围；首个有效验收应能对一个固定问题给出来源完整的组合提案、强对手和实际结果，而不是导入更多名称。
