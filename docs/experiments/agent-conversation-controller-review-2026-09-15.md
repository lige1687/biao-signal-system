## 4. 固定补修一：没有收到正常结束，也被算成完成

位置：`plans/llm.py::_iter_anthropic_stream`、`_request_completion_stream`。

独立输入为“部分正文”后两种结束方式：①连接正常关闭但无 `message_stop`；②服务器发 `type=error`。实测两者都只返回半句话，`interrupted=false`，与正常 `message_stop` 无区别。当前只捕获 requests 异常，未消费协议完成/错误状态。OpenAI风格分支也缺失无正常终止的处理，应在同一个完成契约中核对。

最小修复：按支持的协议识别正常终止、服务错误、缺终止与截断原因；明确未完成不能依赖“Python迭代器没抛异常”。不另造流式框架。共用的买点包装函数也须保留原有失败降级语义。

固定验收：正常完整流；正文后正常EOF但无完成标记；正文后服务端错误事件；网络异常；输出额度截断。对Anthropic/OpenAI各自支持的事件按实际协议验，合成事件即可，不新增付费模型请求。正常例不能为适配实现而省略正常终止。

## 5. 固定补修二：当时说未完成，历史却记成已回答，重试不再生成

位置：`api/routes/agent.py` 流式落回答段、`_append_answer` 与既有请求身份/历史消费路径。

独立测试从真实路由产出“按系统资料，先观察。”后中断：

- 当时 `verify_note` 有“未完成”，但 `answer_state=answered`。
- 数据库正文只有半句话，`meta_json` 只有trace，没有未完成原因；请求状态也为answered。
- 用同一 `client_request_id` 重试，只收到原半句话和 `replayed=true`，提示丢失；模型调用数仍为1。

所以“可重试同一问题”承诺未实现，刷新后也不能准确区分未完成与其他未通过校验的回答。`grounded=false` 是校验状态，不能充当完整性状态。

最小修复：持久化与显示回答完整性及失败原因；复用原问题和冻结依据，允许对未完成结果进行明确重试；旧部分原文保留、最终完成结果不重复建问题。沿现有身份和历史接口局部调整，不重审已通过的全部记录体系。前端两个入口消费同一状态，不能把所有done都当作完整答案。

固定验收：正文中断→当时提示→刷新/历史仍未完成→同身份重试确实再调用→成功后原问题不增加且可恢复最终结果；并发重复重试不重复生成；正常完成重试继续只回放；资料卡保留。使用临时库和可控模型桩。完成后只运行相关回归，不重跑全仓或4轮付费案例。
