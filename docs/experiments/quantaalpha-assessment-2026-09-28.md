# QuantaAlpha：有没有研究增量、能否接入

日期：2026-09-28｜类型：外部研究方法与软件评估｜结论：有条件保留

## 一句话结论（大白话）

**值得接入一小段研究流程试验，但目前不能说它比我们现有 GPT 研究更有效。** 我们已实际调用它的记录组件，成功保存、重读三条已有研究结论；同时发现旧记录可能被覆盖、默认成功标准不适合我们的 ETF 问题，部分检查配置也没有接到实际执行处。下一步最有价值的是让它提出和修订候选，由我们固定的研究程序核实有没有新信息，再与直接用 GPT 做同题比较。

## 1. 本轮到底验证了什么

用户要求：“quantaalpha也可以看看呢，评估一下是否真的有效，能接入”。沿用“能否提供新信息”的目标，不以公式数量或历史赚钱作为验收标准。

服务于策略的**研究假设与证据记录层**：可为道路（均线方向）、A 回调等提出候选解释。没有改变道路、路牌、触发、过滤纪律的生产定义，也没有新增交易规则或账户实验。因此本报告属于方法评估，不冒充新的收益实验。

| 验证层次 | 本轮证据 | 判断 |
| --- | --- | --- |
| 软件是否有实际研究流程 | 固定源码中五步串联及反馈、候选选择 | 有实际实现 |
| 小组件能否在本机调用 | 上游记录组件保存、重读成功 | 已验证限定能力 |
| 作者历史研究是否有积极结果 | 最新论文及对照表 | 有有限支持，未独立复现 |
| 能否直接研究我们的 ETF 问题 | 默认股票排序与本地目标不一致 | 需要适配 |
| 比现有 GPT 多发现有用信息 | 未做同题、同资料、同预算的软件对照 | 尚未证明 |

本轮两位执行者均为 GPT-6 Sol / medium，分别核论文、源码；复用已有子代理上下文，不声称全新盲评。主控另核关键代码、来源指纹、论文指标定义并执行本地组件调用。

## 2. 论文应怎样理解

以 2026-05-18 的 v3 为准。主结果是约 150 个筛选后因子共同输入 LightGBM 模型，任务是股票池预测和组合，不能移作单因子或 ETF 择时证据。[官方论文 v3](https://arxiv.org/html/2602.07085v3)

| GPT-5.2 主结果 | v1 | v3 |
| --- | ---: | ---: |
| 因子数值与随后涨跌的相关程度（IC） | 0.1501 | 0.0472 |
| 扣费后相对基准的年化超额收益 | 27.75% | 4.68% |
| 超额收益曲线的最大峰谷跌幅 | 7.98% | 11.80% |

最后一行不是实际账户最大亏损。两版数字变化明显，原因未查明；不能据此推断造假或数据泄漏。v1 已采用扣费超额口径，不能解释为 v3 才开始扣费。[v1](https://arxiv.org/html/2602.07085v1)、[v3 附录 A.1](https://arxiv.org/html/2602.07085v3#A1.SS1)

v3 同模型比较优于两种研究代理，但传统 TRA 在七项指标中六项更好；移除部分研究步骤后的结果变差，支持流程可能有用。作者约 20 小时、180 万文本单位的运行也不等于我们的调用成本。**ETF适用性、超过现有 GPT 的信息增量均没有得到验证。**[v3 表1、表2及附录 A.4](https://arxiv.org/html/2602.07085v3)

## 3. 实际调用结果：能存，但需要我们的证据账

固定来源提交：`b7ceb27b1001261d7a95b209a963664ae1f8ab23`，与 9 月 24 日评估相同；本轮增加的是核查深度和真实组件调用，不是上游发布了新版本。公开源码选取 89 个文件，主控逐一核对指纹一致。

本轮直接加载未修改的 `factors/library.py` 与 `pipeline/evolution/trajectory.py`。后者的项目日志依赖明确替换为 Python 日志输出；没有模拟模型回答或计算结果。一次执行完成，无修补重跑、无安装、无外部模型 API、无新行情回测。

输入来自我们已完成的三题研究，以“已有证据引用”适配存储，**不是三个可执行的新因子，更不是 QuantaAlpha 发现了这些结论**。

| 实际检查 | 观察到什么 | 对接入的意义 |
| --- | --- | --- |
| 保存并重读已有证据 | 因子库 3 条、轨迹记录 3 条 | 可复用部分记录能力 |
| 没有股票排序指标的研究结论 | 原生成成功数为 0 | 必须更换成功标准；不代表已有研究无效 |
| 同名同表达式再次保存（人工测试资料） | 旧库条目被新实验覆盖 | 原生因子库不能独自承担完整尝试历史 |
| 同表达式换名字（人工测试资料） | 形成第二条记录 | 名字不同不能算新信息 |
| 一次实验包含两个因子（人工测试资料） | 同一实验指标附到两条记录 | 不能据此认定每个因子都有独立作用 |

轨迹组件在显式 `fresh_start=False` 时可恢复历史；不能把因子库覆盖问题扩大为“整个框架都没有历史”。完整观测见 [observations.json](raw/quantaalpha-assessment-2026-09-28/probe/observations.json)，执行与输入见同目录 `run_probe.py`。本次成功仅限这些组件，未运行原生生成、进化与完整回测循环。

## 4. 代码里影响接入的具体问题

以下均指固定源码，完整文件位置和行号见 [源码证据](raw/quantaalpha-assessment-2026-09-28/code/findings.json)。

1. **质量检查需要逐项落实。** 循环读取一致性、复杂度、重复度开关，却只传入一致性开关；部分阈值采用代码默认值，没有采用配置文件值。一致性检查默认关闭，开启后不一致也只警告。历史因子数值相关性去重的一段代码由 `if False` 关闭；同名删除仍存在，不能说全部去重都失效。
2. **默认成功标准不同。** 轨迹以 RankIC（公式排序与随后涨跌排序的一致程度）判断成功和挑选候选。我们关注同一 ETF 中某个条件是否提供新判断信息，需要更换评价和选择逻辑。
3. **调试用结果不能充当最终验证。** 循环模板实际使用 2021 年评价并反馈给下一轮；独立回测配置才指定 2022—2025 年，而且默认使用已有因子集。模板注释与实际年份还存在不一致。未执行继承自外部 RD-Agent 的完整运行过程，不能仅据配置认定实际隔离正确或已经泄漏。
4. **接口有扩展位置，但本地连接尚未实现。** 上游可替换运行与反馈组件；本地 `calculate_batch` 仅接收已登记、已实现的公式，研究脚本也不是通用执行接口。不能把任意生成代码直接交给生产系统。
5. **依赖与许可仍有待办。** 依赖固定 `rdagent==0.8.0`、未固定版本的 `pyqlib`；当前解释器缺 Qlib 等依赖。仓库标示 MIT，但完整树未找到 LICENSE 文件，许可原文仍待确认。GPT兼容接口存在，当前模型与账户实际调用能力未测。

这些是接入成本和可靠性问题，不足以推断论文实验使用了同样配置。[固定源码](https://github.com/QuantaAlpha/QuantaAlpha/tree/b7ceb27b1001261d7a95b209a963664ae1f8ab23)

## 5. 建议的接入方式与下一次验收

**让 QuantaAlpha 负责提出、修订候选；让 LeiSignal 负责计算和判断证据是否成立。**

流程：提出假设和预期反例 → 本地检查定义与资料资格 → 固定程序计算 → 返回新增信息、覆盖范围和失败原因 → 限定次数修订 → 每次尝试追加保存。

- 继续使用现有实验报告库展示结果；原生因子库作为索引，完整尝试历史由本地不可覆盖记录保留。
- 保留现有 ETF 定义、全部机会及缺失记录、既定观察期限与比较对象。研究代理不能自行修改评价程序。
- 下一次建议一题、两个研究方向、至多四个候选版本，每方向修订一次。与直接 GPT 使用相同资料、评价程序和预先固定的调用预算。
- 给两边相同的“已经知道什么”清单；已用过的历史继续标为探索资料。有效增量包括新事实、反例或可检验候选，经独立核实后改变具体研究取舍。
- 同时记录重复建议、失败、人工介入和实际调用成本。没有新增信息也保留结果，预算用尽即结束。

详细接口与前置条件已写在 [接入草案](../archive/handoffs-plans/quantaalpha-assessment-2026-09-28/integration-plan.json)。这是下一轮可执行范围的草案；本轮尚未安装完整框架或实现连接器。原生试验前需独立环境、可用的 GPT 调用渠道、上述检查及记录适配。Codex 中使用 GPT 不等于 QuantaAlpha 的 GPT API 已配置。
