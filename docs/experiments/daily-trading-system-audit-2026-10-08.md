# 日常交易价值：系统多角度审查与改造取舍（2026-10-08）

## 一句话结论（大白话）

系统已有相当多研究、图表和计划工具，但目前最影响日常使用的是：真实持仓、可用资料、原计划与处理记录还没有顺畅接起来。此次实际页面和接口显示，29只已记录基金全部处于资料待补状态，技术结果和计划关联均为0；新闻最近一次成功运行停在9月5日。优先完成这些已有功能的真实接入，比继续增加一批指标更直接。因子研究并非没有成果：它排除了部分“多加条件就会更好”的想法，修复了计算和证据问题；但所核代表性研究尚未证明稳定改善交易。

本轮是系统审查和方案取舍，非策略有效性新实验。核查时间为2026-10-08凌晨（北京时间）；检查本机运行服务、持仓/基本面/Agent页面、75项目标、最新远端协调记录及相关报告。没有重新计算市场结果，没有测试真实模型回答，没有改生产或交易规则。现存持仓记录日期为9月4日，不代表今天实际账户；节假日与不同市场公布日未独立核定，不能把所有9月末数据一概判成故障。

## 3. 推荐优先推进的改造

优先级是产品判断，不是已测收益排序。首批应接续旧目标，不并行新造七个模块。

### 第一优先：先让“我的持仓”对现有产品真正有用

用户问题：“我已有的东西今天有什么变化？原来为什么持有，现在还成立吗？”

先确认持仓记录是否仍有效，区分场内ETF、场外联接基金、主动基金和海外产品。当前页面统一要求完整同产品技术行情，29只全部资料待补，暴露出产品类型与技术工具适配的缺口。场外基金并不一定有可用的开高低收和成交量，不能伪造，也不能把跟踪指数当作基金成交价。

增量：保留严格同产品判定，同时允许展示明确标注的净值走势、公布时间、产品合同限制和用户原持有理由；有可靠对应关系时展示指数/ETF背景，但分开价格身份和用途。让“技术条件暂不可算”不至于变成“所有信息都无用”。

验收：选已有真实产品逐类验证；未知原理由保留未知；每张卡能解释数据截止、当前变化、原计划是否可核；已确认计划关联后刷新和次日仍正确。当前基准为技术0/29、计划0/29，不能靠错误映射提高覆盖率。

复用目标：okr-4c2ea452d3cc。当前持仓真实性必须由用户资料确认，审查未更新金额或计划。

### 第一优先：修好资料更新和“今天”的含义

用户问题：“看到的是最新情况，还是旧东西？”

接续消息恢复任务，核实际运行服务、调度、抓取、存储、页面和Agent消费。资料统一区分观察日期、公布时间、取得时间、页面生成时间，并按市场日历与发布频率解释；固定研究快照明确不会随刷新变新。已有观察卡和日期字段复用，不再造另一套日期系统。

验收：源中断、正常休市、周/月度未到公布日、旧缓存、部分成功五种状态分清；简报与Agent不把旧资料描述成今日变化；成功更新有新记录读回，失败仍可查看旧资料但清楚标注。

复用目标：okr-5d40309b29ae；基本面部分与investor-observation-map核范围。健康接口ok只代表服务能响应，不代表数据可用。

### 第一优先：Agent围绕一项交易判断完成工作

用户问题：“帮我复核这笔持仓，哪些事实支持，哪些事实反对，下一次看什么？”

复用已接通的持仓上下文和计划流程。回答顺序：一句当前判断及资料日期→最关键支持/反对依据→缺什么→接下来观察的既有条件。用户能点击回到具体图表、消息原文、计划版本。跨日保留的是用户已确认理由和当时证据，不自动把聊天推测变成账户事实。

不用先增加模型数量。先用固定真实任务测是否找对产品、引用对日期、承认资料缺口、回答同一个问题并节省查找。必要动作包含整理原理由、核查计划、解释条件变化；新建/变更计划继续走确认流程。

验收：同名产品/A-C份额、切换标的、资料过时、没有原计划、否定持仓、追问昨日判断等案例；对照现有入口记录查阅步骤、回答时延、事实错误和缺失遗漏。工程已实现不等于真实模型质量通过。

复用：okr-b1ce64d26449、okr-8f4f1a5f026f及持仓原任务。计划版本和动作日期按10月7日已有成果核采用，不重做。

### 第二优先：基本面从“指标多”走到“理解这类资产”

保留用户偏好的图表为主、价格与指标同时间轴。按问题组织：上涨主要来自盈利变化还是估值变化？利率和汇率背景在变什么？市场走强覆盖更多股票还是少数股票？这些信息与所看ETF有何关系？

每组只保留核心曲线、数据日期、单位和简短解释；相关不等于因果，参考线不等于买卖线。宏观、盈利、估值、情绪分开，不合成未经研究的总分。对ETF补充其实际跟踪对象、已披露行业构成和集中程度；完整实时盈利共识、历史公布日等未取得就留空，不补故事。

验收：用户能从图中回答变化方向、资料时间、对应资产及一条反例；新增解释不进入技术过滤。已有价格叠加与市场观察持续复用，不能重复立项“建设宏观面板”。这项预期改善理解，收益增量未测。

### 第二优先：把新闻做成“与我有关的事件变化”

现有消息雷达已经关联自选，增量在持仓相关性、同一事件去重、原始来源及后续进展。区分事实公告、市场预期、作者观点和模型解释；未知预期不得生成“超预期”。保留当时版本，后续事实推翻旧观点时可以看见。

示例：一条海外利率消息，先指出涉及哪些已持有资产和为什么值得看，再链接原文；不凭利多利空条数生成买卖指令。

验收：同一事件多家转载只计一个事件；无新事件和抓取失败分开；重要消息关联关系可追溯；缺来源不当已核事实。须先解决新闻更新，再加摘要能力。

### 第二优先：看清“看似很多基金，实际押了几件事”

持仓页已有季报前十大和分类，先复用。增加同基金不同份额合并观察、同指数重复持有、已披露行业/市场/币种重叠及未知覆盖比例。主动基金季报只能说明披露时的局部持仓，不能当今天完整穿透。

增加交易前的现金、申赎到账、持有期、费用、场内折溢价等产品核对候选；具体规则来自核实合同，不凭通用假设。这里先帮助识别重复承担的风险，不自动建议目标仓位。

验收：重复份额不误当独立分散；前十大不冒充全仓；持仓金额日期一致或明确不可合并；缺现金就不输出完整账户配置。新增比例规则或调仓策略需独立定义和研究。

### 第二优先：复盘回答“哪里做错了”，研究回答“以后少做什么”

先接通已有计划版本/动作日期成果，记录信号出现、用户决定、实际申报、实际成交、没有操作的理由；未知不倒填。每周看偏离原计划、资料错误、延迟和事后改理由，而非只看盈亏。

研究页在现有结论卡上增加用途结论：可作描述、未证明新增帮助、资料不足、可做前瞻观察；再单独标运行采用状态。每项只写回答的问题、相对简单做法多了什么、适用对象、最后证据日期和负责人。负结果落成“本批不再加这个条件”，而不是又添一份难读报告。

验收：用户能在一分钟内看懂本月哪三项结论改变了使用方式；不能把定义版本数量或测试通过数显示成有效因子数量。接续K-human-effect、K-forward-protocol和okr-266b531f965d等原条目；不自动改其授权或完成状态。

## 4. 发散候选与暂不优先的方向

| 候选 | 为什么可能有用 | 先决条件/反例 |
|---|---|---|
| 今日变化优先列表 | 少翻页面，只看计划、价格条件和重要事件的新变化 | 必须已有可靠前次快照；旧数据不能制造“变化” |
| 条件场景图 | 用已有触发/失效位展示成立、等待、失效三种路径 | 不生成未经验证概率，不自创技术规则 |
| 机会排除原因 | 解释为什么暂不纳入计划、缺哪个已定义条件 | 当前机会面板已有，先核能否复用，非新评分 |
| ETF产品比较卡 | 同指数产品比较成本、跟踪偏差、流动性和产品限制 | 当前合同/连续资料资格未齐，不承诺现在能完成全市场比较 |
| 事件日历 | 让用户知道哪些已确认事件将公布，减少临时翻查 | 时区、延期、官方日期要核；预告不预测涨跌 |
| 个人错误模式 | 看追涨、计划后改、重复持有是否经常发生 | 先有真实行为记录；少量事例不诊断习惯 |
| 条件满足后的低噪声提醒 | 真有变化才提示，降低通知疲劳 | 需明确通知渠道、去重与用户授权；本轮不创建自动化 |

暂不优先：更多综合分数、更多相似均线因子、全自动调参、多个模型投票买卖、把宏观/消息变成硬过滤、另建平行研究台账。它们要么缺证据，要么扩大策略含义，要么不能解决本轮直接观察到的资料/计划断点。

## 5. 建议实施顺序与验收

1. **完成已有接入。** 持仓资料与产品身份、原计划整理、消息更新和资料日期。验收从实际产品到页面/Agent回答的完整路径，不以组件完成收尾。
2. **完成每天可用的工作流。** 今日变化→查看依据→确认自己的处理决定→次日延续。接入已做好的计划版本和动作日期。
3. **增加理解和比较能力。** 基本面按问题组织、持仓重叠、ETF产品比较、事件进展。以能否更快找到事实和识别错误衡量，不预先宣称收益提高。
4. **收敛因子研究。** 保留能改变具体判断的有界问题；复用负结果；待输入和用途明确后再进行与简单做法同条件的比较，不中断其他负责人已授权工作。

这不是要求所有研究停下，也没有替各负责人排新任务。本轮最值得先投入的是已有功能的最后一段接入，而非更多研究对象。
