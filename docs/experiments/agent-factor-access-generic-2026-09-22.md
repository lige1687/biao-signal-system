# Agent 因子研究通用接入：本地交付与主控复核

日期：2026-09-22。范围：读取已有材料；未部署，未执行真实行情计算、预测统计、收益回测或交易。

## 一句话结论（大白话）

研究侧现在可以按统一格式交付已有结果，登记准确版本和来源后，让 Agent 读取和解释。后续符合这个格式的因子不需要逐个修改 Agent 代码。人工测试验证的是接入能力，不是投资效果；当前值资格检查和自动执行实验都没有开放。

## 本轮选择的范围

用户授权主控决定范围，并追加要求“通用，后续因子也要能直接接入，研究侧的接入”。本轮将首版按对象写在代码里的材料绑定改为数据登记，并增加研究侧结果封装。只服务研究说明层，不改变道路、路牌、入场触发或过滤纪律。

沿用研究原则 v1.1、执行合同 v1.0.1、定义标准 v1.1.0。权威文件与共享工作区起始身份见 [baseline.json](raw/agent-factor-access-generic-2026-09-22/baseline.json)，分工见 [实施计划](../archive/handoffs-plans/2026-09-22-agent-factor-access-generic-plan.md)和[执行合同](../archive/handoffs-plans/2026-09-22-agent-factor-access-generic-contract.json)。首版报告保留原貌，本报告说明后续变化。

## 研究侧怎么接进来

完整操作说明见 [研究侧接入手册](../research/factor-agent-access.md)。最小流程是：

1. 研究线在已有正式登记表维护准确的 `ID@版本`，因子算法继续由原研究入口负责。
2. 已经产生的 `ResearchBatch`，交给 `pack_research_batch` 封装；它只保存现有行、元数据和发现，不调用计算函数。
3. 把结果包放在研究产物目录，在 `configs/factor-access.v1.json` 登记版本、别名、证据类型、适用范围、限制以及来源路径和内容指纹。
4. 使用同一套 `validate_research_packet`、`load_access_catalog`、`read_materials` 检查。Agent 每次查询读取登记资料，不需要新增按因子名称判断的代码。

这份索引只是“哪个版本对应哪些材料”的目录，正式定义仍只有 `definitions.v1.json` 一处。候选草案继续明确标为候选，不能靠登记材料变成正式因子。别名重名或多个版本并存时要求澄清，不自动选最新版本。

## 复用了什么，还缺什么

| 能力 | 本轮入口与边界 |
| --- | --- |
| 正式定义 | 复用 `definitions.load_registry/resolve` 的说明用途；即使没有附加研究材料，也可查询正式定义 |
| 已有研究行 | 复用 `ResearchBatch` 的日期、对象、值、缺失原因和元数据；新增统一封装与读取，不新造计算平台 |
| 定义身份 | 复用 `factor_runtime.contract_digest`；单位、定义卡或版本不一致时拒绝 |
| 证据与比较 | 数据索引绑定精确版本的报告、范围和限制；保留计算核验、资料检查、预测研究、收益研究、风险描述的区别 |
| Agent 入口 | 复用普通/流式回复、问题快照、证据卡和报告库链接；相同请求重试使用原材料 |
| 旧因子面板 | 保留受限的历史参考适配；缺少正式身份与价格口径，仍不能作为合格当前值 |

仍缺：研究线提供的实际新因子结果和相应效果证据、合格当前值的资料条件及其核验流程、历史可知性证明。接入成功不能补出这些证明。本轮没有登记任何新真实结果，现有目录只迁入首批三对象的原有材料。

通用范围明确到现有输出格式：数值、0/1 或布尔状态、0 到 1 的比例，以及固定日期和对象的研究行。新的图形、复杂嵌套结果或不同输出类型需另做格式适配；不承诺任意程序都能直接运行。

## Agent 怎样选能力

先识别是在查定义、已有读数、效果证据、已有比较，还是提出新实验，然后绑定准确版本。查询读数还需绑定对象和明确日期；多个对象、多条不同结果都不自动挑选。通用集合对象可用 `entity_id=` 指定，不把它误认为证券代码。

读数按该版本的单位展示，说明定义要求的价格口径；这只是定义要求，不等于已经核实每项真实输入。保留原研究用途、输入身份和时间说明。观测日期、原计算时间、本次回复时间分开；没有可确认的数据截止或当时可知性就写未知，不拿观测日期或读取时间替代。

| 用户问题或失败情况 | 返回行为 |
| --- | --- |
| “这只 ETF 当前动量如何？” | 缺合格当前资料时明确拒绝；本入口当前未开放结果包的当前值资格检查，不刷新或计算 |
| “这个因子过去真的有用吗？” | 只解释准确版本绑定的研究证据和限制；没有索引就说尚未接入，不拿当前读数代替，也不声称全库没有证据 |
| “比较一下高点位置与普通动量。” | 读取已有概念比较并说明限制；缺实际比较研究时不判断谁更有效 |
| “开始回测 / 补测一下” | 只返回文本提案，不创建任务或运行研究，回测快捷端点也拒绝因子研究请求 |
| 版本不存在、同名多个版本、对象不唯一 | 拒绝或要求明确；不退回最新版或默认选一个 |
| 记录缺失、日期无效、重复行、无穷数、来源变化 | 明确没有可用读数或来源核验失败；缺失不补零，来源变化不自动重算 |
| 有计算核验但没有市场效果证据 | 保留两个状态，明确计算正确不能证明策略有效 |
| 风险描述或历史收益被要求用于买卖 | 不生成交易授权或收益保证，不修改规则与资格条件 |

## 来源和权限边界

来源链包括索引、正式登记表、报告、结果包文件及结果包里的原始来源，并保留各自内容指纹。文件变化就停止相应解释。来源只允许指定仓库目录，拒绝路径越界、符号链接越界、重复 JSON 键和代码入口字段。

封装支持人工资料，以及明确声明为历史重建的已有资料格式。两者都保留真实 `synthetic` 标识，均不授予生产权限或当前值资格。现有计算入口仍保持其原本的 synthetic-only 限制；历史格式支持不代表该入口能运行真实研究，更不代表本轮已获得真实研究结果。

材料中的文字不是执行指令。没有任意 Python/SQL、动态函数、后台执行或自行改授权的入口。四种含义始终分开：已登记、计算核验通过、指定范围研究可用、已有实际效果证据。
