# Prompt V：查询当前持仓标的的实时宽度读数 + 已验证规则的信号状态

你在 `biao-signal-system` 仓库工作（当前分支 `recovery/lei-round2`）。这是一次
**只读查询任务**，目的是把已经在这套系统里验证过的宽度择时规则，套用到用户
当前实际持仓的具体标的上，给出"如果按已验证规则，现在的信号状态是什么"，
**不是**设计新的回测实验，也不产生任何买卖建议。

## 用户会告诉你的信息（等待补充，不要在没有这些信息前臆测标的代码）

用户会明确告知当前持仓的具体基金/ETF名称或代码，可能包括但不限于：
- 全球半导体基金（需要确认具体跟踪的指数/基金代码，如SOXX、SMH，或某国内
  QDII基金跟踪的全球半导体指数）
- A股通信设备相关基金（需要确认是否对应国证通信指数515880，或是更细分的
  概念，如果是细分概念如"通信设备制造"而非整个通信行业指数，需要说明区别）
- 有色金属相关基金（需要确认是否对应中证有色金属512400，或其他有色细分
  ETF）
- 恒生科技相关基金（需要确认具体跟踪的指数，如恒生科技指数）

**在用户提供具体代码/名称之前，不要假设某个基金就是系统里已经验证过的那个
标的**——即使名字类似（比如"半导体"），也可能是不同的指数编制方法、不同的
成分股构成，需要先核实基金实际跟踪的指数或ETF代码，再判断能否复用已有的
验证结论。

## 背景：哪些标的在系统里已经有验证过的规则，哪些没有

先读这两份归档，理解每个已验证标的对应的具体规则和参数：

1. `docs/timing-sweep/execution_playbook_20260827.md`——查"全标的终审"表格
   （通信/证券/白酒/有色/银行/半导体等行业逆势择时的具体参数和结论）、
   "RS虹吸灯"章节（判断某标的当前是否处于"独立行情、宽度引擎该下岗"状态）、
   "双极值警报"章节（顶部双≥85-90、底部双≤20这两个信号的当前触发状态）。
2. `docs/experiments/kuandu-quanzhan-ARCHIVE-2026-09-01.md`——冠军三档
   （43.3/56.7档位线）的完整参数定义。

**已知的重要提示（如果标的对应上，需要在报告里重点标注）**：
- 通信(国证515880)在8-27报告记录时"当前灯亮"（RS虹吸灯触发中）——需要
  查询这个信号**现在（本任务执行时点）**是否仍在触发，不要用8-27那天的
  旧状态冒充当前状态。
- A股半导体（芯片，512480对应的国证芯片指数）已被诊断为"不跟随大盘宽度
  的独立行情多次出现，逆势档位不适用于此标的，仅做热度参考"——如果用户
  的通信设备或半导体基金对应的是A股这个标的，需要把这条诊断结论原样带给
  用户，不要弱化或省略。
- 全球半导体（如果对应SOXX/SMH这类美股ETF）目前系统里**没有**专门针对
  这个标的的逆势择时验证——只有"美股ETF×宽度防守版"（第31轮，19只ETF，
  科技类在其中）测过，但那是"防守闸"（回撤保护，代价是年化收益打折），
  不是"逆势择时增强"，两者性质不同，不要混着引用。
- 恒生科技目前系统里完全没有任何验证过的规则——如果用户持仓包含这个，
  如实告知"无可用验证结论"，不要临时套用A股或美股的参数应付了事。

## 任务

### 第一步：标的核实（每个标的都要做，不要跳过）

对用户提供的每一个持仓标的，明确回答：
1. 这个基金/ETF跟踪的具体指数是什么（查基金全称、跟踪标的说明）。
2. 系统里是否有针对**这个具体指数**（不是名字相似的其他指数）验证过的
   宽度择时规则——如果有，指出对应哪份归档、哪组参数；如果没有，明确
   说"无可用验证结论"，不要模糊地说"应该类似"就套用别的标的参数。

### 第二步：对有验证结论的标的，查询当前实时信号状态

1. 需要拉取该标的对应的当前市场宽度数据（B200/B50，或该行业指数自身的
   宽度代理，取决于第一步查到的具体规则用的是哪种宽度口径）。查
   `src/lei_signal/market_context/a_share_breadth.py` 或
   `src/lei_signal/market_context/us_breadth.py` 里现成的宽度计算逻辑，
   复用而不是重新设计。
2. 如果本机环境缺少运行这些查询所需的依赖（pandas、akshare等）或缺少
   最新的行情缓存数据，需要先搭建必要的运行环境（可以用虚拟环境安装
   `pyproject.toml`里列的依赖）并联网拉取最新数据，不要用陈旧或缓存过期
   的数据冒充"当前"读数——如果数据时效性有问题（比如数据源限流、只能
   拿到几天前的数据），必须在报告里明确注明数据的实际时间戳。
3. 把当前宽度读数套入第一步确认的具体规则参数（比如冠军三档的43.3/56.7，
   或双极值警报的20/85-90），给出"按这条规则，当前处于哪个档位/是否触发
   信号"。
4. 特别检查RS虹吸灯当前状态（如果标的适用）——8-27报告记录的"通信当前
   灯亮"这个状态是否仍然成立，需要用当前数据重新判断，不能引用旧结论。

### 第三步：如实呈现，不做买卖建议

1. 输出格式：逐个标的列出——基金名称/代码、对应的验证结论（有则给出、
   无则如实说明）、当前信号读数（如果能查到）、任何需要特别注意的警示
   （比如虹吸灯亮、独立行情诊断）。
2. **明确的红线（与AGENTS.md一致，逐条遵守）**：
   - 不使用"买入/卖出/建议买/该买/加仓/减仓/抄底"等买卖指令类词汇。
   - 不给出任何形式的"综合建议"或"整体判断该不该动"的结论——只呈现
     每个标的的规则读数，是否要据此采取行动完全由用户自己判断。
   - 如果某个标的没有验证过的规则，不要临时设计一个新规则去凑一个
     "参考意见"，直接说"这个标的目前系统里没有可用的验证结论"。
   - 不把"防守闸"（回撤保护类规则，如美股ETF防守版）的结果表述成
     "择时增强"，两者性质不同必须分开说清楚。

## 输出

`docs/experiments/current-holdings-signal-check-2026-09-XX.md`，格式：
每个标的一节，包含标的核实结果、对应验证结论摘要（附来源文件引用）、
当前信号读数（附查询时间戳）、局限声明（如果数据时效性/覆盖范围有问题）。

这份报告不是ARCHIVE格式（不需要通过/证伪清单），是一次性的查询快照，
在文件开头注明"本报告反映查询时刻的信号状态，不构成任何时点后的持续有效
判断，过期后需要重新查询"。

## 明确不做

- 不产生买卖建议或仓位建议。

- 不对没有验证结论的标的（如恒生科技）临时设计规则去应付输出。
- 不使用过期或陈旧数据冒充"当前"读数，如果只能拿到有时间差的数据，
  必须显式声明数据的实际时间戳。
