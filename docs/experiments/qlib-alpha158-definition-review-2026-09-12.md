## 一句话结论（大白话）

把 Qlib Alpha158 里最常见的五个公式逐个拆开核对了源码：**没有一个能直接拿来替换我们已有的定义**。
"均线相对位置"这一类和我们的"价格相对均线距离"在数学上能精确互相换算（同一个东西的两种写法），
不需要另建；其余四类要么方向反着、要么算的根本不是同一个量——比如它叫 BETA 的其实是
"价格走势的倾斜程度"，和通常说的"跟着大盘涨跌的敏感度"毫无关系。它们可以作为将来写新定义时的
公式参考，但名字相近绝不能当成同一个东西直接用。

## 3. 逐类核查

### 3.1 ROC — 可作公式参考，存在明确语义差异

- 官方表达式：`Ref($close, d)/$close`。Ref 实现为 `series.shift(d)`（ops.py:800-809），
  即 d 根前的收盘价除以**当日**收盘价。注释自述用途"除以最新价去掉量纲"。
- 输入/单位/方向：输入收盘价；输出无单位比值；**方向与涨幅相反**——上涨越多数值越小（<1）。
- 含当日：分母含当日；观察单位为 K 线行（按行移位，不是自然日）。
- 最小样本/缺失：无最小样本保护；历史不足 d 根时 shift 产生 NaN。并列、常数序列不涉及
  （常数序列 ROC=1）。
- 与本地关系：mixed.momentum.raw@1.0.0 = I(t−21)/I(t−252)−1——跳过最近 21 条有效报价，
  **分子是往前 21 条有效报价对应的经济价格指数，不是当前价 I(t)**；结果为涨幅。
  三点全不同：比值方向、是否跳过近月、端点（252/21 vs 5–60）。
  "方向相反"仅指公式层面：对**同一对价格端点**，反向价格比与正向涨幅是反向单调关系；
  本地与 Qlib 的端点和窗口本来就不同，不能据此宣称两者实际排序一定相反。
- 特别核查结论：**确认** ROC 是过去价/当前价，与我们跳过近月的动量不能等同。
- 复用前提与禁区：只有在未来某个已登记对象确实需要"过去价/当前价"这种反向写法时，
  才可照此公式新登记；不得改 mixed.momentum.raw 去"对齐"Qlib；不得因名称都含"动量"混用。

### 3.2 MA — 已有等价能力，无需另建

- 官方表达式：`Mean($close, d)/$close`。Mean 经 Rolling 调 pandas `rolling(N, min_periods=1).mean()`
  （ops.py:742-755、827-844），含当日，均线÷当日收盘价。
- 输入/单位/方向：输出无单位比值；**当前价相对于同窗口均线越高，MA 比值越低**——
  它描述当前价与均线的相对位置，不是时序上单调的方向指标
  （均线本身也在变：价格上涨过程中 MA 比值可升可降）。
- 与本地关系：trend.distance50@1.0.0 = P_signal/SMA50 − 1。对同一个 N、同一组合法价格
  观察，且当前价和均值均为非零有限值时：**MA_qlib = 1/(1 + distance_local)**，
  是单调递减的一一对应（通用 N=5 教学小例见 §4；这是数学关系，不是已接入的运行兼容性
  证明，Qlib 默认 MA5–60 也不是 distance50/200 的现成替代品）。
  trend.sma50@1.0.0 / etf.trend.sma50@1.0.0 即未归一的均线本身。
- 换算成立条件：窗口相同；均线含当日；满窗口（本地 min_periods=50，Qlib min_periods=1，
  序列前段 Qlib 用不足窗口的均值，换算不成立）；有效观察集合与预热一致；缺失处理一致；
  价格与公司行动口径一致（本地是分红/拆分连接后的 economic_index 或 ETF 连续价，
  Qlib 用其自有复权数据）。仅有相同数量的行不保证这些条件都满足；窗口、价格口径、
  缺失语义不同，不能声称完全等价。
- 复用前提与禁区：如需"均线/当前价"形态，用 1/(1+distance) 变换即可，不新建对象；
  排序用途下两者名次完全相反，混用会反转结论。

### 3.3 STD — 可作公式参考，存在明确语义差异

- 官方表达式：`Std($close, d)/$close`。Std 调 pandas `rolling(N, min_periods=1).std()`
  （ops.py:867-884），pandas rolling.std 默认 **ddof=1**（样本标准差，除数为 n−1；
  此为 pandas 文档默认行为，本次未单独抓取 pandas 源码，记为半确认项）。
- 输入：**价格水平**，不是收益率；输出为"价格散布/当前价"，近似变异系数的窗口版。
- 含当日、缺失（按主控审核 F1 修订，原描述"窗口内有 NaN 则结果为 NaN"不成立）：
  含当日；rolling.std **跳过窗口中的缺失值**，样本标准差（ddof=1）需要至少两个有效值；
  `min_periods=1` 不意味着一个有效值也能算出 std——仅剩一个有效值或全缺失时结果为 NaN。
  当前价缺失时，除以当前价的结果仍缺失。常数价格在至少两个有效值时 std=0 → STD=0。
  本规则经当前环境 pandas 2.3.3 独立复算确认（[10,NaN,12]、窗口 3 → std=√2≈1.4142135623730951，
  ÷12≈0.11785113019775793；单有效值 → NaN）；**这是 pandas 依赖行为核验，没有运行 Qlib
  表达式引擎**；当前价为 0、无穷值等其他输入资格不在该小例通过范围内。
- 与本地关系：mixed.rv20@1.0.0 = 最近 20 条简单收益的样本 std（ddof=1）×√252。
  两者都消除了货币单位、通常以小数表达，但**输入（价格水平 vs 收益）、统计含义
  （价格分散程度 vs 收益波动）、时间尺度处理（无年化 vs ×√252 年化）不同**；
  年化方式不同不能成为把一个直接换成另一个的依据。
- 特别核查结论：**确认** STD 用价格而非收益率，除数为 n−1。
- 复用前提与禁区：若未来要描述"价格缠绕程度/离散度"可参考此式新登记；它与 rv20 不互为
  变换，任何"波动率"语境下不得拿 STD 顶 rv20。

### 3.4 BETA — 当前不适用，暂缓

- 官方表达式：`Slope($close, d)/$close`。Slope 是收盘价对**窗口内序号 1..d** 的最小二乘
  回归斜率（ops.py:1221-1254；Cython 实现 rolling.pyx:49-88，递推式等价于
  (N·Σxy−ΣxΣy)/(N·Σx²−(Σx)²)），再除以当日收盘价。即"每个观察序号平均涨多少元/当前价"
  （序号是窗口内位置，缺报价时不是自然日）。
- 与市场 beta 无关：自变量是时间序号，不含任何市场/基准收益。**确认** BETA 是价格斜率，
  不是市场收益敏感度；backlog v1.1.0 的提醒属实。
- 缺失/边界：Cython 版跳过 NaN 用剩余点回归；常数序列 slope=0 → BETA=0；
  **窗口内仅剩 1 个非 NaN 点时，源码分母 N·Σx²−(Σx)²=0，无显式保护**（cdivision=True）——
  这是源码阅读发现的风险；未运行编译模块前，不把具体 NaN/inf 输出写成已实测结果。
- 与本地关系：登记表无价格斜率对象。`src/lei_signal/features/indicators.py` 等文件存在
  斜率类计算代码，但按定义规范，代码存在不等于已登记对象，本次不据此建立对应关系。
- 暂缓理由：backlog 第 4 类候选中"价格斜率先做描述"尚未立项；本地没有需要它回答的问题；
  名字误导性强，贸然引入有混淆风险。将来若要"趋势陡峭程度"描述，可凭本次源码笔记做
  小型适配验证（解决的具体问题：为候选"趋势一致性/斜率"描述提供无单位、跨产品可比的
  斜率口径），届时按定义规范新登记对象，不沿用 BETA 名称。

### 3.5 RANK — 可作公式参考，存在明确语义差异

- 官方表达式：`Rank($close, d)`（ops.py:1133-1168）：当前收盘价在**自身**最近 d 根收盘价
  （含当日）中的百分位。pandas ≥1.4 路径用 `rolling(N, min_periods=1).rank(pct=True)`，
  并列默认 average；旧兼容路径用 scipy `percentileofscore(x, x[-1])/100`
  （默认 kind='rank'，并列同样取平均），分母为非缺失个数。当前值为 NaN 时结果为 NaN。
- **确认** RANK 是单产品历史位置（时间序列分位），不是同日产品间排名；并列取平均，
  与本地 mixed.rv_percentile@1.0.0 的 ties=average 一致。
- 与本地关系：mixed.rv_percentile 是同一族算法（自身历史分位、含当日、平均并列、
  除以非缺失数），但排名对象是 RV20（波动）、窗口 756、最少 252 条；Qlib RANK 排名对象是
  收盘价、窗口 5–60、min_periods=1。mixed.momentum.rank@1.0.0 则是**横截面**有序名单
  （精确相等后按代码升序），与 Qlib RANK 是两种东西，不存在并列算法冲突问题。
- 常数序列：所有值相等 → 平均名次居中，d=5 时 = 0.6（不缺失）。本地 rv_percentile
  同族处理。横截面排序研究中的"常数截面应缺失"约定（定义规范 §7.1）针对的是 IC 类
  横截面诊断，不适用于此时间序列分位。
- 复用前提与禁区：若未来需要"价格自身历史分位"（而非波动分位），是**新对象**，
  可复用同族并列/缺失语义与本次源码参照；不得改 rv_percentile 的窗口去模仿，
  不得把 Qlib RANK 当横截面排名使用。

## 5. 公式、数据处理与预测目标的边界

按 Alpha158 handler 默认配置（handler.py:37-45、98-152）与示例流程 yaml 分清三层：

1. **原始特征计算**：§3 的公式串原样输出；Alpha158 的 infer_processors 默认为**空**，
   特征不标准化（注意 Alpha360 默认才带 ZScoreNorm 等，两者不同，不能混引）。
2. **数据处理**（按主控审核 F2 修订，原描述把 CSZScoreNorm 误写成按训练期拟合）：
   learn_processors 默认为 DropnaLabel + CSZScoreNorm（只作用于 label），
   process_type=PTYPE_A（学习集 = infer 链 + learn 链）。已补查同一固定提交的
   processor.py（快照见 `docs/experiments/raw/qlib-alpha158-definition-review-2026-09-12/supplement-2026-09-13/`）：**CSZScoreNorm 按 datetime
   分组，对同一日期不同产品的值做横截面标准化，构造参数没有 fit_start/end，
   不从训练期估计固定参数**；按训练区间拟合均值/标准差的是另一个类 ZScoreNorm
   （Alpha360 默认 infer 链使用，Alpha158 默认不用），二者不能因名称相似混用。
   本次仅确认这两类的分组方式与拟合接口，未运行处理器，未穷尽其调用的标准化函数边界。
   handler 配置中的 fit_start/end 只会注入声明了该参数的处理器，Alpha158 这两个默认
   处理器均不接收。
3. **预测目标**：默认标签 `Ref($close,-2)/Ref($close,-1)-1`，即 t+1 收盘到 t+2 收盘的
   **未来**收益；它是评价/训练用标签，不是当时可用特征，严禁进入任何当时信号。

本轮不提出新增训练方案。未来若借用：特征公式、横截面/时序归一化、未来收益标签必须
按上述边界拆开登记与授权，不能把处理后的模型输入冒充原始公式，不能把标签当特征。

## 6. 复用决策汇总与理由

| 类 | 决策 | 理由 |
|---|---|---|
| MA | 已有等价能力，无需另建 | 与 trend.distance* 存在精确换算（条件：同窗口/含当日/满窗口/同价格口径）；新建只会制造同名异义 |
| ROC | 可作公式参考，存在明确语义差异 | 反向比率写法本身无本地需求；若未来需要须新登记，不动 mixed.momentum.raw |
| STD | 可作公式参考，存在明确语义差异 | "价格散布比"与 rv20 不应直接互换；互补价值**未检验**（需另外的问题、数据和比较）；暂无以它为答案的问题 |
| BETA | 当前不适用，暂缓 | 名称误导（非市场敏感度）；本地无对应需求；backlog 候选未立项 |
| RANK | 可作公式参考，存在明确语义差异 | 同族分位算法本地已有（rv_percentile）；"价格历史分位"若需要是新对象 |

不采用/暂缓的共性理由：本轮目标是定义对照， backlog 未授权新增对象；五类中没有出现
"现有对象答不了、且已被确认值得回答"的问题，故无一进入"值得以后做小型适配验证"档
（BETA 保留条件性可能，见 §3.4）。任何未来适配都使用现有定义体系与新对象 ID，
不建第二份登记表，不沿用 Qlib 同名掩盖差异。
