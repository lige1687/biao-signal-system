## 五、冲突发现（prompt 点名必答两问）

1. **本任务与 H5、Prompt D（orthogonality-check）的方法论关系——有重叠
   但颗粒度三层，不含糊**：H5 测「**同模块**同日**跨标的**」的信号数量
   （市场宽度聚集 → 收益质量断言，本次证伪）；Prompt D 测「不同信号**腿**
   的**日收益序列** Pearson 相关（腿级、跨标的合成收益 → 能否当第三腿的
   必要条件初筛）；本任务测「**同标的同日跨模块**」的触发**事件共现性**
   （标的级 → 两个模块对同一次价格行为的解读是否矛盾）。三者回答的是
   「市场在聚集吗 / 腿之间独立吗 / 单个标的上矛盾吗」三个不同问题。本任务
   的增量有二：① 把"冲突"第一次落到标的级事件——这是唯一能区分「同一
   价格行为的矛盾解读」的颗粒度；② 给出可检验性判定本身：D 任务只能看到
   腿收益低相关，**无法区分**「低相关因为标的不同」还是「因为从不同时
   触发」——本任务的结构审计回答了后者（同标的层面中位错开 607 天），
   这是相关性矩阵给不出的信息。
2. **「冲突组显著更差 → 确认层规则」是否成立——不成立，且不是因为在
   冲突组上测出了坏结果，而是因为冲突组没有方差**（N=1 < 预注册下限 20，
   按纪律 sample_insufficient，不得下方向性结论；从单例导出规则违反本任务
   自己的预注册协议）。结构审计进一步给出反面证据：四模块在标的级近乎
   完全互斥（间隔中位 607 天），「同一信号触发时检查其他模块是否给出矛盾
   判断」这个确认层**没有可标记的对象**——该思路在 E（MACD 分层）/L（板块
   RS）上有方差可用，在模块间冲突上没有。模块间真正的交互发生在**市场级**
   （同日多模块在不同标的上聚集），而那个维度的收益断言正是本次证伪的 H5。
   结论：模块间冲突确认层方向以「结构性不可检验」结案，角色定位问题
   （类比 E/L 只进确认层）不再成立——无对象可确认。

## 数据工程欠账与局限（解读必读）

1. **共触发检测基于过滤后成交流**：三流各自带门槛（A 的 cm05 收缩、B' 的
   cb30/cl3%、C 的 bias−15%），被过滤掉的信号不进流——真实共触发率被
   低估。严格复验需要检测器过滤前事件流归档（欠账，下一步方向 3）。
2. **backtest 包半重构，本机不可重跑**（继承 macd-strength-layering 归档
   的已知欠账）：本任务全部基于已入 git 的归档逐笔，未生成新逐笔、未动
   `src/`；A 模块另有 `raw/breadth_overlay/wf_a_noshrink.json`（655 笔，
   不同配置）未并入（防口径混淆，仅在 S0 同源性上引用主样本）。
3. **D 模块休眠**：全池 5 笔（stop-loss-matrix 归档）/本档去重后 1 笔，
   任何 D 结论样本不足——继承既有归档判定。
4. **A 池（32 只 ETF）与 B'/C 池（45/49 只个股）无同标的交集**：A 的跨模块
   冲突只能靠 lifecycle 型单标的全模块 run 检验，本任务已查 2 例（510300/
   518850）皆 0 例共触发。
5. T2_D 归档含同键重复记录（仅 entry_reason 波谷参照价不同），按交易经济
   键去重后使用；该修正属描述性审计的事实修正，不触及任何判定线（H5R
   判定只用 A/B'/C 主样本），已披露于结果 JSON。
6. 阴性对照 NC1 与 bootstrap 主判定信息部分重叠（均针对同一零假设），
   双双如实报告；NC2（第二步打乱对照）因第二步未执行而不存在。
7. 本机无 pandas/numpy，脚本纯标准库实现（10000 次 bootstrap + 200 次
   打乱实测约 6 秒）；全部随机数来自固定种子 `random.Random`，双跑哈希一致
   证明与 PYTHONHASHSEED 无关。
