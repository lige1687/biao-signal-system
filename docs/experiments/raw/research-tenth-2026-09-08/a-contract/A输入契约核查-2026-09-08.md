# 第十批：A 回调模块输入契约核查

## 一句话结论（大白话）

测的是“上升趋势回调”能否作为小规模账户模拟的可靠输入。结果发现：只增加一根后来的K线，先前已经出现的底部构造和A入场记录就可能被挪走；因此当前冻结实现暂时不能接入账户模拟。本次没有测真实基金的候选或收益，没有修改现行规则。

## 原文、代理和实际覆盖

最高依据是 `docs/trading-spec-v1.md` §3.2、§6、§7.3、§9 A1—A6、§10、§13、§14。A服务于“先看上升道路，再等回调触发、守原支撑失效位”这一层。MACD不参与触发，板块和基本面不成为硬过滤。

原文要求稳定多头、回调至既有支撑、结构转强、早期或共同向上两种入场、三种独立退出。现行及第八冻结包实际执行 `rules.v2.yaml` 的A 3.0.0：20/60/120周与日线双组排列、时钟二类、SMA附近1倍ATR20触及，是已经存在但仍须标“研究代理”的具体选择；没有改这些数值。`rules.v1.yaml` 的双距离阈值和3根窗口是历史口径，不能当当前运行规则。

A3原文列四种可选条件，当前只实现“底部构造”和“重新站上EMA20”，没有实现低一级周期多头排列和独立破底翻分支。另一个“四组”是早期/确认各分首次/非首次，不是四套独立A3条件。筹码支撑与分钟级扩散也不在本次覆盖内。

## 已有证据

| 核查 | 结果及实际含义 |
|---|---|
| 周线完成时点 | 650根合成日线在120周附近的21个截断结果完全一致；第120个已完成周前不放行。周五收盘才允许本周信息；默认工作日日历不能称已覆盖真实节假日短周。 |
| 未来K线是否改写历史构造 | **明确反例**：前三根高低范围依次为9.8/9.0、10.3/9.3、10.8/9.7，第三根形成底部；追加10.7/9.8后，第三根与第四根被合并，旧确认日被移至第四根。 |
| 是否传播到A入场 | **明确反例**：固定时钟/周线环境、使用真实冻结A和构造函数，2024-01-31两条A入场在追加2月1日后从历史中消失。原输入与事件全文保存在 `probe-results.json`。这是依赖隔离的合成案例，不声称是某只真实基金发生过的问题。 |
| 底部失效后是否重检 | **明确反例**：A记住的底部ID后续失效，A仍可用它确认入场。用受控结构对象隔离验证；无重新站回EMA20的替代理由。 |
| 周线变差是否阻断新触碰 | **明确反例**：已有趋势周期内，周线转空仍生成新触碰，证据自己写着 `weekly_bull_env=false`；该日不产生入场，但可能影响以后“首次”的归类。 |
| 最低输入字段 | A显式要求OHLC、颜色、三组SMA/EMA/抵扣价；实际还必须有volume，否则通过显式列检查后在周线聚合抛错。净值仅收盘、伪造OHLC或成交量，不能充当完整触发输入。 |

关键原因是 `strict_structure.py` 先合并全段K线再找构造；合并时直接把完成日期改为最后一根。A虽然按日推进，预先拿到的结构列表本身已经会被后续行情改写。只验证事件ID是否仍存在的普通上涨案例，抓不到这个情形。

失效价在每次确认时取“触碰日至确认日的最低价”，已发出事件的数值不会被状态对象直接修改。但当整个历史确认事件会消失时，不能据此声称“输入失效价已通过不受未来影响的检查”。早期和稍后的确认可能各自冻结不同低点；这不允许移动已经持有的早期交易的原失效位。

## 候选、生命周期和退出如何对应

仅 `first_ma_pullback_confirmed` 配合 `entry_variant=early/confirmed` 才是入场候选；触碰和回撤失败不是交易。必须一起保存事件ID、生命周期ID、触碰日、均线周期、首次标记、A3来源/结构ID、信号收盘、固定失效价、目标来源和可知日。当前 `EntrySpec` 丢掉了生命周期/触碰日/结构ID，不能只靠它解释账户去重与入场理由。

第八冻结执行器会在下一根开盘重新检查：仍用原目标和失效位，实际预期盈利至少是风险的3倍才接纳。生产执行器与第八冻结执行器内容不同，本次结果不得把二者混称为同一版本。

趋势周期遇到SMA排列破坏、跌破SMA120或转黑会重置；失败或早期/确认都发出后，该均线下一次触碰标为非首次。两个版本都发出后，该回撤周期不再持续发失败事件，所以持仓必须另用固定失效价判断。新触碰当天不执行A4入场分支，是当前代理的时序选择。

三种退出共同保留“收盘跌破初始失效价、下一根开盘执行”。第一种另外观察EMA20与20日抵扣价；第二种另外依赖顶部构造后出现反向关键波动；第三种仅用初始失效价。第二种同样依赖有问题的严格构造，且实现允许顶部确认当日同时满足反向波动，也没有重检顶部失效；本次没有用收益试验替它做合格背书。

## 测试和交付边界

- 冻结包运行原有周线环境、严格构造和周线可知日测试：**20项通过**。日志为 `existing-tests.txt`。这些原测试没有覆盖上述追加包含K线反例。
- `probe.py`运行成功并保存反例；“脚本运行成功”表示成功复现问题，不表示A合格。全过程设置 `PYTHONDONTWRITEBYTECODE=1`，原有pytest关闭缓存，并以冻结包作为唯一模块搜索入口。
- 来源及SHA256、当前/冻结比较、字段映射、未覆盖项均见 `contract.json` 与 `probe-results.json`。A、周线、严格构造、指标、时钟和日历当前与冻结内容相同；执行器不同。
- 只在本目录新增审查材料。未跑真实基金候选、未跑收益、未改生产规则/冻结包/UI/台账/OKR。正式实验登记由本批总报告负责，本文件为子任务证据。

**资格结论：暂不进入有限账户模拟。** 下一步先呈交上述最小反例，在明确授权的隔离研究中处理历史构造不稳定、A3缓存失效与周线触碰差异，再逐日比较完整事件内容。不能临时删掉底部构造分支，仍称完整A已通过。
