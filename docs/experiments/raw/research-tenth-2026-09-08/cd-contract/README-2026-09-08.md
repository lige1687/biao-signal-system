## 已证实的实现问题

1. **D 删除过去事件。** `d-future-zone-end.csv` 取前 197 根时，2024-10-02 有一条确认；增加未来数据至 219 根，同一条确认消失。原因是连续离开密集条件 21 根后，D 把区间结束日期回写成离开第一根，原来允许使用的低点被排除。最高规格 §3.2 不允许这样改写过去。
2. **C 没选最近前低。** `c-recent-valley.csv` 已有更新的 101 前低，仍然扫描旧的 100；同一次跌破收回分别产生两组确认。有效账本 C1 明写“最后一个已确认”低点。
3. **D 没选最近波谷。** `d-recent-valley.csv` 中 99 和后来确认的 99.2 都参与同次假跌破，分别生成确认。手册与模块说明要求最近的参照。

上面新增 CSV 是用来单独检验规则函数的指标输入，均线列没有从这份 OHLC 重新计算。它们证明函数存在这些路径，不能据此声称真实行情出现次数或影响比例。已有单测则从合成 OHLC 经正式指标函数计算。

## 入场与结束口径

- C v1 是窗口内收回前低；v2 还要求由下重新穿回 EMA20 且 EMA20 上升；v3 要求价格高于 EMA20/SMA20、两者上升且既有颜色为绿色。三者分别发事件，不要求 v2 先于 v3。合成分日例中依次在 2024-01-17、18、19 日可知，失效价均为 99。这里的 v1/v2/v3 是入场版本，与规则版本 3.0.0 不是同一个含义。
- C 在收回前，每根先用昨日最低价检查是否收盘失守，再用当日最低价更新；该顺序已写入有效账本，不能误报为代码错误。收回后固定最低价，各入场版本沿用同一个初始失效价。
- D 保留“曾快速收回”的事实，但均线条件只看当前；收回后等待均线期间，失效参照仍可能随日内最低价下移。确认事件发出时，才作为初始失效价固定。
- 确认检测器停止后不一定继续发失败事件。第八回测执行器独立检查入场时锁定的失效价：收盘跌破，下一根开盘退出。因此不能仅凭检测器停止，就断言整个系统没有止损。此次未执行收益。
