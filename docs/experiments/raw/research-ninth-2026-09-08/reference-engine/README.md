# 第九批：入场目标条件的诊断参照账户引擎

日期：2026-09-08。范围仅本目录；不是生产策略或投资建议。

## 一句话结论（大白话）

本项检查的是：临时取消“必须找到历史目标、预计可赚金额至少是初始风险的三倍”这两项入场要求，能否保持其他账户规则不变。最终合成测试全部通过，旧八套规则在 32 个场景里的每个输出字段也完全一致。它只使下一步历史对照可核算，尚未在本任务中计算真实策略成绩，也不说明应该取消现行纪律。

## 接口与边界

`engine.py` 保留第八批 `simulate` 的输入和输出接口，新增 `config_id='R0'/'R1'`，分别配合 P0/P5 原候选。候选生成不属于本目录；调用者必须提供既有候选，不得利用本引擎生成现行信号。

- R0/R1 对 `signal_accepted=False` 只接受精确的 `target_unavailable`、`signal_reward_risk_below_3` 两个原始拒绝原因；其他原因、缺原因、空字符串和拼接原因继续拒绝。
- 放宽这两项原因后，仍独立检查信号日存在有效报价、失效位是正数且低于信号参考价。缺省 `signal_ref` 键只在合成接口中回退当日收盘；显式 `None`、非有限数值都无效。真实调用应提供该字段。
- 下一指定报价日开盘仍需开盘价高于经公司行动转换的正失效位；不再要求目标存在，也不再因目标与开盘价的比例低于三而拒绝。有限的目标仍计算开盘比例，供审计，不据此作决定。
- 持仓、资金不足、整手、禁开盘、缺价、卖出后当日不重买、收盘确认后下一可开盘卖出、费用、分红应收和拆分均沿用原引擎。R0/R1 退出沿用 P0/P5 的结构失效优先，其次同时低于 EMA20 与 cost20。
- `candidate_metadata` 深复制所有原始输入键值，只用 `setdefault` 补充审计键。原始 `signal_accepted`、`signal_reject_reason` 和目标及来源不被改写。`original_candidate_id` 优先采用已有值，其次 `source_candidate_id`，最后兼容无来源的合成 `candidate_id`；原配置同理。
- R0/R1 的订单、成交、日账、完整买卖记录均标注 `diagnostic_reference_only=True`。事件记录沿用原格式；整组结果须始终标明诊断。原始元数据若自带不同诊断标记，保留原值供查验，实际结果外层仍明确为诊断。
- P0–P7 不增加新字段，原拒绝顺序保留。默认回调能力与第八批一致；本轮不增设新的退出回调。

## 编写与独立审查经过

按用户要求，简单分支修改及首组七项测试由 `gpt-5.3-codex-spark` CLI 编写。首次七项测试先得到“不支持 R 配置”的七个错误；首版随后自测 30 项通过，但独立测试发现多个实质问题：旧规则输出被加上 `False` 字段、旧开盘缺目标检查被删除、白名单条件跳过信号正风险检查、原拒绝优先级变化，以及已标注候选导致重复参数错误。首次独立完整检查是 43 个失败子场景和 1 个错误；不能采信其自测通过结论。

首版已保存到 `first-pass/`，日志未覆盖。只给 Spark 一次针对性修正机会。第二轮恢复了旧开盘检查、拒绝优先级、修复白名单后继续验证正风险；它在最后一次修改后因 Spark 专用额度耗尽退出。第二轮文件和日志存 `second-pass/`；未申请额度重置，也未继续派发。

本研究审查 agent 随后独立运行第二版：39 个测试方法仍有 40 个失败子场景，主要是旧输出多出的诊断字段。增加根调用者的来源编号与逐键元数据保留检查后，41 个方法有 42 个失败子场景。审查 agent 只作以下最终修补：恢复旧订单字典构造；移除旧完整买卖记录多出的 `False` 字段；只对 R 结果附加标记；来源编号兼容 `source_*`；元数据补充键不覆盖原键。具体差异见 `reviewer-vs-spark-second.diff`。

最终 41 个测试方法全部通过，含 23 个原测试、7 个 Spark 测试、11 个独立测试方法；方法内另有多场景检查，不能将 41 当成全部独立市场样本。

## 检查证据和限制

- `test_parent_review.py`：P0–P7 × 普通持有、提前退出、无报价日拆分、分红四场景，共 32 套结果，直接比较全部日账、成交、订单、事件及完整买卖记录；另核对 8 个多无效字段的原拒绝顺序组合。
- 独立边界涵盖精确拒绝原因范围、白名单后仍须正风险、目标不参与决定且保留、跨拆分待买单开盘低于失效位、次日买入与收盘后次日卖出、未知配置、已有审计键及根调用来源编号。
- `parent-final-tests.txt` 为最终运行输出；失败运行均保留。`final-vs-baseline.diff` 为全部引擎变动，`reviewer-vs-spark-second.diff` 区分最终审查 agent 的修补归属。
- `engine_baseline.py` 和 `test_baseline.py` 的 SHA 与复制前记录一致；所有运行使用 `python3 -B` / 禁用字节码环境，本目录没有 `.pyc`。
- 本任务没有读取本轮真实收益来选择实现，也没有运行真实账户。合成场景不等于所有可能输入的形式证明；真实 P0/P5/P6 逐表回归、R0/R1 真实输入审查及账户核算由根 agent 独立执行。
