# 第九批两组诊断账户：独立资金核算

日期：2026-09-08。仅复核R0/R1，没有重新运行策略，也没有改变主研究文件。

## 一句话结论（大白话）

两组诊断账户共8,398天的现金、持份、分红、费用和财富，都由另一套算法重建并与主账对齐；941笔成交和2,211份订单也对得上。期末三份未结束持仓保留真实估值，没有虚构卖出。这证明给定买卖的账算对了，不证明取消目标空间纪律适合正式使用。

## 接受版本与独立性

核算方案和程序在读取新结果前冻结，见`protocol.md`及`review-code-lock.json`。主研究通知结果完成后，复制36份输入到`accepted/`：两组账户五表、候选、汇总、协议、主引擎版本和第八批名义行情/已核行动等。`accepted-inputs.json`记录原路径、SHA-256和接受时刻。输入在复制时和核算后均未改变。

核算程序来自已封存第八批独立程序，原件及指纹保留在`original-verify-accounts.py.txt`和`adaptation-source.json`。本次用40位十进制计算，从基金名义行情、已知事件、每周一四产品各250元以及成交表重建，不调用主账户引擎、价格helper或Spark统计函数。接受的主引擎只保留为版本证据。

固定研究期2015-01-01—2026-06-30，各4,199个民用日、600个周一，共投入600,000元。所有日账受核字段容差为0.00001，实际最大数值差约1.03×10⁻⁹，来自浮点与十进制运算差异；没有超过容差的字段。

## 分红、拆分与期末持仓

分红权益从本复核自己的登记日收盘持份计算，除息后计应收，付款才转现金，权益归回原持仓。两组期末应收均自然为零。真实路径没有“持仓卖出后才除息并产生正应收”的案例，因此不声称该边界已由这两条真实路径证明。

513100的2022-01-13拆分无报价日，已知旧价格按一拆五从5.192转成1.0384；两组当时均无持仓。因此本次实际路径核到了无报价价格单位转换，持有中拆分的数量边界应引用第八批真实P6核算，不能把本次零持份重复算成新验证。

## 保留的首次检查失败

全部日账首次通过；附加汇总检查首次在R0最大跌幅处失败。原因是本复核脚本把逐日负数回撤直接与主汇总正数跌幅大小比较。`first-pass/`保留原检查脚本、指纹及两组实际数值，`checker-correction.json`记录仅增加一个负号的修正。修正后订单、金额汇总、最大跌幅和恢复天数全部通过。

主账户金额、主汇总和独立逐日核算程序均未因此改变。原冻结指纹不覆盖重写；修订后的代码由最终文件指纹另记。

## 交付与限制

- `results.json`：逐日核算摘要；`reconciliation/`：8,398行独立日账。
- `events-reconciliation.csv`、`roundtrips-independent.csv`：全部事件和持仓的金额核对。
- `summary-and-orders-checks.json`：2,211份订单、941成交及独立恢复天数。
- `accepted-inputs.json`、`input-integrity-after.json`、`delivery-checks.json`和`final-manifest.json`：接受版本与最终指纹。

这两组仅用于解释取消目标空间条件后会发生什么，不等于经典突破的完整复现，也不能根据历史差额直接决定放宽正式纪律。第八批的日线近似、已知公司行动范围、实际交易细节和费用限制继续有效。复核目录完成不代替用户验收，不修改任何目标台账。
