# 因子、信号与基准定义规范

版本：1.1.0；生效日期：2026-09-10。适用于此后新建或明确重做的研究，不追溯改变冻结实验。

这是 [研究与验收原则](experiment-backtest-principles.md) v1.1 的定义管理细则，不是另一套研究总纲。
它服务于研究层的计算可追溯、受控比较和收益解释；不改变 `docs/trading-spec-v1.md` 的交易体系、
规则账本、生产消费者、正式交易授权或 OKR 状态。独立配置研究不是冒充 A/B/C/D 的交易触发。

## 1. 单一权威与使用入口

唯一手写登记表为 [definitions.v1.json](definitions.v1.json)。它同时是定义卡的结构化正文；
`profiles` 保存共用字段，`objects` 保存对象差异。解析规则是：一个对象最多引用一个 profile，
顶层字典字段只合并一层，其他值整体替换。不能仅阅读省略字段的原始对象，把继承内容当作不存在。
`resolve()` 返回完整卡；复算脚本输出 `resolved-definition-cards.json` 是生成快照，不另行手工维护。

读取次序：根 AGENTS → 研究与验收原则 → 本细则 → 本轮协议 → 涉及的完整定义卡及输入版本。
派发子任务必须带这两个规范版本、准确 `id@version`、协议、代码/输入路径与不可修改范围，不能假设自动继承。

盘点证据位于 [混合池证据映射](definition-evidence-mixed-2026-09-09.md) 与
[宽度证据映射](definition-evidence-breadth-2026-09-09.md)。结案报告补充长期投入与最终处理状态。
证据文档说明“程序做了什么”；不能用代码存在证明设计正确，也不能按文档猜出缺失的实现。

## 2. 类型与用途分别登记

| 类型 | 它是什么 | 不可混淆的边界 |
|---|---|---|
| `feature` | 描述或排序的数值、排序结果 | 涨幅、排名、过滤和取前三是不同对象 |
| `state_signal` | 一个状态或条件 | 均线上方、当天上穿、允许回补不是同一个状态；不等于完整策略 |
| `factor_return` | 有构造与单位定义的收益序列 | 不为填类型新造多空组合；现金零息假设不是无风险序列 |
| `risk_metric` | 真实持仓的权重、集中或风险描述 | 不因有集中度就认定存在收益溢价；模型估计的暴露须另有模型卡 |
| `benchmark` | 选择、权重、现金、费用、成交规则完整的参照账户 | 声明是否可投资；参照收益可被模型引用，但其身份不因此改变 |
| `policy/strategy` | 把信号、选择、仓位与执行组合起来的决策规则 | 模块有效不等于完整资金账户有效 |

机器用途枚举：`description` 描述、`ranking` 排序、`research_signal` 研究条件、
`attribution` 解释收益或风险、`comparison` 对照、`diagnostic` 算法/数据核验。
卡片须明确 `uses` 与 `not_for`，二者不得相交；`production_trade` 不在本登记表的允许用途中。
用途声明不自动提供该用途所需证据，例如允许研究信号不代表它已有预测能力。

## 3. 完整定义卡与五种状态

每个 `id@version` 必须包含以下分节；校验规则实现在研究专用
`src/lei_signal/research/definitions.py::validate_registry`，不另维护第二份手写模式文件。

1. `id/version/name/type/uses/not_for/scope`：唯一身份、语义版本、适用与禁用范围。
2. `definition`：公式、参数、端点、单位、方向、所有变换；没有变换写无。
3. `input`：字段、价格/公司行动口径、币种、频率、交易日历；`sources` 绑定来源路径及 SHA-256。
4. `universe`：池与历史名单版本、资格、预热、缺失、质量门槛、降级。信号股票集合与实际买入 ETF 分开。
5. `time`：观察时点、可得时点、最早决策/成交、时区、生效日期。未知逐条到达时刻必须写未知。
6. `dependencies`：精确依赖版本；组合对象另有 `policy` 的选择、权重、现金、费用、调仓、成交、退出、回补、可投资性。
7. `validation`：方法、绝对/相对/整数容差、测试证据、限制。测试文件存在不代表卡内所有策略状态都被执行。
8. `status`：分列 `definition_clarity`（是否清楚）、`data_qualification`（资料是否合格）、
   `implementation`（代码核验到哪里）、`effectiveness`（是否有实际价值的证据）、`production`（生产授权）。

登记表加载检查必填、字段类型、唯一身份、精确版本、合法依赖、循环依赖、非空执行规则、来源格式、
时区、数值容差和禁用用途。`verify_sources()` 另外核实际文件哈希；完整复算命令在计算前后都运行它。
机器不声称能从自然语言公式自动证明语义正确；定义审阅与逐值复算仍不可省略。

模型卡与对象卡分开。涉及 β/α 时必须有因变量、因子收益 ID、模型形式、频率、窗口、无风险收益、
币种、缺失对齐、估计方法和不确定性。没有适配的模型及无风险资料，1.0.0发布时 `models=[]`，不估计 α。
宽度水平 B200 不是收益序列，不得直接填进收益因子位置。

## 4. 时间、单位与版本边界

- 混合池动量按各产品自身有效报价第 `t-21` 与 `t-252` 条，首次可算在第 253 条；月选资格另需 273 条及当日报价。
  20/21 与 252/253 不能互换。SMA 含当日，按最后 N 条有效报价；停牌不填假报价。
- 混合池 `trend.*` 只绑定 `mixed.price.economic`；ETF 价格趋势另登记 `etf.trend.*`，不能把两种连续价暗中互换。
  输入缩放不得改变涨幅、距离、状态或宽度；均线绝对值随同缩放。
- 宽度是“当时成员中，合格股票有多少站上各自均线”。共同分母版 B50/B200 同用 E200。
  新版 `fraction` 是 0—1；旧 `percent` 是 0—100，保留独立 ID。差值 0.05 是 5 个百分点，不是相对增长 5%。
  布尔状态单位为 `boolean`（可输出 0/1/缺失）；名单为 `ordered_symbol_list`；账户路径为 `account_path`，不是单个收益标量。
- 历史成员变化本身会改变宽度，不全归于价格转强。创业板指数不等于整个创业板市场。
  无合格数据、名单缺失或覆盖不足返回缺失及原因，不能伪装成零宽度。
- 公司行动 `effective_date` 是上海本地交易日期；`available_at` 是带时区的真实可知时刻。
  新接口只在事件已于本次观察收盘前可知时连接，否则报错，不补入过去、不推迟成虚构交易。
  可在生效后才取得资料：此时重算是历史修订，不是当时可用证据。冻结旧资料缺到达时间，不能补造时间获得合格标签。
- `available_at` 不得晚于决策；本轮历史复算的决策时间是实际复算时刻，不冒充历史下单。
  月末须由完整月份与声明交易日历确认；冻结代码取日期并集每月最后一行，截到月中可能制造假月末。
  本轮只映射此行为，不提供生产月末调度或快速回补状态引擎。
- 同一已发布身份的公式、价格尺度、池、时点、预处理、交易含义不得静默改变。
  不兼容语义改动用新主版本或新 ID；兼容扩展升次版本；笔误升修订号并记录影响。
  旧引用不解析成 latest，冻结实验只做外部映射，不回填新版本伪造迁移。
  首次 1.0.0 发布前的失败测试与审阅修订保留在本轮报告和独立输出目录；发布后必须新增版本。

## 5. 接入与验收

机器实验清单由 `make_manifest()` 生成，至少保留规范版本、登记表文件与规范化内容哈希、
对象与依赖版本、代码文件哈希、输入快照/名单版本、数据截止、可得与决策时点、协议哈希、质量和授权状态。
每个输出文件用旁置 manifest 描述字段单位、对象身份及缺失编码，不在每行重复全文；行内仍保留观察日期和对象标识。
历史资料修订需保存旧指纹、新指纹及原因，与只追加未来行的测试分开。

1.0.0发布时的接入快照（不代表当前全仓最新状态）：两条小型研究示例和单元测试。`calculate()` 仅支持登记且参数匹配的混合池动量、混合池 SMA、共同分母宽度。
其他纯函数服务核验；它们不能替代完整策略执行。所有旧账户引擎、生产宽度与全A日常计算仍为 `legacy`，不调用新登记表。
已登记策略不等于已实现新的策略引擎，更不等于全仓库迁移完成。

复现命令（从仓库根目录；输出目录必须不存在）：

```sh
python3 -m pytest tests/unit/test_research_definitions.py -q
python3 scripts/verify_research_definitions.py --output docs/experiments/raw/definition-normalization-2026-09-09/your-new-run
```

混合池示例：冻结名义价和行动 → 保存经济指数输入 → 引用动量/均线/选择定义 → 逐值和月末名单比对 → 输出数据及 manifest。
经济指数行情真实性及历史事件到达时间不在这次真实输入比对的合格声明内；行动算法另用带真实时间语义的合成小例验证。
宽度示例：冻结资料明确引用的本地收盘缓存及历史成员 → 截取普通日和成员变化日 → 共同分母计算 → 与旧百分数值和封存结果比较 → manifest。
缓存不存在或指纹不同则降级为明确标记的合成例，不下载新数据、不称真实市场证据。

归因仍沿用三层：资金贡献核完整净损益；决策增量用公平对照；风险/因子解释按问题选模型。
纯数据/公式核验不强制回归；同期解释拟合不是事前预测。残差不能直接叫独特 α 或运气。
生产采用另外需要完整账户、资金与真实成交约束验收及明确授权；不以高收益、高相关或显著统计值作为本轮完成条件。

## 7. 验证目标与有条件的证据（新任务文档合同）

本节对应规范包03，不新增登记类型、模型卡或机器枚举。研究对象仍是§2六类；研究集合（Universe）复用卡内 universe/输入名单，实验、未来结果合同（TargetSpec）与证据（Evidence）是协议或报告的关系记录，不混入对象库。对象类型不是“特征成功后升级为因子”。使用位置另写排序、准入、仓位、退出、回补、执行限制、描述或归因，不擅自扩张现有 uses 枚举。

### 7.1 未来结果合同

只有研究问题需要未来观察结果时才填写：身份/版本、主要或辅助目标、单位方向、信号与最早进入时点、诊断价或可成交价、观察跨度与端点、交易日历/时区、退出观察价、价格或总回报、分红再投资/费用/币种/参照、路径风险分母与符号；另列未成熟、缺开盘、停牌、终止合并、未来缺失及不可成交的处理。

例如固定h个交易日的开盘到开盘观察，e为信号后的下一个交易日开盘，h=1结束在e后的下一交易日开盘，不是e日收盘。无行动/费用时100到110为10%，这仅是算法小例，不是新策略窗口。相对入场值的最大不利变化与期间峰谷回撤分母不同，须分开命名。

未来结果只供离线评价，或在另行授权训练且 `label_available_at <= fit_time` 时进入拟合；不得进入当时信号、在线排名或历史资格过滤。未成熟标未成熟，不缩短观察期；不因未来缺价删掉产品，也不顺延到任意更晚日期仍称原期限。输入总数、成熟/未成熟/缺失与每类排除数均保留。历史修订与追加未来数据分开留指纹。

同日排序研究若使用相关性诊断，约定 IC 为逐时点原始数值的 Pearson 相关，Rank IC 为逐时点排名的 Spearman 相关（不同命名须映射）；说明并列、最小样本、缺失和汇总权重。常数截面应缺失并注明原因，不填0；小池不强制十组。同日所有ETF共用的B200不适用横截面排序相关。状态、政策、风险与收益解释按问题另选检查，纯政策比较可引用账户评价合同并写 TargetSpec 不适用。

### 7.2 证据记录

每条证据在原报告中绑定：问题/假设/研究家族、对象及依赖版本、使用位置、集合与名单版本、目标合同或不适用理由、输入/代码/协议、评价区间/费用/基准、原始结果文件和字段、独立复核范围、结论/反例/限制及与旧证据关系。

同一对象在不同政策/来源/时期下可有不同结果，不用最后一条覆盖旧证据，也不写永久 `valid=true`。区分未运行、运行失败、数据不可用、计算正确但无增量、有条件候选；这只是报告用语，不替换现有状态枚举。已有五种状态继续分列，执行可行性另在报告说明，不新增第六个强制卡字段。

### 7.3 能力边界

本节与模板中的 TargetSpec/Evidence 是新任务人工填写和审阅合同，**未接入现有runner、schema或校验器**；没有标签生成、成熟检查、IC套件或自动证据生命周期的实现声明。
现有 `validate_registry/resolve/make_manifest` 只承担其已实现范围；正文更新不更新代码内的旧规范默认版本。新任务必须显式记录实际采用的文档路径、版本和指纹，并核对机器输出；输出仍标旧版本时单独说明，不伪装已接入。旧v0不为本节增加能力。
