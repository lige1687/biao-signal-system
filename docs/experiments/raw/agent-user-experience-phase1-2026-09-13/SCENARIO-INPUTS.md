## 场景 1：单 ETF，事实足够，模型正常

- 假模型固定回复（合成，首段=结论）：
  「这只 ETF（沪深300ETF，510300，数据日 2026-09-11）目前处在上涨后的
  高位整理，系统状态为绿色/阶段三。针对你问的整体方向问题：方向仍向上，
  但离下方关键位有距离。机会：系统给出一个买点候选（上升趋势中的回调，
  等待触发，关键价 3.92）。风险：若跌破 3.85 则形态失效。历史依据：适用于
  这次问题（有同方法补测，交易 24 笔，胜率 58%，每笔平均 0.21 倍风险金额）。
  接下来：等回调到关键价附近再看，或打开下方依据核对。」

- 判定：首屏（第一段）可读到：名称/代码、数据日、状态、针对什么问题；
  机会与风险各有事实；R 首次出现带「倍数不是收益率」解释；依据详情
  （运行编号）不在首屏正文里，点「查看依据详情」/展开后可见且数值一致。

## 场景 4：没测过就补测，未选方法

- 固定输入：`510300 帮我补测一下`（后端解析为 backtest 意图）。
- 交互：回答下方出现「准备补测」动作 → 打开中文面板：A/B/C/D 中文打法
  选项（各带一句解释）、退出方式预选系统默认且可见可改、提交前摘要展示
  对象/方法/退出/区间（未指定窗口显示"未单独指定"）。
- 判定：不选打法时提交按钮不可用；选定后提交恰好产生 1 个
  `/copilot/backtest-requests` 请求，参数与面板一致（模块/退出/对象）；
  不默认替用户选 A。

## 场景 7：任务完成 / 无可统计交易 / 失败

- 覆盖方式：完成与无交易两态用单测+回归断言（真实执行器在合成数据上
  会诚实拒绝，属"失败"态）；浏览器实测"失败"态（合成数据源被冻结拒绝）。
- 判定：三种终态文案不同、各有可用下一步；失败不写成"没有机会"；
  运行编号只在括号/详情，不冒充结论。
