# 带日期的共享资金合成账本：工程交付候选

## 一句话结论（大白话）

已把“钱什么时候能花、刚买的份额什么时候能卖”放到账本唯一入口，明确日期没到就拒绝；测试中的共享资金没有重复花，拆分没有提前解禁份额，分红到账也没有凭空增加资产。本次只验证人工构造场景的工程行为，尚待主负责人独立验收，不说明任何投资方法更赚钱，也没有接入真实账户。

## 已支持入口

dated_ledger.py 的 Ledger.apply(event) 是唯一支持的修改入口。初始化绑定具名合成日历与原始余额；运行必须给事件ID、带时区时刻、合格开盘的产品允许买卖状态、开盘价及信息/决定时刻；买入解禁时刻与卖款可用时刻必须显式绑定。缺数据就拒绝，没有无日期 settle() 或公开 buy() 旁路。

事件按入金→行动→支付→成交→收盘排列，同一时刻不同ID的合法多笔成交允许。时点倒退、同日阶段倒退、重复ID、重复行动与支付被拒绝。先在副本检查所有约束，成功后才一次性换账；拒绝不消耗ID，不改变资金、份额、费用、单位或先前完整日净值。独立audit保留拒绝原因。

每笔买入保留独立 release_at，卖出只取已到时份额。卖款独立记受限现金，到账且严格晚于卖出开盘才能转可花现金；买入仍必须当前是目标产品合格开盘。受限款不锁住已有自由现金，也不能代付超过卖款的卖出费用。开盘后到账不能倒回开盘，不保存自动追单。

分红使用合成输入绑定的已登记权益，支付事件在规定时刻才转现金；卖出/拆分不会重算旧权益。拆分换算每个已/未解禁批次与当前价格单位，保留解禁时刻。收盘估值缺价拒绝，入金只读取账本保存的上一完整日单位净值。

## 合成假设与尚未实现

- 人工日历固定Jan3/4周末与Jan5假日，明确Jan6解禁；这是反例工具，不是正式交易所日历或T+1计算算法。
- 真实产品解禁算法、实际卖款到账时点、公司行动细顺序、合法开收盘及停牌估值材料仍未取得资格。没有用行情K线猜日期。
- Group4只验证拆分批次/解禁与旧权益：合成分红有效价1.9、拆分后价.95，所以拆分前后均390；随后合成开盘价2使资产810。这个价格跳变明确属于人工价格输入，不能称拆分产生收益；本组没有声明完整市场价格连续性。核数回执单列该算术。
- equity(prices) 是只读诊断估值；正式保存完整日净值必须用绑定收盘的 apply(close)。程序内部Python私有字段不是防恶意使用的隔离机制；支持入口的原子性与约束已核验。
- 只绑定人工开盘资格与价格，未做订单容量、撮合、价格上限求解、P0/P1完整订单生成及周政策模拟；没有收益、预测、参数拟合或真实资金结论。
- 不接券商、账户数据库、生产系统、技术信息workflow；正式市场运行依然等待新的合格资料与授权。
