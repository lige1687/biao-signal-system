# 第十四批：顶部失效后是否还被错误用于退出

2026-09-08。用户授权“继续好吧，测的方向目前有比较亮眼的成就了吗”。本批先完成 A6② 消费方的确定问题核查；收益比较暂不启动。

## 一句话结论（大白话）

先验证程序是否会拿一个已经被新高推翻的旧顶部来要求卖出。这个问题若不排除，后续“顶部加反向波动”的好坏比较就可能是在比较程序错误。

## 策略位置和范围

- 服务交易规格 §7.1 的顶部失效、§9 A5/A6② 的持仓退出、§3.2 的收盘后下一开盘成交。账本 `top_structure` 明确写着“失效后不得继续参与 Top+Black”。
- 第十一批严格构造保存确认和失效日期；退出消费方 `prepare_frame` 却只留下确认日期。只修隔离研究副本中的生命周期消费，不改正式程序、策略参数、候选、资金规则或旧归档。
- §8.3“同时出现”和 A6②“后，再出现”存在同日是否允许的歧义，已问用户。本批反例保持旧版允许同日的行为，以便一次只检查一个确定问题。这不等于替用户确认策略口径。
- 进入之前确认的顶部沿用现有排除规则；入场当天收盘确认的顶部可以参与后续观察。没有给顶部增加自定寿命或等待期限。

## 先复现、后修复

1. 调用第十一批真实研究引擎的 `prepare_frame` 和 `simulate_trade`，允许用可解释的合成行情、明确的结构对象替换结构检测输出；不把自写的布尔表达式当原程序反例。
2. 先保存旧版失败：确认顶部 → 后来创新高失效 → 此后反向波动，程序仍要求卖出。反例只验证结构结果如何被消费，不声称重新证明完整顶底检测算法。
3. 隔离副本保留确认与失效日期。观察某日时，仅可使用当时已经确认、且当日尚未失效的顶部；当天已失效不可使用。
4. 不能用最终 `is_valid` 筛选整个历史：未来才失效的顶部，在此前仍能合法提示退出。必须有反例防止这种使用未来信息的“修复”。
5. 边界至少覆盖：有效顶部、此前失效、同日失效、未来失效不抹除过去退出、入场前顶部、入场当天确认、旧顶部失效后的新顶部、原同日确认行为未改。保存旧失败、新通过、代码差异和输入指纹。
6. 负责人独立检查源码差异及关键反例；核对旧归档未改。消费者测试通过只说明该错误得到修复，不证明退出更赚钱、更稳或值得上线。
