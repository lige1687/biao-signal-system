## 代码如何保留时间顺序

`src/lei_signal/research/structure_persistence_comparison.py` 是新研究工具纯函数。现有已修检测器可以按一个连续合格资料段只计算一次，但这里仅取节点首次确认时已经发布的六个字段；不读取它的未来失效日或最终 `is_valid` 去筛过去的根。手工序列逐前缀与全段核同，涵盖以后确认节点和后续失效。去包含只改当前合并尾部；已经公布的旧节点不回写。相同方向同日重复或冲突节点直接报错。

共同顶部段从首次确认顶部的次日开始，根日只留审计。原根高点以后被严格超过或首次新底确认时，两原因可同日并存，终止日仍留共同观察范围，两解释都记 0；当天不重新种根。逐根解释一旦出现有效合并组的高或低不再双双严格下降，就在该段永久中断；正在比较的尾部后来被包含扩展时会当日重查，不能改写前日状态。节点解释起初等待，只有第二个已确认顶部的冻结高点和确认低点均严格低于前一个顶部才成立；以后比较失败永久中断。两者都不能因短反弹或失败删掉观察日。

资格入口是 `guarded_runner.py --stage feature_qualification`，必须带主控以后发布的准确 release JSON 和外盘输出目录。启动前先核旧清单、新登记更正、规则/源码/面板和依赖闭包的每个 SHA，才导入检测器或读取面板。资格阶段只生成逐日状态、共同观察日、日历可成熟性和共同支持格，未来收盘不拿来算目标。缺行情或不合格行动会记为未知并切断连续段，之后重算 252 根预热；未知不是状态 0。输出保留每只 ETF、两个评估期及早期背景的范围、根/段/终止、两状态、共同支持、第二种实际进展次数与允许反弹日数。

真实写出时，runner 还要求绑定主控固定外盘计划及本机唯一尝试记录。尝试记录先建立，然后在异常捕获内以 `O_DIRECTORY|O_NOFOLLOW` 和 `dir_fd` 从已核设备挂载点逐级打开目录，独占创建运行与结果目录；结果文件以 `O_EXCL` 写入、同步并原位读回校验。任何断盘、路径被换、部分写入或计算错误都保留失败尝试，不回退内盘、不自动重试。当前未建立真实结果目录。

效果入口另需 `--stage effect` 专属 release，绑定资格文件字节 SHA 和主控的 `estimate` 或 `describe_only` 决定。未来跌幅固定从次一日收盘至第 21 个未来收盘，必须同连续段、同评估期且 21 个收盘齐全；不因状态或顶部段结束缩短。两解释先用**同一**特征和日历成熟条件选出的可比较背景格，各格权重在看未来结果前冻结。主结果按每只资产、每期分别汇总，再四资产等权、两期等权；不足完整八个资产时期便写不足，不偷换权重。预定的连续日期块抽取是两解释、四资产同步，长度 60 和 20 各 1000 次，固定种子；缺任何必要状态的抽取计无效，少于 900 有效次不报区间。全程 0 拟合、0 新账户。
