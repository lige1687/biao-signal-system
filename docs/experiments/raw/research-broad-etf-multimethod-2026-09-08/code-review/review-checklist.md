# 增量账户执行代码审阅清单

日期：2026-09-08。此清单在最终执行代码就绪前形成，只服务于 `protocol.md` 的规则与时点审阅，不做完整资金独立复算。

## H1 二元缓冲周度适配

- 精确用整数乘法比较：现金状态且 `breadth * 3 <= 130` 才转为1；持有状态且 `breadth * 3 > 136` 才转为0。
- 等于130/3必须进入；等于136/3必须保持持有；两线之间保持原状态。不得截断43.33/45.33。
- 从2015-01-01后的完整自然周、状态0起步；不得用2013/2014宽度预先种入状态。
- 每个完整周只取最后一个有效宽度；有观察的周即使状态不变也发布当前目标。
- 下一周首个允许开盘只评一次5个百分点条件；受限时可在同周顺延，新完整周替换旧订单。
- 缺宽度周不制造目标；上一周未成交订单在进入新周时取消。研究末尾不完整周只能记录，不能进入账户。

## H2 宽度与每日60日趋势取较大目标

- 每日60日状态必须复用首12定义：当前收盘严格高于此前60根最高收盘才转1，严格低于此前60根最低收盘才转0；相等不切换。
- 公司行动比较口径只能使用信号日当时已经生效且已公开的事件；不能用未来调整后的整段价格反向算历史状态。
- 2015主窗从状态0开始；2014只作60根预热，不继承虚拟持仓或旧触发。
- 合成时取截至完整周结束已经形成的每日状态；不得读取下周收盘。最终目标为当周宽度目标与该趋势状态的较大值，且不超过1。
- 只有该周存在有效宽度观察才发布合成目标；缺宽度周不能仅凭趋势交易。
- 每条信号要保留周决策日、宽度来源日和值、ETF最后观察日、最近趋势切换日、两原始目标和合成目标。

## 共同执行与旧资金逻辑

- 先由收盘信息形成信号，再到后续允许开盘执行；`eligible_date > signal_date` 只是最低检查，还要确认确为协议规定的下一周/下一可用开盘。
- 复用首12的目标差额、现金约束、百份整数、0.1%/0.2%费用、涨跌幅限制、停复牌和订单顺延/替换顺序。
- 分红必须保持登记日确认权利、除息后计应收、发放日转现金；应收计入资产但买入前不可用。H1/H2不得另造分红再投入捷径。
- 截止2026-06-30；末尾未执行订单与未完成周分类清楚，期末持仓按收盘估值，不强制卖出。
- 新方法只产生8账户；旧12账户只引用或做不改变结果的回归核对。
