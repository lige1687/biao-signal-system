# 宽基ETF技术48账户执行代码审阅

日期：2026-09-08

## 一句话结论（大白话）

本批执行代码把10个A/C/D配置和两个简单参照按协议分开处理：前者每次只拿前一日账户财富的1%计划风险并只按初始结构退出，后者用可用现金尽量买入并保留原来的趋势退出。两只ETF各自使用自己的价格日期和公司行动，来源候选原样保留；限定静态审阅没有发现影响主运行结果的偏差。

## 审阅范围

本次只审阅协议、执行器增量、运行入口、配置、候选筛选、输入锁和少量输出字段。没有独立重算48账户的逐日现金、份额、费用或收益；这部分由独立资金复核负责。审阅没有修改执行代码或运行结果。

## 协议逐项核对

- **10万元只进入一次：通过。** 主入口明确传入 `initial_per_symbol=100000`、`weekly_per_symbol=0`。执行器在循环开始前设置现金、累计投入和账户份数，只写一条初始入金事件；日账没有后续追加。48个账户的 `total_funding` 始终为100000，`deposit` 始终为0。
- **默认0保持旧行为：通过。** 新旧执行器代码差异只涉及 `initial_per_symbol` 的参数、校验、初始值和非零时日志；默认仍为0。单元测试用相同输入逐字段比较旧、新返回对象，7项测试全部通过。
- **明确配置只含A/C/D十组：通过。** `acd_methods` 恰为A20E/A20J、A60E/A60J、A120E/A120J、C1/C2/C3、D；主入口把这一集合传为 `explicit_config_set`。R0/R1不在集合内。
- **R0/R1不误用1%缩量：通过。** 诊断参照走 `full_available_cash`，买入数量只受现金、费用、整百份及正风险限制，成交记录的 `risk_budget` 为空。A/C/D才使用前一日单产品账户财富的1%预算。
- **A/C/D只按初始结构退出：通过。** 主入口为十组A/C/D显式传入 `structure_only` 回调，因此结构失效未触发时不会落入EMA和成本参考退出。输出中A/C/D卖出理由均为 `structure_stop`。
- **R0/R1保留原参考线：通过。** 两个参照不传额外退出回调，执行器先查初始失效位，再检查收盘同时低于EMA20与20根前收盘成本参考，随后下一可成交开盘退出。
- **单产品日期和行动隔离：通过。** 每个账户只向执行器传 `{symbol: prices[symbol]}`，所以下一计划日只来自该产品报价日期；行动、退出观察、涨跌幅制度和禁止交易日期也按同一产品切片。输入行动表虽含一个纳指ETF拆分，加载与调用时均被产品清单排除。
- **候选不改：通过。** 主输出 `candidates.json` 与两份冻结来源按产品和方法筛选后的对象逐字段、顺序完全相同，共1134条；其中A/C/D为379条，R0/R1为755条，候选ID无重复。
- **D零样本账户：通过。** D在两产品均无来源候选，主循环仍生成两产品乘两费用共4个账户。四个账户均有完整现金日账、零订单、零成交、期末100000元。
- **资金和空间精度边界：通过。** A/C/D在信号和计划开盘分别用十进制数重算至少3倍空间；恰好3倍通过、略低于3倍拒绝。数量先按现金和费用取整百份，再受1%风险预算限制。

## 主运行锁

运行前 `source-lock.json` 固定17项：协议及协议锁、执行器、汇总程序、主入口、测试与真实默认回归、配置、行动与覆盖说明、限制、退出观察、两份候选源和两只ETF名义行情。审阅时17项逐一重新计算，均与锁内指纹一致；完成文件也声明48账户结束且输入未变。

## 审阅中澄清但不构成问题

通用执行器在没有退出回调时保留原EMA20与成本参考退出，这是旧行为兼容所需，不能直接按A/C/D协议判断为错误。决定实际语义的是主入口：A/C/D传 `structure_only`，R0/R1传空回调。最终入口已正确分流。

通用执行器内部的计划日期来自本次传入的全部价格日期；若一次传两只产品会混用日历。最终入口每次只传一只产品，因此本批实际账户没有该问题。

## 限制

这份审阅确认的是实现分流、输入身份和关键边界。它没有逐笔重新计算成交数量、分红权利、卖出金额或期末财富，也没有把输出收益当成策略已经适合实盘。独立资金复核若发现逐日差异，应以其可复算记录继续处理。

审阅对象及报告指纹见 `review-hashes.sha256`；该清单不包含自身。
