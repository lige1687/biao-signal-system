# 原v0.2订单与日期账本：单账户单批整笔合成适配候选

## 一句话结论（大白话）

已把冻结的买卖份数、预算、费用和时点实际接到同一个人工账户账本：超限整笔拒绝，成交只记一次，卖款等明确到账后才安排后续买入。三个固定金额案例与12项新检查通过，保存的23次尝试和20项独立金额重算可以逐步核对。本次只证明这个人工账户的小范围接法，尚待主控独审，不是完整策略或真实交易完成。

## 来源与实际启动

只写本raw目录。source-manifest.json记录开工实测空间516382720字节、协调分支已由主控核验的b8c17c1cf26623e68f0c488fe1071fc13c8d59a6，以及原v0.2规范、planner_v2、planner_v1基础算术和dated_ledger的精确四源SHA。原文件只读，未重跑它们的封存测试。两策略文档SHA亦绑定；本改动只服务资金研究执行层。

接口为attempt_open(decision, plan, order, opening_evidence, ledger, batch_context)。SyntheticAccount自己创建日期账本、具名日历及开盘资料；不能给它换任意外部账本。决定和现金快照从这个账本产生，现金来源ID绑定完整账本状态和时点；不允许临时存入钱来凑通过。

## 已支持流程

开批先核完整plan_hash、decision_hash和各order_id，要求计划状态允许、现金资料来自本账户且未过时、资金回执出自本账户真实模拟卖出。只允许一个未完成内存批；每笔按原冻结顺序尝试。每次先核同一决定/成本档、计划、固定数量、日历和开盘价、买卖资格与行动覆盖，再构造稳定event_id并调用一次日期账本apply。

佣金率、最低佣金和滑点费用逐项显式传给原账本：成交价格仍是合成日历绑定的开盘价，没有先加滑点价再扣一次滑点费用。超限拒绝不缩量，未用预算不能同开盘分给另一单。一次成功更新批的预期账本状态；批外变动使该批停止，不在变动后悄悄改订单。

到账、支付、行动与收盘事件单列，不属于买卖尝试；不能在未完的冻结批中插入这些事件。本例先完成卖单，再用日历明确的advance释放受限款，然后从该账本读取已包含卖款的当前现金快照。后续计划用原参考、排序和不足额，且在之后目标开盘前冻结，仍经过原planner_v2检查。

同一order_id的成功或拒绝重放都没有第二次账本调用。单账户内存中同时记录原decision/方向/代码/目标开盘这一尝试身份，禁止拒绝后重建批或换plan_hash追同一笔。它只存在于本次模拟内存，不是预占、持久化或进程重启恢复引擎。

## 清楚保留的边界

- 一个人工账户、一次内存运行、同一冻结批内串行，只有整笔成交或整笔拒绝。没有部分成交、预占、撤单、多批并发、重启恢复或整批回滚。
- 批外现金/可卖份额变化在调用账本前停止，不靠补钱或重新缩量修复。已知必做行动未记账时，由原账本apply拒绝并保持原状态。本例分别核验这两层，不能说所有拒绝都调用了账本。
- 公司行动跨越仍unsupported；未知覆盖、无整手可卖和失败后追买没有自动处理。跨真实行动的订单调整、正式交易资格、成交能力与真实时点仍待资料及新明确合同。
- 对外直接改Python私有字段的负向夹具只用于验证批外变化会被拒绝，不是可用的资金操作接口。单账户内存来源身份也不构成防恶意输入的安全隔离。
- 没有联网、安装、真实行情、拟合、标签、真实交易、账户数据库或生产接入；没有执行完整P0/P1市场策略。工程候选、独审接受、研究结论和用户采用分别判断。
