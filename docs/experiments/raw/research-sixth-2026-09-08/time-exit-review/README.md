# 899笔旧时间退出审计：独立复核

日期：2026-09-08。只读本批冻结输入，不运行原`run_step2`、不导入主审计函数、不修改其他文件。`independent.py` 用逐个机会、逐项条件及标量价格重新构建，且把每条结果与主研究明细逐项对号。

## 一句话结论（大白话）

**重复计数确实存在，修正后的数字也核对通过。** 原15日方案把6笔重复计算，20日方案把2笔重复计算，导致原来所报的平均下降被夸大。每笔只算一次后，两方案相对原基准的平均改变都非常接近零；这足以撤回错算的下降幅度，不能据此宣布时间退出有效。四个附加条件方案没有这处重复错误，其原数值也独立复现。

冻结原脚本`run_time_stop_tail_aware_full_pool.py`普通N日分支：触发后先追加新退出结果；仅当原交易持有至少41根时才`continue`，其他触发机会接着又追加一次原结果。均值于是有905/901项。后面计算区间时的普通N日分支在追加后无条件`continue`，又回到了899项，所以旧均值与区间并非同一组数。

## 成交边界、未来信息及费用

1. **普通15/20方案本次全部是带.SS/.SZ后缀的对象，按原算法用下一根开盘。** 四条件式分别有5、3、50、26次使用非中国后缀对象的同日收盘价；即共84次以当日收盘条件同时按同一收盘成交，不符合严格“收盘确认、次日成交”。这是原算法真实限制，不应把其差异解读为实盘可以得到的改善。
2. 原禁卖循环判断下一根开盘时，错误地同时读取了**待成交那一根的收盘是否大于0**。当天开盘还不知道这个收盘。本次166次中国后缀触发所读取的收盘全部为正（最小0.322），所以这个无关条件没有改变本批数值；它仍是通用函数的未来信息依赖，后续不能原样当真实执行器。
3. 原循环在价格文件最后一根不再检查禁卖条件，存在“最后一根即使限制卖出也照卖”的边界问题。独立重建本批触发中受此影响为0；本批也没有实际顺延开盘、没有模拟退出晚于原基准退出的案例。因此这是潜在边界缺陷，不是可以用来撤回本批重复计数数字的实际原因。
4. 899条已按**旧结果最终平仓且第10日仍持有**筛选。第10/15/20根触发判断本身只用截至其检查日的收盘；旧事件表也计算了短交易退出之后的第15根观察，但这些短交易不会进入相应退出触发。完成交易的总体筛选、原最终持有41根分类均含事后信息，只可用于这次历史审计，不能替代包含未平仓、无法成交、资金不足和再进入的完整账户研究。
5. 费用混合另作独立算术排查：假设原退出价等于冻结行情里记录退出日的开盘价，用1970条`r_net`反推扣除费用，全部与替代退出所用同一公式吻合，单边费率差最大约2.4×10⁻¹¹个基点。**本事件集合未发现基准与替代退出混用费用公式。** 这不是券商费率证明；660条低价对象受按股最低收费影响，1310条反推单边5个基点。原指数、行业合成对象也不能当作可直接购买的产品。
6. 一条身份一条结果不代表彼此独立；同一行情、重叠持仓与同日多个对象仍共同承受市场变化。两项修正后平均改变接近零，也不能因为数字稍正就宣布策略有效。
