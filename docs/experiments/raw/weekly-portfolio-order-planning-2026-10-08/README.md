# 两产品共享资金：纯订单规划工程交付候选

## 一句话结论（大白话）

已把开盘前“每只分多少预算、最多买多少整百份、固定份数最高能接受什么价格”做成纯计算。给定合成输入，下一档价格超预算就拒绝，不能临时缩量；卖款没到账不能用，同开盘余款不能临时分给另一单。本次15项检查和16项独立金额重算通过，只证明这些人工算例的工程算术，尚待主负责人独审，不说明配置方法更赚钱，也没接入真实账户。

## 来源与范围

本轮只实现原v0.2已定义的开盘前算术，服务资金研究执行层。原规范SHA为695ce8a18e34d3520c53f793b1f347a05e146fea345474b5d72224ba93c30a5a，已验收带日期账本SHA为20f6547deea6d19c6416daa6048ee18a7111ff6bf4c7b21bbae90a7b379e62d3；均只读，未改动。合同、两策略源指纹、协调分支及写前磁盘实测见 input-manifest.json。每周250元、各半和偏离5个百分点是冻结研究情景，不是用户个人投入或风险偏好。

## 已实现

Decision、Asset、Costs、Order、Plan与SaleResult均为不可变对象。决定保存参考价及其已知时刻、持仓和可卖份额、自由/受限现金、应收、目标、成本与输入SHA。未来入金只标注，不计入资产或可花现金；尚未到账的free不允许写入决定。排序来自原参考资产的正不足金额，从大到小，代码打破同分。

P0按这个排序把自由现金分成互不重叠预算。整百份数量取满足预算的最大数量；数量为0不创建订单也不收费。固定数量后反求最大可承受价，向下取0.001元价位。两个费用分支用精确分数计算，避免相除舍入跨过预算界限。

P1按原5个百分点判断调节；卖量由原参考价算超额份数、向下取100整数，再受可卖整百份上限。没有触发就用P0。已触发却没有整手可卖，明确返回 triggered_no_sellable_whole_lot_pending_user，不默选如何处理新钱。当前只支持一笔完整合成卖出结果；失败、部分成交或不匹配订单ID/时刻不建立追买计划。

后续买单仍用原决定的排序、参考价和目标不足额；可花资金只按原自由现金加实际净卖款计算，费用按实际卖价计。必须实际到账后、目标开盘前冻结，并且目标开盘严格晚于卖出开盘。开盘检查固定订单身份、份数、时刻、价限及显式资格；不缩量、不改变预算、不把已过去的开盘用作执行价格。

## 明确未实现

- 不执行带日期账本，不预占资金，不支持部分成交、撤单、恢复或真实撮合；开盘验证结果只是纯函数判断，不能证明下单或成交。
- 不开发价格或交易资格的数据来源；开盘资格必须显式输入，未知就拒绝，卖出执行资格仍unsupported。
- 跨决定至执行期间公司行动，传入其时刻就返回unsupported，不猜旧订单如何调整；该动作列表来自调用者的合格资料，本模块不会发现遗漏行动。
- 触发却无可卖整手分支仍等用户决定。多笔卖出组合与失败后的重新安排没有定义，不擅自支持。
- 不对同一订单的重复调用作执行防重复处理：纯计算可以重算，后续实际执行要绑定已有订单身份与预占接口，须新适配合同。
- 不运行P0/P1真实市场策略，不获取行情、拟合、生成真实标签、读私有账户或写生产。工程完成与独审接受、研究收益、个人采用和交易授权分别判断。
