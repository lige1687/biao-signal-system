# 单原始 P0 整笔买单恢复：人工工程核验

本目录只服务原目标 5 的资金执行工程层。用一份具名人工账户、一个原决策和两张串行整笔买单，检查保存后由新 Python 进程恢复时，不会再次扣同一笔钱。它没有处理部分成交、卖款接入、真实市场资料或生产订单；不改变原有数量、限价、费用及买卖规则。

`whole_buy_recovery.py` 每次从冻结人工输入重建 `SyntheticAccount`、原决策及 `plan_p0`，按已保存次序调用原 `attempt_open` 重放成功或拒绝的尝试，再比较完整账本、审计、账户和批次状态。核对吻合后才允许下一固定订单。已提交请求会返回原回执，报告本次新增资金账本调用为零；恢复时用于重建历史的调用单独报告。

权威 `state.json` 与测试状态、故障快照、日志全部位于 `output-plan.json` 绑定的外盘结果目录。提交次序为同目录临时文件写入、刷新、替换、目录刷新。替换前失败时旧状态仍权威；替换后响应丢失时重启识别已提交请求。验证只覆盖单写者的已提交边界，不证明断电、并发写者或恶意修改防护。坏状态拒绝，不能通过重新初始化覆盖。

运行入口仅为 `run_recovery_checks.py --plan <已保存计划>`，第一次使用前重核固定外盘身份、容量和路径；每次结果写入前重核设备。该入口只运行本目录 8 组人工测试及两条真实新进程恢复路径，不调用旧套件或市场实验。外盘 `logs/validation-failed-v1.json` 保留了首次金额显示精度断言失败；后续版本另存，未覆盖。`validation-receipt.json` 汇总最终通过版本和原文件指纹。

验收结论只限一份冻结 P0 人工整笔买单在上述边界的恢复与不重复扣款。P1、卖出、部分成交、撤单、新决策、外部账户变化及实时交易资格均未接入。
