# 开发任务路由改为 GPT-6 系列

## 一句话结论（大白话）

项目开发任务现在会按难度建议 GPT-6 Luna、Sol 或 Astra，并写明思考强度；旧模型路线已停用。29项路由检查和3项编排检查通过，尚未用新的路线做真实任务派发或再次调用 Jev。

## 服务于哪一层

这次改的是开发协作流程，用来选择谁执行代码、研究适配或复核任务。交易体系中的道路、路牌、入场触发与过滤纪律均由原有规则决定；本次未修改交易判定或产品接口。

## 现行路线

| 工作 | 模型与思考强度 |
|---|---|
| 一个命令、只读核对或极小修改 | 当前任务直接完成，不增开模型调用 |
| 边界清楚的小脚本或机械修补 | GPT-6 Luna，低思考 |
| 方案明确的普通开发 | GPT-6 Sol，低思考 |
| 研究适配、冻结实验、证据整理 | GPT-6 Sol，中等思考 |
| 疑难工程排查 | GPT-6 Sol，高思考 |
| 策略含义、研究方法或重要架构决定 | GPT-6 Astra，高思考 |
| 真实资金、关键时点或跨层高风险复核 | GPT-6 Astra，超高思考 |

用户当次明确指定的模型优先；任何委派仍先检查当次模型可用性。Jev 只在相邻路线确实难分时提供一次建议，不能直接派发。
模型名称与思考强度核对了 [OpenAI 官方模型目录](https://developers.openai.com/api/docs/models) 和 [GPT-6 迁移说明](https://developers.openai.com/api/docs/guides/latest-model)。

## 改动与兼容

- 项目级 `lei-task-router` 的路线表、候选说明和输出已改为 GPT-6，并直接输出 `model` 与 `reasoning_effort`。
- 路由协议从 `1.0.0` 升为 `2.0.0`；旧的 `spark_low`、`terra_medium` 请求会被拒绝，旧缓存不会套用到新路线。
- 项目专用的 `lei-gpt-zcode-orchestrator` 已迁入仓库 `.agents/skills/`。新任务使用 GPT-6 Codex 委派；既有 ZCode 任务记录仍保留原始归属。
- 通用的 `codex-delegate` 继续按项目 `AGENTS.md` 和冻结任务合同接收模型与思考强度，本身没有固定旧模型。

## 验证

- 路由测试：29项通过，覆盖 GPT-6 名称与思考强度、旧路线拒绝、模型不可用时回退、缓存和 Jev 异常处理。
- 编排 Skill 测试：3项通过，覆盖新任务模式、历史任务边界与必要的模型合同。
- 两个 Skill 的结构校验通过；仓库归置检查通过。
- 本次未消耗 Jev 调用额度。旧报告中的真实调用数据只代表旧版路线，不能当作 GPT-6 路线的实际效果。
