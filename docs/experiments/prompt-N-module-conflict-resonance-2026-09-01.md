# Prompt N：A/B/C/D 入场模块间信号冲突与共振检测（预注册复验）

> 独立成文件，供分发给独立、无上下文的 agent。与 `prompts-2026-09-01.md` 里的
> A-M 十三份 prompt 并列，遵守相同的收尾规约（见文末）。

你在 `biao-signal-system` 仓库工作（当前分支 `recovery/lei-round2`）。只读研究任务，
**不改 `src/` 下任何生产代码，不 push，不删任何现有文件**。

## 背景：这个方向从哪来，为什么是真空

现有系统四个入场触发模块——A回调 / B密集突破 / C 2B破底翻 / D假突破——按
`AGENTS.md` 的定义是"四模块独立，进出同一逻辑"。到目前为止所有回测（exit-matrix、
exit-structural-stop-revival、stop-loss-matrix）都是**逐模块单独测**，从未有人系统
检验过：**同一个标的、同一天，如果两个或更多模块同时触发信号，这算共振（应该更
可信）还是冲突（两个模块对同一价格行为给出了矛盾的解读，应该更可疑）**。

已有一条相关但不完整的线索，必须先读：
`docs/experiments/heiti-ARCHIVE-2026-08-31.md` 第三节"观察中"表格的 H5 行——
"同日信号聚集：4+ 信号日 expR +1.05 vs 单信号 +0.60（n=88）"，标注"单一后验分组，
需预注册复验"。这条测的是**信号数量**（多少个独立信号同一天触发），不区分是
"同模块多标的同时触发"还是"同标的被多个模块同时命中"，也没有区分"共振（方向一致）"
和"冲突（方向矛盾，比如 A 模块判断为回调买入，同时另一标的的 D 模块判断为假突破
卖出——这本身不构成冲突，因为是不同标的；真正的冲突场景是同一标的同一天被 A 模块
判定"回调买入"、同时因为价格行为也满足了 C 模块"2B破底翻"的触发条件，两者对
"这是延续还是反转"给出了矛盾信号）。这是 H5 完全没拆解过的维度，也是本任务真正
要做的事：**先把 H5 的后验分组做成预注册复验，再往下拆解"共振"和"冲突"两种子情形
是否有不同表现**。

## 任务

**第一步：H5 的预注册复验（不是重复，是把后验发现按纪律重跑一次）**

1. 复用 `scripts/run_exit_matrix.py` 或已有归档（`raw/exit_revival_a64/`、
   `raw/stop_loss_matrix/`）里已经产出的 A/B/C 三模块逐笔记录（含 entry_date 和
   symbol 字段），先按 heiti-ARCHIVE 原始定义复现 H5（同日信号数量分组 vs expR），
   判定标准和分组阈值（"4+信号日"这个界限是怎么定的）**必须先写死在脚本 docstring
   里再跑**，不能跑出来看着调整分组线——heiti-ARCHIVE 自己承认这是"单一后验分组"，
   本任务的第一个任务就是把它变成有预注册纪律的版本。
2. 用配对 bootstrap（参照 `stop-loss-matrix` 已用的方法，10000次，固定种子）检验
   H5 的 +1.05 vs +0.60 差异在预注册后是否仍然显著。
3. 如果预注册复验后 H5 本身就不显著了，直接归档为"后验发现未能复验，证伪"，**不要
   继续做第二步**——这是纪律要求，不是可选项。

**第二步（仅当第一步复验通过才做）：拆解共振 vs 冲突**

4. 定义"共振"：同一标的、同一天，多个模块（不论哪几个）同时触发，且触发方向一致
   （都是买入类信号，当前系统入场信号统一是买入方向,不存在系统内建的卖空信号,
   故本任务的"方向"实际指的是"评估同一次价格行为为延续 vs 反转"——A/B是延续类
   逻辑,C/D是反转/假突破修正类逻辑,需要先去读 `src/lei_signal/rules/` 下四个模块
   的信号定义确认这个分类是否准确,不要凭本prompt的描述直接假设,以代码里的实际
   触发条件为准)。
5. 定义"冲突"：同一标的同一天,一个延续类模块和一个反转类模块同时触发（如 A 模块
   判定当前趋势延续可回调买入,同时 C 模块判定这是破底后反转)。
6. 分组统计：共振组 vs 冲突组 vs 单模块组的 expR/PF/胜率对比,判定标准同样先写死
   (比如"共振组显著优于单模块组"和"冲突组显著劣于单模块组"分别是两条独立可否证
   的假设,不要合并成一条模糊结论)。
7. 样本量如果不足(冲突场景大概率比共振更稀有,可能显著样本不足),必须显式标注,
   不得用样本不足的格子下结论。
8. 双跑哈希核对(PYTHONHASHSEED=0/42)。环境限制:主树 backtest 包目前处于半重构
   状态(见 `macd-strength-layering-ARCHIVE-2026-09-01.md` 开头说明),若需要重新
   生成逐笔数据,复用 `raw/exit_revival_a64/README.md` 里的环境重建方案,不要重新
   发现这个已知问题。
9. 至少一个阴性对照(比如把触发日期标签随机打乱后重新分组,确认真实的共振/冲突
   效应显著高于随机噪音基线,参照 `macd-strength-layering-ARCHIVE-2026-09-01.md`
   用过的"200次标签打乱"方法)。

## 输出

`docs/experiments/module-conflict-resonance-ARCHIVE-2026-09-XX.md`，格式对齐现有
ARCHIVE（通过清单 / 证伪清单 / 观察中 / 下一步方向 / 冲突发现，各项标验证强度）。

冲突发现一节必须明确回答：
1. 本任务的"冲突/共振"检测和 heiti-ARCHIVE 的 H5、以及 `orthogonality-check`
   任务（Prompt D，测的是不同信号腿之间的相关系数）是否有方法论重叠——如果
   有，说明本任务的增量具体在哪（本任务是模块间**同标的同日**的细粒度冲突检测，
   D 任务是**不同信号整体收益序列**的相关性，颗粒度不同，但需要在报告里明确
   讲清楚区别，不能含糊）。
2. 如果发现"冲突组显著更差"，是否可以自然地导出一个**确认层规则**（不是新的
   买卖点，是"同一信号触发时，检查是否有其他模块同时给出矛盾判断，若有则标记
   该信号为低置信度"）——这个结论如果成立，其角色定位应类比 Prompt E（MACD分层）
   和 Prompt L（板块RS分层）：只能进确认层，不能自己产生交易事件。

## 明确不做

- 不做仓位系数映射（不是本任务范围）。
- 不产生新的买卖点或交易事件——即使发现"共振组更好"，结论也只能是"共振可作为
  现有信号的置信度参考"，不能设计成"共振时加倍下单"这类新规则（那需要另开一轮
  实验且需用户单独拍板，仓位相关的机制改动全部走 Prompt F/K 那一类任务的纪律）。
- 不重新定义 A/B/C/D 四个模块本身的触发条件（这是既有生产规则，本任务只读不改）。
- 不在有第一步都没通过预注册复验的情况下继续做第二步——如实止步。
