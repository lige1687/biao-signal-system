# Prompt W：持仓基金与已验证宽度指标的相关性研究——找到可复用的参考规则

你在 `biao-signal-system` 仓库工作（当前分支 `recovery/lei-round2`）。只读研究
任务，**不改 `src/` 下任何生产代码，不 push，不删任何现有文件**。

## 用户会告诉你的信息

用户会提供当前持仓的具体基金代码/名称（可能包括全球半导体基金、A股通信设备
相关基金、有色金属相关基金、恒生科技相关基金，具体以用户实际提供的代码为准，
不要在拿到代码前臆测）。

## 任务目标

这不是简单的"查一下现在的信号读数"，是要做一次**相关性研究**：系统里已经
验证过一批行业/宽基指数的宽度择时规则（证券、白酒、有色、银行、通信、创业板
等，见下方背景），但用户的实际持仓可能是QDII基金、跨境ETF联接基金等，不一定
和系统里已验证的标的是同一个指数。你需要：

1. 找到用户每个持仓基金**实际跟踪/最贴近**的标的（可能是A股行业指数、可能是
   海外指数、可能是某个ETF的联接基金）。
2. 计算这个持仓基金的历史净值/份额走势，和系统里已验证过规则的各个候选标的
   之间的相关性，找出相关性最高的那个。
3. 如果相关性足够高（需要设定一个明确的、写在前面的阈值，不要事后调整），
   才能说"这个持仓可以参考XX标的已验证的规则"；如果所有候选相关性都不够高，
   如实说"未找到可复用的参考规则"，不要为了给用户一个答案而硬凑一个低相关性
   的候选。

先读这两份归档，把里面所有已验证规则的标的都列成一个候选清单：

   SPY/QQQ/XLK/SMH/XLF/XLE防守版（第31轮"美股ETF×宽度防守版"）。
2. `docs/experiments/kuandu-quanzhan-ARCHIVE-2026-09-01.md`——创业板(159915)
   冠军三档、8指数等权篮子的构成清单（创业板/证券/新能车/白酒/有色/银行/
   通信/沪深300）。

**已知的重要背景（写进最终报告，不要遗漏）**：
- A股半导体(512480)已被诊断为"2019年起两段不跟随大盘宽度的独立牛市（国产
  替代、AI），逆势档位在独立行情段会踏空，仅做热度参考不做进出引擎"——如果
  相关性研究发现用户的全球半导体基金与A股半导体高相关，这条诊断需要原样

  从未验证过的"恒生科技逆势规则"。

## 任务步骤

### 第一步：数据准备

1. 获取用户提供的每个持仓基金的历史净值序列（如果是跟踪指数的ETF/联接基金，
   净值走势应该高度贴近其跟踪指数，可以直接用指数点位序列做相关性计算的
   代理，但要在报告里说明用的是净值还是指数点位）。
2. 获取候选清单里每个已验证标的的历史价格序列（复用系统现有的数据获取
   逻辑，比如`src/lei_signal/data/`下的provider，不要重新设计抓取方式）。
3. 时间窗口要对齐——用持仓基金和候选标的共同存续的历史区间做相关性计算，
   如果持仓基金历史很短（比如新发的QDII基金只有1-2年数据），如实声明样本
   量的局限，不要用短窗口的相关性系数冒充长期稳健的结论。

### 第二步：相关性计算（判定标准先写死，不要跑出来看着调）

1. 用日频收益率（不是净值水平本身，避免趋势混淆相关性）计算持仓基金与
   每个候选标的的Pearson相关系数，同时算Spearman相关系数做交叉验证（参照
   `docs/experiments/prompt-T-valuation-overlay-2026-09-02.md`验证创业板50
   与沪深300代理关系时用过的方法——那次用0.80作为"可代理"的阈值，本任务
   需要独立设定阈值并说明依据，不要不经检验直接照搬那个数字）。
2. 判定线：设定一个"高相关"（可以复用该标的已验证规则作为参考）和
   "中低相关"（不建议复用，只能说方向类似）的分界线，在docstring里写清楚
   这个分界线是怎么定的（比如参照统计学惯例或本任务自己的论证），跑前
   固化，不得跑完看数字再调整。
3. 双跑哈希核对（PYTHONHASHSEED=0/42）。
4. 滚动窗口检验：不要只算一个全窗口的相关系数就下结论——检验相关性在
   不同时间段（比如按年或按2-3年窗口滚动）是否稳定，如果相关性本身在
   剧烈波动（某几年高相关、某几年完全不相关），必须如实报告这个不稳定性，
   不能只报一个平均值。

### 第三步：对找到高相关标的的持仓，查询当前信号状态

1. 只对第二步判定为"高相关"的持仓-标的配对做这一步。
2. 拉取该标的当前的市场宽度数据（B200/B50或行业自身宽度代理），套入已验证
   规则的具体参数（如冠军三档43.3/56.7、双极值20/85-90），给出"按这条规则，
   当前处于哪个档位"。
3. 如果本机环境缺少运行查询所需的依赖或最新行情缓存，需要搭建必要环境并
   联网拉取最新数据，不要用陈旧数据冒充当前状态——如果数据有时间差，必须
   明确注明实际时间戳。
4. 特别检查通信板块的RS虹吸灯当前状态是否仍然触发（不能引用8-27的旧结论）。

## 明确的红线（必须逐条遵守，与AGENTS.md一致）

- 不使用"买入/卖出/建议买/该买/加仓/减仓/抄底"等买卖指令类词汇。
- 不给出任何"综合建议"或"整体判断该不该动"的结论——只呈现相关性数字和
  对应规则的当前读数，是否采取行动完全由用户自己判断。
- 不为了给每个持仓都凑一个"参考标的"而放松相关性判定标准——找不到高相关
  标的是一个合法且可能正确的结论，必须如实报告。
- 不把"防守闸"类规则（回撤保护）表述成"择时增强"，两者性质不同。
- 不使用合成或插值数据冒充真实历史价格。
