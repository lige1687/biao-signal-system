# Prompt X：宽基指数体系化回测——覆盖清单同步 + 缺口补齐 + 组合搭配 + 技术系统应用总览

你在 `biao-signal-system` 仓库工作（当前分支 `recovery/lei-round2`）。这是一个
**大型汇总+补齐任务**，分四个阶段，前两个阶段是强制的（不能跳过），后两个
阶段依赖前两个阶段的产出。全程只读研究性质（新增文件），**不改 `src/` 下
任何生产代码，不 push，不删任何现有文件**。

## 任务背景

系统已经对A股/美股的行业指数、宽基指数、双极值警报、参数网格等做过40+份
独立归档实验（`docs/experiments/*.md`），但这些结果分散在各份报告里，从未
对"宽基指数"这个类别做过一次系统化汇总，也没有覆盖用户实际关心的几个标的
（科创100、恒生科技）。用户的诉求是：**把宽基这条线彻底测透，并且看清楚
不同宽基之间怎么组合搭配、以及现有技术信号系统（LEI四模块/宽度/MACD等）
在宽基上具体怎么应用**。

## 阶段零（强制，必须先做）：跨机器任务覆盖清单同步

**这是本任务的第一优先级，早于任何回测工作。** 本系统的实验任务分布在
至少两台不同机器/会话上执行，各自都可能产出了对方看不到的归档文件（可能
只commit未push、或push了但另一边未pull、或在不同的本地分支）。在开始任何
新的回测之前，必须先做这件事，否则会重复已经做过的工作，浪费算力，也可能
产出与已有结论冲突却互相不知道的重复实验。

1. 执行 `git fetch --all` 和 `git log --all --oneline -- docs/experiments/`，
   列出当前能看到的**全部**commit历史里涉及`docs/experiments/`的文件变更，
   不要只看当前HEAD checkout出来的文件列表（远端可能有还没pull下来的
   commit）。
2. 列出`docs/experiments/`目录下所有`*.md`文件（当前工作区+git历史里存在
   过的），和`docs/experiments/prompts-2026-09-01.md`及后续单独成文件的
   `prompt-*.md`系列做交叉核对，确认每一份已发出的prompt（截至本任务发出
   前，编号A到W，具体清单见该目录下所有`prompt-*.md`文件）是否已经有对应
   的执行结果归档，以及执行结果归档本身是否已经被pull到本次任务运行的
   环境里。
3. 如果发现远端有本次任务运行环境里不存在的commit（无论是新的归档、新的
   prompt文件、还是对现有文件的更正），**先pull下来**，再继续往下做。
   如果pull后出现冲突或分支状态不一致，停下来在报告里如实描述冲突情况，
   不要自己用`--force`或者丢弃本地更改的方式强行解决。
4. 产出一份`docs/experiments/coverage-sync-2026-09-XX.md`，列出：
   - 已确认存在且已同步的归档清单（按任务字母/名称，一行一条）
   - 本次同步过程中新发现、之前未见过的归档（如果有，说明是从哪个commit
     找到的）
   - 任何未能同步的疑点（比如某个commit引用的文件在任何分支都找不到）

**只有阶段零完全跑完、确认环境状态一致，才能进入阶段一。**

## 阶段二：补齐缺口回测（仅针对阶段一确认为"未测"或"证据不足"的标的）

根据阶段一的核实结果（不要预设结论，可能科创100其实已经被某份归档间接
测过，也可能确认的缺口比预想的更多），对确认缺失的标的补测，**复用现有
框架和参数，不重新发明规则**：

1. **科创100**（如果阶段一确认缺失）：套用现有A股三档逆势框架（全A等权
   宽度cn_all定档，参照冠军三档43.3/56.7或行业已验证的30/70、40/60档位
   线，先判断科创100的波动特征更接近哪一类再选档位线，不要不加选择直接
   套用创业板的档位线）。判定标准和验证强度要求（三窗一致/参数邻域/5年
   滚动）参照冠军三档当年的验证方法，不能降低标准去凑一个"测过了"的结果。
2. **恒生科技**（如果阶段一确认缺失）：这是一个**已知的高风险方向**——
   Prompt W的相关性研究已经明确说明"恒生科技的宽度择时若要做，需要香港
   本地成分股宽度数据，不在本系统现有候选的能力范围内"。本任务需要先
   查证：系统是否有获取恒生科技指数成分股清单及个股行情的能力（港股
   数据源，参照`src/lei_signal/data/providers.py`现有的港股支持范围）。
   如果没有本地成分股数据，只能退而用"恒生科技指数自身的价格宽度代理"
   （比如用恒生科技指数自身的均线结构做双均线判断，而不是成分股广度），
   这是一个**性质不同、强度更弱**的择时方法，必须在报告里明确说明这是
   降级方案，不能包装成和A股三档同等级的"宽度择时"。如果连指数自身数据
   都拉不到，如实声明数据工程欠账，不要跳过声明直接放弃或者硬凑合成数据。
3. 双跑哈希核对（PYTHONHASHSEED=0/42），判定标准先写死在脚本docstring。
4. 阴性对照（复用已有框架里用过的方法，比如黄金/无关资产对照）。

## 阶段三：宽基组合搭配研究（依赖阶段一+阶段二完成）

不是重新设计新机制，是把阶段一+阶段二产出的所有"已验证/新验证"宽基候选，
系统性地梳理它们之间可能的组合方式：

1. **汇总现有已测过的组合先例**（不要重新发明，先列清楚已有的）：
   - 两只版（创业板择时+纳指持有）
   - 8指数篮子（1宽基+7行业等权）
   - 攻守兼备型（沪深300反转10/90+分批+闸门）
   - Prompt PQ（如果已执行）里可能测过的其他宽基对比结果——**注意查阶段
     零的同步结果，Prompt PQ这份文件截至发出时可能还没被执行，需要核实
     当前状态**
2. **新组合候选设计原则**：任何新组合搭配的假设,必须说明"这个组合想验证
   什么假设"，不能只是排列组合几个标的凑数。参考此前合体组"两条低相关性
   策略腿正交叠加"的方法论——组合是否有意义，先看候选标的之间的相关性
   （复用Prompt W已经建立的相关性计算方法），再决定要不要设计组合回测。
   建议的组合方向（供参考，不是必须全测，按相关性结果筛选后再决定）：
   - A股宽基（创业板/沪深300/科创50/科创100，如果补测完成）多资产等权
     vs 现有8指数篮子，对比"纯宽基篮子"和"1宽基+7行业篮子"哪个稀释效果
     更好（这是此前Prompt Q提议但可能未执行的方向，需要核实执行状态）
   - 恒生科技（如果补测出可用信号）与A股宽基的相关性——如果相关性低，
     可能构成一个新的分散候选；如果相关性高（比如和创业板/科创50这类
     成长股高相关），则不构成独立分散价值，只是同一个beta的另一种表达
3. 判定标准、双跑哈希、阴性对照要求与前述阶段一致。

## 阶段四：技术信号系统在宽基上的应用总览（依赖阶段一二三）

汇总现有系统里，四个入场触发模块（A回调/B密集突破/C 2B破底翻/D假突破）、

**实际验证过的应用情况**——不是重新测试，是整理成一张清晰的"组件×标的"
覆盖表：

1. 查`docs/experiments/macd-strength-layering-ARCHIVE-2026-09-01.md`、
   `docs/experiments/module-conflict-resonance-ARCHIVE-2026-09-02.md`等
   已有归档，确认这些技术组件测试时用的标的池（个股为主还是也覆盖了
   宽基ETF），如果宽基ETF上的技术信号应用证据不足或缺失，如实标注为
   "技术组件目前主要在个股/行业ETF池验证，宽基指数上的独立验证证据
   不足"，不要臆测宽基上也一定适用。
2. 双极值警报和RS虹吸灯已经在宽基上有直接验证（创业板/科创50/通信等，
   见Prompt W查到的当前信号状态），这部分整理成表即可，不需要新测。
3. 产出一张"宽基指数×技术组件"矩阵表，每个格子标注：已验证/部分验证

## 明确的红线（贯穿全部四个阶段）

- 不产生任何买卖点或仓位系数机制（继承所有已有prompt的红线）。
- 不重新发明已经验证过的规则参数——阶段二补测时优先复用现有档位线/分位
  阈值，只有在标的特征明显不同（比如波动率结构、历史窗口长度）时才可以
  调整，且必须说明调整依据。
- 不为了完成任务而降低验证标准——阶段二的补测如果做不到三窗验证/参数
  邻域扫描（比如数据历史太短），必须如实标注认证强度不足，不能包装成
  和冠军三档同等级的结论。
- 不臆测阶段零的同步结果——如果发现远端有更新的prompt文件（比如PQ、T、
  U这几份是否已经执行完成），必须先核实清楚再决定阶段三是否需要重新
  设计组合方案，不能假设"应该已经测过了"就跳过。
- 恒生科技如果只能做降级版择时（指数自身价格结构而非成分股宽度），
  必须明确标注这是弱化版本，不能等同于A股三档规则的认证等级。
