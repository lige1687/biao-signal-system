# Prompt S：B模块高波信号反向假设——加仓而非减仓

你在 `biao-signal-system` 仓库工作（当前分支 `recovery/lei-round2`）。只读研究
任务，**不改 `src/` 下任何生产代码，不 push，不删任何现有文件**。

## 背景：这个方向从哪来

`docs/experiments/full-pool-revalidation-ARCHIVE-2026-09-02.md`（任务R，全池
复验）第五节"下一步方向"第3条记录了一个未深入的观察：三个入场模块在RV20
三分位的高波组表现方向不一致——

- A模块：高波组 r_net **-1.106R**（全池复验强化了原K任务的发现，高波是亏损
  主力，vt缩放对A模块有减仓的合理性）
- B模块：高波组 r_net **+0.330R**（与A反号——高波信号反而是盈利的）
- C模块：高波组 r_net -0.073R（接近零）

该报告原话："这意味着B模块的'高波入场'可能不是亏损主力（与A不同）...这一
线索若属实则B应反vt（高波时加仓）而非去vt。本任务仅观察到这一反差，不下
结论——B的处理需要单独的实验设计。"

现有K任务（`vt-signal-driven-sizing-ARCHIVE-2026-09-02.md`）和R任务都测过
"vt缩放对B模块无效"（全部证伪，7档ΔexpR≈0或负），但两次测的都是**同一个
方向**——用波动率去**减仓**（`E = clip(目标/RV20, 0.25, 1)`，RV20越高E越小）。
如果B模块的机制真的和A模块相反，那么"vt对B无效"这个证伪结论的真实原因
可能不是"B模块不需要按波动率调整仓位"，而是"调整的方向错了"——两者是完全
不同的结论,前者说"B不需要这个机制"，后者说"B需要这个机制但要反着用"。

## 任务定位：先验证机制假设本身，再决定是否设计反向规则

**不要跳过验证直接设计"B模块高波加仓"的新规则去回测。** 按四路体系一贯的
纪律（继承自F/G/L等复活尝试任务的开工条款），必须先回答"这次为什么可能
不同"这个机制问题，再决定是否值得设计新实验。

### 第一步：确认这个反差不是统计噪音（必做，决定是否继续）

1. 复用 `docs/experiments/raw/vt_signal_sizing_full_pool/run_vt_signal_sizing_full_pool.py`
   里B模块的RV20三分位分组统计代码（该脚本已经算出了本任务背景引用的
   +0.330R这个数字），补充做：
   - **配对bootstrap检验**：B模块高波组 vs 低波组的r_net差异，95%置信区间
     是否显著不含零（任务R原报告只列了三个模块的三分位均值对比表，没有对
     B模块单独做显著性检验，本任务的第一件事就是补上这个）。
   - **样本量核查**：B模块552笔有效平仓分成三分位后，高波组具体有多少笔，
     是否达到基本的统计功效门槛（参照M任务用过的n≥30这类门槛，先写死在
     脚本docstring里再跑）。
2. 判定标准先写死：如果置信区间含零或样本量不足，直接归档"反差不显著，
   可能是三分位切分下的噪音，不构成机制假设"，**不进入第二步**。
3. 双跑哈希核对（PYTHONHASHSEED=0/42）。

### 第二步（仅当第一步确认显著才做）：设计并测试反向仓位规则

如果第一步证明B模块高波组确实显著优于低波组，才设计"高波加仓"的反向vt
规则：

1. 定义反向缩放系数：`E_reverse = clip(RV20/目标, 1, 4)`（RV20越高，E越大，
   与现有vt公式方向相反；上限4是防止极端杠杆，需要在docstring里说明这个
   上限的选择依据，不要拍脑袋定数字不解释）。或者更保守的版本：
   `E_reverse = clip(1 + (RV20-目标)/目标, 1, 2)`（温和放大，不做4倍杠杆
   这么激进的假设）——两个版本都测，不要只测一个就下结论。
2. 判定标准复用K/R任务已经写死的J1/J2/J3框架（风险效率改善/绝对收益保留/
   盈利因子约束），但注意：**这次retention的方向定义需要重新想清楚**——
   原vt任务的retention衡量"减仓后是否保留了大部分绝对收益"，反向加仓
   不存在"收益保留不足"的问题（加仓只会让收益更多，不会更少），J2这个
   判定条款对反向规则可能不适用或者需要换成别的经济性约束（比如"是否
   引入了不成比例的尾部风险"），必须在docstring里重新论证一遍判定标准，
   不能照抄原公式却不检查是否合理。
3. 双跑哈希核对，至少一个阴性对照（比如把RV20标签随机打乱后重新分组，
   确认高波组的优势不是随机噪音）。
4. 数据源：复用任务R已经锚定验证过的175标的全池（
   `docs/experiments/raw/backtest-runs-snapshot-2026-08-31/` 的B模块run
   + `docs/experiments/raw/pool-snapshot-2026-08-25/` 的K线快照），不要
   重新抓数据，直接复用已经锚定过5层100%对齐的现成基准。

## 明确不做

- 不对A、C模块做同样的反向测试——A模块的"高波亏损"机制已经在两轮任务
  （原K + 全池复验R）里被反复验证是真实且方向一致的，不需要再测反向假设；
  C模块高波组接近零（-0.073R），没有显著的方向性证据支持反向假设，除非
  第一步的显著性检验意外发现C也有反差（如果发现了，如实报告但不必因此
  扩展到C模块的第二步实验，那需要另开一个任务）。
- 不产生任何新的买卖点——即使反向加仓规则测出正增量，结论也只能是"B模块
  的vt缩放方向可能需要反转"这个仓位管理层面的候选，需要用户单独拍板是否
  要往下推进到实际落地，不能自己下"应该采纳"的结论。
- 不假设4倍杠杆这个上限是对的——必须和更温和的版本对比，如实报告哪个
  更稳健。
