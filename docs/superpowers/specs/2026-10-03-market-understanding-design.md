# 市场理解：内容与入口设计草案

状态：用户于2026-10-03以“继续大范围的做吧，按照我们的目标去做”确认后，按B方案实施第一版；最新实测状态见同日实施证据README。日期：2026-10-03，Asia/Shanghai。任务：investor-observation-map。工作基线：`1f59cf73dd019df487b7a2d3138445f4a3756e28`；现有市场页面参考：`55d8aa96b45d97b09901ded4ebf78f490bbb7f6b`。后续不得从共享脏目录直接复制整页。

## 1. 已确认要解决的问题

用户想了解专业投资者和机构关注什么、为了什么，补齐系统缺项，增加已有信息的解释密度，并让这些内容显眼、易懂。日常观察、理解市场、联系具体ETF三种使用都需要。用户明确要求避开远端任务。

完成产品的业务含义：用户从一个观察入口能回答“发生什么变化、是什么对象和时点、可能代表什么、还要核什么、何时可能误判、是否与我关注的ETF相关”。上线、卡片数量和工程测试不能代替用户能否理解的测量。收益效果未测，本设计不承诺提高收益。

## 2. 三种可以选择的做法

| 做法 | 优点 | 代价/局限 |
|---|---|---|
| A：仅扩充现有基本面页 | 最少导航改动，复用现有卡 | 信息仍在菜单和不同页面里，主题与投资目的难形成统一入口 |
| **B：新增“市场理解”入口，复用各模块数据与详情** | 能先按问题读，再到原模块；显眼且可保持原负责人 | 需要一个新聚合页及少量导航/路由接线，必须先协调具体块 |
| C：全面重构首页、情绪、基本面、资讯和ETF详情 | 可统一全部体验 | 跨团队改动大，容易与远端重叠，也延迟第一版可用 |

建议B。先完成一个清楚的观察入口，页面细节引用现有模块，数据接入仍由原来源负责人维护。此选择起初是主控建议；后续继续实施授权已确认本方向。第一版不重构其他页面、不自建第二套数据缓存或研究总分。

## 3. 显眼但能逐层阅读

建议主导航“看盘”附近放“市场理解”。在窄屏保留可识别入口，不仅放入多层菜单。首页可增加一个链接摘要，但是否改首页留到准确文件分工后；第一版主导航入口本身即可满足直接到达。

入口建议路由 `/market-understanding`（本轮实施的新路由）。页面依次提供：

1. **我今天应该留意什么**：按A股/美股选择展示有依据的变化、即将到来的已核事件以及资料缺项。只有历史或缺数据时如实说明，不能写“今日市场平静”。
2. **我想理解哪类问题**：趋势参与、调查仓位、杠杆、波动保护、经济融资、估值经营、ETF产品、个人方法八个主题。可切换趋势/定投/价值读取顺序，不改变数据或技术规则。
3. **这个指标怎么看**：展开说明卡，显示“位置高低”和“变化方向”、配套资料、另一种解释及证据。
4. **与我关注的ETF有什么关系**：先按标的指数、市场、币种和产品结构关联，不根据名称猜成分，也不读取私人资金/数量。关联不确定时写明范围未知。

首屏优先级按内容组织：资料身份和异常状态 → 与选定市场/ETF直接相关的变化或事件 → 其余主题。先用明确排序，不把众多指标加成一个风险分数，也不用未验证的收益预测给卡片排队。

## 4. 同一张卡的三个层次

**收起时**：指标名称、适用市场、读数/缺项、所属期、比较期、变化的一句事实。首次公开时点未核时显示该状态。颜色表达变化方向或资料状态，不暗示买卖。

**第一次展开**：这项数据在回答什么；升高、降低和位置高低各是什么含义；两到三项配套检查；一个容易误解的情况；与当前所选方法的关系。

**证据详情**：定义、单位、公式/分母、来源及版本、观测期/发布/取得时间、历史窗口和有效覆盖、修订/分类断点、使用限制、说明内容版本。

指标的定义和读数分开管理：没有读数也可以阅读学习卡，但学习卡不得混入“今日变化”。事件类字段不硬塞高低解释；没有合格预期时展示“未取得可比预期”，禁止生成“超预期”。

首批内容输入为`docs/experiments/raw/market-understanding-expansion-2026-10-03/indicator-cards.json`，12卡均为设计素材，`latest_value=null`。它不构成已实现API、合格数据或已上线功能。

## 5. 复用关系及技术边界

现有读取入口已在准确版本核到：`GET /api/fundamentals/observations?market=cn|us`，前端调用为`fundamentalsApi.observations`。其内容与`/fundamentals/overview`的其他宏观资料不是同一条资格链，不能混称全部已核。

拟议模块只需要：

- 新聚合页：管理市场/主题/方法选择、空缺显示和跳转。
- 解释内容：版本化的说明对象，绑定指标ID、适用对象、来源和反例。先复用研究内容，正式落点在实现计划阶段选定，不让归档raw脚本成为生产依赖。
- 现有观察数据：复用接口和既有日期/来源组件，未经确认不改`ObservationSourceNote`或`MarketObservationCards`。
- 关联表：指标适用市场/指数/产品结构到ETF详情的显式映射，未知不推断。

新资料接入为独立后续步骤。FINRA不存在官方data feed的事实需纳入取得方式设计；CFTC必须固定类别/合约/格式；ETF数据按具体产品核资格。只把来源和内容补齐，不改变LEI触发、失效、退出或宏观硬过滤。

拟议页面文件`web/src/pages/MarketUnderstandingPage.tsx`与独立内容组件已在本任务独立工作区创建。`web/src/App.tsx`、`TopNav.tsx`仅修改已登记的路由/入口小块；它们在共享工作区已有别的修改，不能据本草案视为无人使用。实施前重新fetch协调并明确实现者；本任务不占整文件，不切换脏工作区。Streamlit保持冻结。

## 6. 状态、时间和错误如何呈现

状态至少区分：有当前合格资料、有延迟但正常频率的资料、仅历史固定资料、未接入、上游错误、资格未核。数据为空不能填0，来源失败不能消失成“没有变化”。

月度数据不因多日未变被标失效；A股与美股交易日、时区分别处理。数据所属期、实际公布时点、系统取得时点不能互相替代。相邻点之间若有缺期，“前20个有效点”不能改称“20个交易日”。

不同市场的杠杆、调查、指数估值和期限曲线不直接同轴排名。计算比值前检查范围/时间/单位；融资证券可能含基金，不能除以仅股票成交额。跨境ETF净值和价格时点不同则展示限制，不计算貌似精确的套利空间。

官方数值、调查、估计和解释分别标识；内容更新或版本变化保留审查记录。没有许可时只保留入口和缺口，不因公开可读就批量保存或再分发。
