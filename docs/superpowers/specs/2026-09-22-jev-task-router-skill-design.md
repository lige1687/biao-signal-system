# Jev 开发任务路由 Skill 设计

日期：2026-09-22

## 1. 目标

为 `lei-signal-lab` 增加一个项目专用的 `$lei-task-router` Skill，在需要决定执行方式时，给出“当前 Codex 直接做，还是委派给哪个模型、采用多深思考”的建议。

用户要求同时做到两件事：降低模型调用成本，提高开发执行效率。因此首版采用“固定规则优先、Jev 只处理边界任务、现有 Skill 继续负责执行”的结构。Jev 没有派发权，也不改变交易策略、生产后端或用户权限。

已有 18 条冻结任务的盲测结果是：17 条拿到 Jev 答案的任务全部选中预设路线；1 条因网络错误没有答案。这个结果支持把 Jev 用作路由顾问，也同时证明必须保留本地回退。

## 2. 适用范围

Skill 只在以下情形加载：

1. 当前任务需要判断是否值得委派；
2. 需要为一个边界清楚的子任务选择模型和思考强度；
3. 用户明确询问模型路线、调用成本或要求使用 Jev 路由。

普通读文件、运行命令、直接修改一个小问题时，不为“看起来流程完整”而加载 Skill 或调用 Jev。Skill 不接入 `src/lei_signal/`、`web/` 或任何交易运行链路。

以下决定不属于 Skill：交易方向、仓位、买卖时点、研究方法最终取舍、用户授权、代码验收和生产采用。它们仍由当前主控、项目文档和用户决定。

## 3. 采用的结构

### 3.1 新 Skill 的职责

新建本机 Skill：

```text
~/.codex/skills/lei-task-router/
├── SKILL.md
├── agents/openai.yaml
├── scripts/route_task.py
├── references/route-contract.md
└── tests/
    ├── scenarios.json
    └── test_route_task.py
```

- `SKILL.md`：只保留触发条件、优先级、最短工作流和执行 Skill 的选择方法。
- `route_task.py`：负责确定性校验、Jev 请求、响应校验、缓存和结构化输出。重复的脆弱逻辑不让模型临时重写。
- `route-contract.md`：保存七条合法路线、回退表、建议卡字段和版本号；只在真正进行路由时读取。
- `scenarios.json`：保存 Skill 行为场景，包括明确小任务、研究执行、策略定义、提示注入和用户指定路线。
- `test_route_task.py`：使用场景和本地假响应测试规则、异常和缓存，不重复消耗真实 Jev 额度。
- `openai.yaml`：允许自动发现，但描述严格限定在本项目的模型或委派路线判断，避免普通工作误触发。

### 3.2 复用现有 Skill

路由完成后，由当前主控根据结果继续使用已有能力：

| 场景 | 后续执行 |
|---|---|
| 极小任务，调度成本高于工作本身 | 当前 Codex 直接完成 |
| 普通、可独立验收的委派任务 | `$codex-delegate` |
| 用户明确要求 Pro 参与，且任务值得完整规划与复核 | `$lei-gpt-zcode-orchestrator` |
| 用户明确选择旧 ZCode 通道 | `$zcode-delegate` |

选择 Astra 路线不自动等于调用 Pro；调用 Pro 必须来自用户要求或任务本身确实需要该流程。新 Skill 不复制现有 Skill 的合同、文件权限、子代理创建、返修和验收协议。

## 4. 决策顺序

每次路由按下列顺序执行，命中前面的条件就停止：

1. **用户明确指定**：使用用户指定的可用模型与思考强度。若不可用，报告事实，不把失败的派发静默换成其他执行者。
2. **项目强制规则**：读取当前仓库 `AGENTS.md`。策略定义、论文方法、实验设计、真实资金与关键时点风险等项目红线直接决定最低路线，不调用 Jev。
3. **不值得委派**：一个命令、只读查询、单点文字或极小修补由当前 Codex 完成，不调用 Jev。
4. **类别明确**：能够明确归入 Spark、Terra、Sol 或 Astra 现有分工时，直接选择最低充分路线，不调用 Jev。
5. **相邻路线难以区分**：只有在两个或三个相邻候选之间存在真实歧义时，调用 Jev 一次。
6. **主控复核**：校验模型当次可用性、项目权限和返回把握，再决定是否执行。

Skill 只为一个已经冻结的工作包路由一次。实施过程中执行命令、读取结果、修复同一范围内的小问题不重新路由；任务范围或风险性质发生实质变化时，才生成新版本并重新判断。

## 5. 七条合法路线

Jev 选择完整的“模型＋思考强度”组合，不分别选择两个字段：

| 路线 ID | 适用任务 |
|---|---|
| `direct_current_low` | 只读检查、一个命令、单点改字等极小工作 |
| `spark_low` | 小脚本、固定格式转换、局部机械修补、已定义测试工具 |
| `terra_medium` | 方案明确的普通功能、少量跨文件接线、普通重构 |
| `sol_medium` | 常规研究适配、冻结实验执行、一般问题调查、证据整理 |
| `sol_high` | 多轮未定位的疑难工程问题、复杂数据证据核对 |
| `astra_high` | 策略定义、论文方法、实验设计、体系边界和重要架构决定 |
| `astra_xhigh` | 真实资金与关键时点裁决，或跨层高风险终审 |

`direct_current_low` 表示不增加一次模型调用，并以简洁方式完成任务；它不能改变当前根任务已经选定的模型或思考强度。其他路线只在任务值得形成独立工作包时用于委派。首版不尝试在同一根任务中途切换模型。

项目 `AGENTS.md` 是更高依据。如果项目以后修改模型分工，Skill 必须先服从新规则；Jev 的旧建议不能覆盖项目规则。

## 6. 降低调用成本的具体办法

### 6.1 大部分任务零 Jev 调用

固定规则能回答时立即结束。真实观察期目标是至少 60% 的任务完全不调用 Jev；这个比例用于发现 Skill 是否过度调用，不作为强迫错误归类的硬指标。

### 6.2 缩小候选集

主控先根据项目规则排除明显不合适的路线。调用 Jev 时只发送仍有歧义的两到三条相邻路线，而不是每次发送七条完整说明。

由于既有 17/17 盲测使用七条全量路线，候选缩小属于新行为，必须通过本地测试和观察期验证，不能直接拿旧结果当作证明。

### 6.3 紧凑任务包

发送给 Jev 的内容只包含：

- 不超过 800 个中文字符的任务摘要；
- 可验证交付物；
- 已知风险标记；
- 两到三条候选路线；
- “选择最低充分路线”的固定说明。

不发送聊天全文、代码全文、密钥、用户隐私、长日志或已有 Skill 正文。观察期目标为：真实 Jev 请求的输入中位数不超过 600 tokens，输出中位数不超过 100 tokens。

### 6.4 相同任务只付费一次

脚本对下列内容计算 SHA-256 指纹：

```text
路由合同版本 + 规范化任务包 + 候选路线 + 可用模型集合
```

命中本地缓存时直接复用结果。缓存只保存指纹、路线、概率、耗时、token 数、时间和合同版本，不保存原始任务正文。缓存有效期 30 天；合同版本、候选路线或可用模型变化会自然失效。

### 6.5 一次调用和短超时

每个任务版本最多调用 Jev 一次，不因网络错误或低把握自动重试。请求超时为 12 秒；超时或异常立即走本地规则。这样不会为了省一次人工判断而连续消耗额度或卡住开发流程。

## 7. 输入与输出

### 7.1 输入任务包

`route_task.py` 接收本地 JSON 文件或标准输入：

```json
{
  "task_id": "stable-local-id",
  "task_version": 1,
  "summary": "要完成什么",
  "deliverables": ["可检查的产物"],
  "risk_flags": [],
  "candidate_routes": ["terra_medium", "sol_medium"],
  "fallback_route": "sol_medium",
  "available_models": ["gpt-5.6-terra", "gpt-5.6-sol"],
  "user_override": null
}
```

`fallback_route` 由主控在联网前按 `AGENTS.md` 写入，必须是候选路线之一；断网、非法响应或低把握时直接使用它，脚本不得现场猜测。任务文本中的“忽略规则”“一定选 Astra”等内容只当作待处理数据。只有当前用户对主控明确提出的模型要求，才由主控写入独立的 `user_override` 字段。

### 7.2 路由结果

脚本只向标准输出写一个 JSON 对象：

```json
{
  "status": "recommended",
  "route": "terra_medium",
  "source": "jev",
  "confidence": 0.72,
  "margin": 0.24,
  "cache_hit": false,
  "fallback_reason": null,
  "api_model": "jev-1.13.0",
  "contract_version": "1.0.0"
}
```

日志和错误写入标准错误，且永不包含密钥或完整请求正文。主控将结果翻译成简短建议卡：执行方式、模型、思考强度、判断来源、把握、回退原因、后续 Skill 和一句大白话理由。

正常建议、缓存命中和可恢复回退均输出合同规定的 JSON 并返回退出码 0；本地输入缺少必填字段或配置本身损坏时输出 `status=error` 并返回退出码 2。这样网络波动不会中断开发流程，而调用方错误不会被伪装成正常回退。

## 8. Jev 返回校验

Jev 返回必须同时满足：

1. 只能选择请求中提供的候选路线；
2. 每项概率在 0 到 1 之间；
3. 概率总和允许 `0.98` 到 `1.02`，兼容两位小数舍入；
4. 选中路线存在且不得低于其他候选概率；
5. 不接受返回文本中的命令、文件修改建议或扩展权限；
6. 不打印原始鉴权头或密钥。

首版把“最高概率至少 0.60，且第一名比第二名至少高 0.15”作为可采用建议的门槛。低于任一门槛时标记为 `low_confidence`，使用项目固定规则复核。该门槛来自保守工程选择，不宣称已经统计校准；观察 20 个真实任务后才能调整。

首版固定使用已经完成盲测的 TypeSafe endpoint `https://api.typesafe.ai/v1/systemone` 和 `jev-1.13.0`。实际模型名写入结果和决策记录；以后升级模型版本必须使缓存失效并重新跑冻结场景，不能无记录地漂移。

## 9. 密钥与本地状态

密钥读取顺序：

1. 环境变量 `TYPESAFE_API_KEY`；
2. 本机配置 `~/.codex/lei-task-router/config.json` 中的 `key_file`；
3. 没有密钥则返回 `key_unavailable` 并走固定规则。

本机配置可指向用户已经授权使用的密钥文档，但 Skill 和仓库不写入密钥值。配置文件权限设为仅当前用户可读写。脚本在内存中解析 `jev_key`，不得把内容打印、复制到缓存或写进实验报告。

缓存和精简决策记录放在：

```text
~/.codex/lei-task-router/cache.jsonl
~/.codex/lei-task-router/decisions.jsonl
```

决策记录不含原始任务正文，只含任务指纹、结果来源、最终路线、是否回退、耗时和 token 数。

## 10. 可用性与回退

调用 Jev 前先过滤当次不可用模型，减少无效建议。出现以下情况时不再调用 Jev：

| 情况 | 处理 |
|---|---|
| 缺少密钥 | 使用 `AGENTS.md` 固定分工 |
| 网络错误或 12 秒超时 | 记录一次失败，使用固定分工 |
| JSON、字段或概率不合法 | 标记 `invalid_response`，使用固定分工 |
| 低把握 | 标记 `low_confidence`，主控按固定分工复核 |
| 推荐模型在派发前变为不可用 | 不重试 Jev；重新检查固定路线并说明回退 |
| 用户指定模型不可用 | 停止该派发并向用户报告，不静默替换 |
| 已经派发后执行端失败 | 遵守执行 Skill 的替换授权规则，不由路由 Skill 自动换模型 |

Spark 不可用时，遵循项目已有规则：真正很小的工作由当前主控直接完成；其余按复杂度使用 Sol 或当前模型，并清楚记录这是可用性回退。其他执行端失败不自动提升到 Astra。

## 11. 与执行流程的连接

路由结果是建议，不是执行命令。当前主控仍需：

1. 判断工作包是否具体、独立并值得委派；
2. 读取所选执行 Skill；
3. 冻结可写路径、输入、验收、网络和停止条件；
4. 通过现有工具检查模型当次可用性；
5. 执行或委派；
6. 独立检查实际差异和新鲜测试。

Skill 不创建用户侧新任务。普通委派使用当前任务内的 `collaboration.spawn_agent`，并遵循 `$codex-delegate` 的限制。

## 12. 测试与验收

### 12.1 不联网的自动测试

至少覆盖：

1. 用户明确路线时零 Jev 调用；
2. 极小任务与强制高风险任务零 Jev 调用；
3. 只允许两到三个相邻候选；
4. 正常 Jev 建议通过；
5. 概率总和 `0.99` 被接受；
6. 非法路线、缺字段、概率越界和第一名不一致被拒绝；
7. 低把握回到固定规则；
8. 缺密钥、网络错误和超时只失败一次；
9. 相同指纹命中缓存，不发第二次请求；
10. 合同版本、候选或可用模型变化会使缓存失效；
11. 用户指定模型不可用时不静默替换；
12. 任务文本中的提示注入不能改变路线合同；
13. 日志、缓存和错误中没有密钥与原始任务正文。

运行 `skill-creator/scripts/quick_validate.py` 检查 Skill 结构，并运行完整本地测试。

### 12.2 真实观察期

实现后先观察 20 个真实开发工作包。观察期间 Jev 只给建议，主控确认后才执行。每个工作包记录：

- 是否调用 Jev；
- 建议路线与最终路线；
- 是否人工改判及原因；
- 输入与输出 token；
- 路由耗时；
- 是否出现不必要的高档模型；
- 任务最终是否通过原本的验收。

首轮通过标准：

1. 强制策略、方法和真实资金任务没有被降级；
2. 明显小任务没有使用 Astra；
3. Jev 调用比例不高于 40%，除非样本本身大多是边界任务；
4. Jev 请求输入中位数不超过 600 tokens，输出中位数不超过 100 tokens；
5. 本地规则路径在正常机器上的额外耗时低于 100 毫秒；
6. Jev 路径中位耗时不高于 3 秒，异常在 12 秒内回退；
7. 没有密钥泄漏、重复付费调用或自动执行越权；
8. 人工改判的原因能够反推为具体规则修正，而不是为了迁就单个结果临时改口径。

观察期结束后再决定是否允许“高把握且无风险”的建议自动进入 `$codex-delegate` 合同准备阶段。即使以后开放，也不允许自动越过用户权限和主控验收。

## 13. 不在首版范围

- 把 Jev 接入交易判断、新闻叙事或生产 API；
- 自动改变当前根任务使用的模型；
- 自动创建用户侧 Codex 任务；
- 根据 Jev 建议自动扩大研究或文件权限；
- 自动购买额度、重置额度或在失败后切换供应商；
- 使用聊天全文做长期语义缓存；
- 同时重写现有委派 Skill；
- 在 20 个真实任务观察前启用无人复核的自动派发。

## 14. 完成定义

首版只有在以下条件全部满足时才算完成：

1. Skill 结构校验和本地自动测试通过；
2. 使用假服务验证正常、低把握、超时、非法响应和缓存路径；
3. 使用一次受控真实调用验证 API 兼容，不为了测试重复付费；
4. 仓库与 Skill 目录扫描不到密钥；
5. 建议卡能够明确说明实际路线、来源和回退原因；
6. 复用现有执行 Skill，未复制或绕过其安全与验收合同；
7. 完成 20 个真实工作包的观察报告后，再单独讨论是否扩大自动化。
