# LEI 技术体系权威文档索引与 Web 阅读页设计

日期：2026-09-29  
状态：设计已获用户确认，等待用户复核本文后实施

## 1. 目标

项目以后以桌面目录中的两份文档为当前权威来源：

- `~/Desktop/lei signal doc/LEI 技术交易体系.md`
- `~/Desktop/lei signal doc/LEI 技术实现.md`

项目不复制正文，也不在仓库内维护第二份可能漂移的版本。仓库负责三件事：记录权威来源及已确认指纹、让项目规范和研究任务正确指向它们、在 Web 中提供按章节阅读的专属页面。

## 2. 文档职责与优先级

两份文档的职责必须分开：

1. **《LEI 技术交易体系》**回答“这套策略如何理解市场、观察道路与路牌、寻找触发并执行交易”，是技术思想和交易语义的最高来源。
2. **《LEI 技术实现》**回答“如何把上述判断变成可计算、可回测、可输出的规则”，是当前实现和实验定义的直接依据。
3. `configs/rules.v1.yaml` 等规则账本继续保存具体阈值、版本和来源。规则账本不得反过来改写技术体系含义。
4. `docs/trading-spec-v1.md` 保留为历史 V1 快照，供旧实验复现和审计，不再作为新任务的最高来源。

出现冲突时，先确认冲突属于策略语义、实现形式还是阈值版本，再按以上职责处理。不能静默选择更适合回测的一版。

## 3. 变更权限

两份桌面文档均为只读权威源。项目代码、自动化任务和 agent 不得直接新增、删除或改写其中内容。

以下变化都必须先向用户确认：

- 新增或删除策略章节、交易模块、过滤条件、状态、输入变量；
- 改变道路、路牌、触发、失效、退出或风险纪律的含义；
- 把宽度、机构情绪、散户情绪或 A 股情绪正式纳入技术交易体系；
- 让原本只作解释或预警的信息参与技术判定；
- 改变两份文档的职责、优先级或权威路径。

确认前必须先说明：改动内容、影响的策略层、会新增或删除哪些因子研究对象、既有实验是否仍可比较。用户确认后，才可修改原文或更新“已确认指纹”。

## 4. 项目索引与变更识别

新增 `configs/strategy-documents.v1.json`，只登记两个固定文档，不接受接口参数传入任意路径。每项至少包含：

- 稳定 ID；
- 展示名称；
- 使用 `~` 表示用户目录的权威路径；
- 文档职责；
- 当前已获确认的 SHA-256；
- 确认日期；
- 在 Web 中的展示顺序。

初始已确认指纹：

- 《LEI 技术交易体系》：`df92d85b3b04ed3ab71d56bc108d0effe8eb31051b7a1531eda59edcbf0aab20`
- 《LEI 技术实现》：`85e0e3270ff96fe85247756805c58c650a0e83b21ea15c9feccea84d31aaf903`

读取时重新计算指纹。若源文件不存在，页面明确显示缺失路径；若当前指纹与已确认指纹不同，页面仍可只读展示，但必须显示“源文件已变化，尚未确认”，项目规范同时要求研究任务不得据此扩大或缩小因子范围。

## 5. 项目指针更新范围

更新当前仍会指导新工作的权威入口，包括：

- 根目录 `AGENTS.md` 的“第零步”；
- `docs/README.md` 和当前系统架构说明；
- 当前研究原则、定义规范和因子准入入口中对“最高来源”的说明；
- Web 设计说明中对策略溯源的说明。

历史实验、冻结协议、历史计划、原始结果和已钉住 V1 指纹的定义记录不批量改写。这些材料描述的是当时实际使用的输入，保留旧路径才能复现。新研究必须记录两份桌面文档的实际指纹；若仍需与 V1 比较，要明确标注“历史对照”。

## 6. 后端读取接口

新增独立的只读策略文档模块和 API 路由。模块负责：

- 加载固定索引；
- 展开 `~` 并校验解析后的路径仍位于配置的目录；
- 读取 UTF-8 Markdown；
- 计算当前指纹和确认状态；
- 从 Markdown 标题提取一级到三级章节，生成稳定锚点；
- 返回文档角色、章节目录、正文、路径、确认状态和更新时间。

接口只提供“列出两份文档”和“按固定 ID 读取一份文档”。未知 ID 返回 404；缺失、无法读取或编码异常返回清楚的中文错误，不回退到旧 V1 正文，也不暴露目录中的其他文件。

## 7. Web 专属页面

新增 `/strategy`，导航名称为“技术体系”。页面是一份交易手册式阅读器，延续现有 Web 的深色信息界面，但减少仪表盘卡片感。

桌面布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 技术体系  [交易体系] [实现规范]  来源状态 / 更新时间         │
├──────────────┬───────────────────────────────────────────────┤
│ 章节目录      │ 文档角色说明                                  │
│ 当前章高亮    │                                               │
│ 二三级标题    │ Markdown 正文，标题带可复制深链接              │
│              │                                               │
├──────────────┴───────────────────────────────────────────────┤
│ 研究扩展：宽度｜机构情绪｜散户情绪｜A 股情绪                 │
└──────────────────────────────────────────────────────────────┘
```

交互要求：

- 两份文档用清楚的中文标签切换，URL 保留文档 ID 和章节锚点，刷新后位置不丢失；
- 左侧目录随阅读位置高亮，可点击跳转；
- 正文支持标题、列表、表格、代码块、引用和原文链接；
- 窄屏时文档切换保留在顶部，章节目录折叠为可展开列表；
- 键盘焦点清楚，遵守减少动态效果设置；
- 页面不计算交易信号，也不修改文档。

视觉上以“可查阅、可定位、可追溯”为主要特征：正文行宽受控，章节层级靠缩进、字号和分隔线表达；醒目元素只用于“未确认变更”状态，避免把正文切成大量同形卡片。

## 8. 研究扩展区

页面底部提供四个研究方向入口：宽度、机构情绪、散户情绪、A 股情绪。每项只显示：

- 大白话定义；
- 当前属于“原文已有”“实现已有”或“体系外研究扩展”的哪一类；
- 对应研究页或报告入口；
- 当前状态，例如待定义、研究中、已有阶段证据。

这一块只做范围导航。未经用户确认，体系外候选不得出现在正文目录中，也不得标成 LEI 原始规则、硬过滤或已可用于交易。

## 9. 安全与失败处理

- 路径来自版本管理的固定索引，API 不接受用户提供文件路径。
- Markdown 来源是本机受控文档；渲染前仍禁用或清理危险 HTML，避免脚本执行。
- 文件缺失时显示具体路径和恢复办法，不静默展示旧文档。
- 指纹变化时不自动更新确认值，不自动扩大因子研究范围。
- 本任务不修改 Streamlit 目录，不改变 Python 判定规则、回测参数或生产交易逻辑。

## 10. 验收标准

1. 项目当前权威入口不再把 `docs/trading-spec-v1.md` 称为新任务的最高来源。
2. 两份桌面文档可在 `/strategy` 完整阅读并按章节导航。
3. Web 显示每份文档的职责、真实路径、当前指纹和确认状态。
4. 文件缺失、未知 ID、指纹变化都有明确行为和测试。
5. 任意路径不能通过 API 读取。
6. 宽度和各类情绪因子被列为独立研究扩展，未混入 LEI 原文。
7. 不修改两份桌面文档，也不批量重写历史研究材料。
8. 后端相关测试、前端构建、仓库目录检查通过，并完成桌面与窄屏页面检查。

## 11. 本次范围之外

- 不在本次任务中新增、删除或改写任何技术交易规则；
- 不因建立页面而启动新的因子回测；
- 不重新解释或重算历史实验；
- 不把研究扩展自动升级为正式策略；
- 不建设在线文档编辑器。
