## 3. 本期固定设计

### A. 第一屏直接帮助理解

回答优先呈现下面四件事，短问题可以自然段表达，不强迫所有聊天套四张卡：

1. **现在怎么看**：标的名称/代码、所依据的数据日期、现有系统状态；交代针对哪类问题或交易方法。
2. **机会与风险**：已有事实支持什么、冲突在哪里。没有可核实机会就如实说；不为了填满版式臆造利好。
3. **历史依据够不够**：本次适用、仅可参考或暂时没有，中文说明关键原因；现成统计保持原数值和原范围。
4. **接下来可以做什么**：来自现有条件的观察项，或清楚的补资料/选方法步骤。没有明确触发价时不造数字。

首屏目标约 150—300 中文字，作为设计目标而非截断规则；不得为了字数切掉影响结论的限制。事实日期、没有可用统计、模型暂不可用等影响理解的信息必须可见。

资料路径、规则/运行编号、`exact/unknown`、方法代码及详细统计移入“查看依据详情”；首屏用“适用于这次问题”“暂不能确定是否适用”等映射。`R` 首次解释为“相当于每笔预定风险金额的多少倍”；不要把它显示成收益率。

正文和依据卡减少机械重复：正文解释意义，卡片负责来源和明细。不能靠隐藏整张依据卡或删除原文实现简洁。用户原话、原有历史内容不批量改写。

模型不可用时，现有 Python 事实经过同一套中文展示转换，仍能读懂；不得只修改模型提示词。没有值就说明缺少什么，不用通用行情段落填充。

### B. 下一步动作贴合问题

每次最多 3 个动作，优先复用已有能力，例如“看看还需满足什么条件”“查看历史依据”“准备补测”“讨论进出计划”。

- 展开依据直接展开本回答；讨论类动作把完整中文问题放入输入框，用户可改后发送；不自动发一串请求。
- 带上当前回答实际绑定的标的与原问题身份。切换标的后不得让旧按钮偷偷按新标的执行；应保留原对象并明确提示。
- “准备补测”打开本期中文选择面板；“讨论进出计划”只进入讨论，不直接确认计划或记录成交。
- 没有实现的能力不要做看似可用的按钮。“比较 ATR 止损”若引擎没有对应现成选项，应明确“这项比较暂未支持”，保留继续讨论入口；不以普通结构止损替代 ATR。
- 复用原有发送防重复、请求标识和任务状态处理，不重写第二套发送流程。

### C. 补测使用中文选项

不再要求用户手敲“模块 A”“退出 1”或运行编号。把现有引擎支持的方法用中文选项和一句解释展示：例如“上升趋势中的回调”“整理后突破”“跌破后重新收回”等，准确映射既有 A/B/C/D；退出名称同样映射现有合法选项。

- 选项来源复用现有能力接口；静态中文词典可维护显示名，但不能凭词典创造引擎能力或决定参数。
- 明确选择才能提交；现有默认值若需要保留，必须可见，并允许修改，不静默替用户选择最优打法。
- 有歧义只问完成本次任务必要的一项，不让用户填完整研究问卷。
- 提交前展示对象、测试方法、退出方式，以及已有选定窗口；未指定窗口沿用原协议，不在本轮发明新窗口选择。
- 本期只支持一次既有单方法任务，不做批量自动研究或自动选优。
- 完成、无可统计交易、失败都用中文说明与可行下一步；详细运行编号放详情。复用现有任务查询，不把停止接收解释成停止后台计算。

### D. 两入口与历史统一

研究工作台与标的页控制台共用回答展示、术语映射和下一步动作，不各写一套。保留现有图表联动和服务端计划卡的权威关系。

历史页面明确区分“当时的回答/数据日期”和“图表当前数据”。修正与现有能力不符的恢复提示。历史缺字段允许朴素展示，不填造当时摘要，不拿当前事实补写旧结论。

本期只让用户容易接着讨论，不新增长期会话状态机、跨会话个人记忆、自动盯梢或独立决策台账。

## 4. 给因子库留什么位置

因子是对市场某种特征的量化描述，例如趋势方向或波动大小。它将来可作为回答的依据，但“有数值”“研究中有效”“获准参与交易规则”不是同一个状态。

本轮只保证回答组件不过度绑定 A/B/C/D 专有排版，能容纳现有来源说明；在交付文档写明未来输入至少需要：标的、因子身份及版本、观察日期、中文含义、证据引用、研究/采用状态、允许用途。**这些只是后续接入建议，不是本轮新公共接口。**

不新增空白因子面板、模拟因子成绩、综合分、概率模型、权重或自动仓位。基本面/消息面叙事边界不变。因子服务不存在不阻塞本轮体验。

## 5. 一次定清的验收场景

先把以下场景做成固定输入，再实施；模拟数据要标清，不能用演示文案冒充真实行情。测试真实组件与点击后的请求，不只测字符串工具。

| 场景 | 用户应该获得的体验与可核事实 |
|---|---|
| 1. 单 ETF，事实足够，模型正常 | 首屏有清楚观点、机会/风险和下一步；详情保留对应原始依据，中文名称不改变数值 |
| 2. 同一问题，模型不可用 | 仍有可读事实与下一步；明确解释暂不可用，没有内部代码清单代替解释 |
| 3. 历史依据不可适用或无统计 | 首屏说明限制；不显示虚构胜率；能打开原始来源 |
| 4. “没测过就补测”且未选方法 | 中文选项帮助完成选择；提交只产生一个既有任务，参数与界面一致 |
| 5. “换 ATR 止损试试”但当前不支持 | 如实说明不支持，不偷偷改成另一个退出规则或声称已比较 |
| 6. 点击继续讨论后切换标的 | 草稿和发送对象清楚；不串旧问题与新标的；连续点击不重复提交 |
| 7. 任务完成/无交易/失败 | 三种状态解释不同；都有实际可用下一步，不把失败写成没有机会 |
| 8. 形成计划、重新打开历史 | 沿用既有确认步骤；历史计划身份及当时日期保留，查看历史不写入成交 |

两个入口都覆盖 1—6；工作台覆盖 7—8，控制台核对相同共享逻辑。至少留宽屏和窄屏截图，检查溢出、卡片展开、输入与图表联动。运行相关前端测试、类型检查与构建；若改后端解释代码，运行相关普通/流式回归及受影响的计划、补测测试。测试内容跟实际变化对应，不再无差别重跑全部旧审计脚本。

本轮用固定模型输出与不可用替身验证界面；如未经过真实模型，不得宣称“真实模型回答质量已通过”。另交 3 条建议主控后续亲测的问题及预期体验，不能先收费代跑。

新增影响已有判断/确认边界的错误仍需报告并停止相关分支，但不要由一个展示任务扩大为全部真实性审计。新的产品偏好记下一期，不不断追加为本期必修。
