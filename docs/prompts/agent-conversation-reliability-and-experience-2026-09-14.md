## 4. 最小架构安排

沿用现有会话、问题身份、冻结依据、流式/普通讨论接口以及两入口共用组件。

1. **资料准备与模型解释分开。** 系统事实准备好即可展示，不等模型完成；明确“系统资料已就绪，AI解释仍在生成”。资料尚未取得时只报真实状态，不预填判断。
2. **同一问题使用同一份依据。** 后补的解释绑定原问题和对象；切会话或切标的后，迟到内容不插入新页面。不能为分阶段展示重复创建问题、重复计展示成绩或丢失最终历史。
3. **正常和失败都能继续。** 模型超时后保留已取得事实，明确哪些解释未完成；重试复用原问题，不重复落业务记录。数据库准备失败时不能冒充已读到事实。
4. **不另造判定器。** 只重组现有事实和解释，前端不算信号，不用自然语言模型推算新胜率，不修改数值接地容差算法。

先复用现有事件和响应字段；确有缺口才做最小兼容扩展。不要新建通用调度平台、向量库、第二套证据登记、空因子接口或占位面板。

## 5. 回答内容的固定要求

- 先回答这次问题。状态对应“是否足以继续讨论入场、先观察什么”，随后解释阶段、路牌、触发条件和风险；颜色和内部编号放详情。
- 数据日期不只是角标。已有状态明确为过期/无法核实新鲜度时，用同样强度的中文说明；不得自行凭相隔天数新造新鲜度规则。
- 依据分清“支持什么”和“暂不能说明什么”。没有匹配统计就不给本次胜率；不能拿空测试库推断真实系统没有回测。
- 下一步最多三项，并且贴合问题。“只想观察”就说可观察的既有条件；不用每次都要求选择 A/B/C/D 或补测。
- 问资金、入场和退出时，先明确已有和缺失条件。只讨论不等于保存计划，更不等于报成交。缺完整依据可以解释尚不能定案，不能填造价格/仓位。
- 首层用人话，详细规则与来源仍可查。无详情可展开时不要给无反应按钮。

不要求每次机械重复四段模板，不用增加文字长度冒充分析深入。

## 6. 固定验收，完成后不自行扩题

先存原始输入、基线现象和验收表，再实施。

| 编号 | 必须验证的内容 |
|---|---|
| A | 两类首问失败分别有证据、明确归属；产品缺陷与脚手架问题分开。不能复现/外部不可用如实保留未完成 |
| B | 可控模型延迟/超时下，真实前端先显示已准备事实，失败后保留；记录准备、首次有用内容、模型完成/失败三段时间，不拿加载动画算回答 |
| C | 同一个真实模型四轮案例，逐轮保留问题、回答原文、依据身份、耗时和人工评价；固定文本桩仅验证交互，不算回答质量 |
| D | 工作台和标的控制台均实际打开并验证分阶段展示；切会话迟到响应不串入，刷新能恢复原问题最终状态，不重复记录 |
| E | 同样事实的改前/改后表达对照：能否直接回答、机会风险是否解释、依据边界是否清楚、下一步是否贴题。失败和不确定都入报告 |

真实模型案例优先沿用510300，连续问：

1. “510300 最近怎么看？先说判断，再讲机会和风险，现有依据够不够？”
2. “这个判断哪些有历史依据，哪些只是当前观察？现在能不能给胜率？”
3. “我先不买，只观察。接下来具体看哪些变化，什么情况再来讨论？”
4. “假如后来满足入场条件，进入、失效和退出该怎样讨论？现在还缺哪些信息？先别替我保存计划。”

只读使用已有资料；旧资料明确日期。隔离库若需要已有研究记录，可最小只读导入可核实材料，记录来源；不导入真实交易记录。没有就说明该案例不能评价“有匹配证据”的分支，不能伪造正例。

真实模型最多四轮加一次失败重试，共5次请求。首轮持续不可用则停止真实生成分支，完成独立的交互验证并提交阻点，不换假模型宣称通过。无需联网补行情、启动收益回测或真实保存计划。

测试按修改范围：相关后端测试、前端回归/类型/构建；有改动或新失败才重复。已有计划确认、记录生命周期全套不重审，不再跑无关全仓回归。预览结束停掉自己的进程。

## 7. 因子库的衔接：本期只写交接，不实施

因子是用于描述或检验市场特征的计算结果，不同类型用途不同，不能全部换算成一个总分。

等第一批实际交付满足下面条件即可讨论接入，不用等整库“全部建完”：

- 定义和版本可追溯，真实输出或可调用入口已核验；不能拿任务书里的示例当实现。
- 对象、日期、当时是否可知、缺失状态与来源能说明清楚。
- 研究结果明确适用标的/环境/观察期限、失败与限制；计算正确不等于有预测作用。
- 明确允许的用途：研究材料展示、辅助解释，还是申请改变技术判断；后者需主控单独裁定。

本期只在报告给出“现有讨论上下文何处适合读入已验收材料”的代码位置和缺项清单。不冻结第二套因子字段、不接研究包、不改因子负责人代码、不自动合成胜率、排序或仓位。

未来第一步优先让 Agent 准确回答“这个因子是什么、对本标的有什么证据、不能说明什么”。有增量效果证据后再讨论采用。基本面/消息面仍只解释原因，不变成技术硬过滤。
