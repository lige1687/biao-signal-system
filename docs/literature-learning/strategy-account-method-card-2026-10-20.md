## 比较怎么做，怎么避免重复劳动

1. 先复用已经有的两种退出、局部动作比较与完整单项账户。只有定义、用途或资料出现实质新问题，才进入原负责人合同和剩余预算。
2. 同一用途固定一个主要变化，其他入场、数量、成本和日历先相同。需要研究两条件配合时，可预先声明四种组合；不能因为建议列了四格就重开旧绿色/黑色研究。
3. 同起点的动作比较解释“提前卖少亏还是少赚”；允许现金与后来交易变化的连续账户回答“整套办法是否值得”。两类差额不相加，单笔价格差也不直接当账户贡献。
4. 对照保留适配的简单持有、原策略，以及预先固定的较低投入方案。降低回撤伴随大量留现金时，先看更简单的少投入能否接近；用完整测试期反推的“刚好同风险”只能作事后诊断。
5. 主指标按用途绑定，代价同时列：收益、亏损幅度、回本等待、相对落后、现金与集中、费用和漏掉的大行情。已有“大赢家贡献”检查继续使用，不机械删除最好几笔重新定义正式成绩。

决策差异沿已有订单/候选输出保留：`decision_time`、`information_available_at`、`product`、`baseline_action`、`candidate_action`、`reason`、`available_cash_before`、`order_time`、`fill_time`、`cash_usable_at`、`status`、`source_event_id`。这是建议采用的字段映射，**当前没有通用自动导出器**；不能把本段当作API字段已上线。

## 已补入的账户路径工具

`src/lei_signal/research/account_path_diagnostics.py::compare_nav_paths`是无行情访问、无下单、无文件写入的纯计算函数。输入两组完全相同日期的正净值，并明确声明已排除入金影响。它不处理原始现金流，不替代原账户引擎或资格审查。

净值是把新增投入与投资盈亏分开后的增长刻度。直接拿“总财富”计算，会把入金误认成回本；调用者须核原日账的份额与净值关系。两条净值各从共同起点归一到1，再计算候选净值÷基准净值。

工具分别输出：

- **账户回本等待**：从最近一次同高或更高的位置，跌下去到回到该位置的时间。相等算回本；一直持平不叫亏损。
- **从共同起点持续落后**：上述比值低于1的连续区间。它不等于每一天都跌，也不等于从首次落后后永不再追上。
- **相对过去最好位置的回落**：上述比值低于自身历史最高值的区间。即使候选仍累计领先，也可能发生；不得和上一项混称。

每项分开列“最长已结束区间”和“期末仍未结束区间”，标起止日、自然日跨度、低于参照的观察数及最深幅度。自然日包含周末；本次旧日账在周末及休市日沿用原估值，不表示每天有新报价或可以成交。只按交易日提供资料时须声明`observed_dates`，不能冒称完整自然日观察。固定`1e-12`只处理数值舍入。观察日期、起点和结束点决定这些描述，工具不证明稳定改善或未来等待多久。

示例属于调用方式，不是策略参数：

```python
from lei_signal.research.account_path_diagnostics import compare_nav_paths

result = compare_nav_paths(
    baseline_rows, candidate_rows,
    cashflow_adjusted=True, calendar="calendar_day",
)
# rows: [{"date": "2026-01-01", "nav": 1.0}, ...]
```
