# 怎么判断修复真的有效

日期：2026-09-08。

文献索引：`sullivan1999`，归在“实验方法”。这里沿用已读论文的比较思想，不新增全文阅读记录。以下具体规则来自本系统时间要求与工程验收，作者没有给出我们的测试门槛。

**修复的验收至少有两层：发现过的问题要消失，原本正确的行为要留下。** 例如修复历史确认会消失的问题，不能通过删掉所有确认来“通过”；还需检查原来确实应该出现的两条确认仍出现，未来加入后完整内容相同。结构以后真的失效，也必须照常记录，不能把保留历史误做成旧结构永远有效。

**同版本的时间一致性与跨版本纠错差异要分开。** 同一版本增加未来行情，过去已发布字段不能改变；修复版本相较旧版可以纠错，但应公开差异。例如一只基金底部实际12月30日已确认，旧程序31日把日期挪后；新版本引用30日是纠错，不应为追求和旧版一模一样而保留错误。

**不要用减少的信号数宣称提高质量。** 本地C确认从881条变384条，其中有沿用过时参照的旧流程被限制；这些记录没有全部成为交易，同一市场动作也可能有多条记录。最终意义需同资金、费用、执行与风险约束的完整比较。

**测试若与批准的新接口矛盾，应公开改了哪一项。** 本轮缺输入从空列表改为明确异常，原失败日志保留，研究复制测试改成检查报错，生产调用方仍需适配。这与偷偷删除失败测试不同，是否合理要回到事先约定的要求判断。
