# 提交交易想法后，系统怎样完成一轮研究

新研究已经接在现有 `scripts/run_factor_lab.py` 的两个新分支。先检查、演练和冻结，
再计算，最后核对生成的表并登记；旧实验继续按自己的冻结版本运行。
当前规范路径和版本只有一个导航来源：[current-standards.json](current-standards.json)。

你只需要提出交易判断，比如“回调时保持均线上行，是否少一些未来下跌”。主控把它
变成可以计算的定义，确定对象、期限、已有信息、反例、允许的尝试和资料范围。
对象是否对应用途、这个代理是否忠实、方法是否合适、最后结论能说多大，由主控
留下理由；程序不把理由当作“已验证”。技术体系的新增、删除和含义调整仍需你确认。

程序先查看实际文件，保留每个缺口的原因。正常停牌、漏报、尚未上市、行动尺度不明
和未来结果未成熟分别处理；不拿假报价补洞。固定期限的首尾变化、途中最低收盘或
最低价、峰谷回撤、可操作开盘需要不同证据。相邻日期及同日资产一起处理，不能把
重复观察当作很多互相独立的验证。检查前的资料只用于资格，导出的冻结检查不显示
未来结果数字；看过的结果不会因为更换AI、文件名或家族名成为新验证。

接着用人工生成的小样例演练完整流程，冻结本轮数据、相关定义、代码、目标、
频率、权重和有限方法。正式计算前会再次检查。错误的时点、未披露的缩池、没有
反例、旧凭据、超预算或越界用途会停在相应位置。合理的部分覆盖可以完成，但
报告会明确实际比较对象，不能说成全范围已经验证。

结果表由程序生成：简单历史参照、已有信息、加入候选后的误差并列；展示差值、
单位、允许的改善与恶化范围、机会数量及未覆盖部分。预测更准不直接等于投资
收益，途中最有利价格也不等于已经兑现。方法较差、没有新增帮助或证据不足都可以
正常结案；不会自动换参数直到找到正结果。结论的科学解释由主控看完表后确认。

以后换一个技术想法，作者只补特征/事件适配器和研究卡；时点、标签、配对、基准、
统计范围、报告与验收复用。尚未支持的适配器会直接拒绝，不把名称写上就算实现。
目前内置的是演示用SMA相对距离、前一真实报价下跌事件，以及连续预测/二元风险
频率评价器；它们不等价于A01双均线带的完整注册定义。真实A01等作者须先接准确
特征适配器，不能拿这里的演示代理替换原定义。
当前特征用日线真实报价计算，`bar_frequency=daily_quote`与每周/每月取一次观察分开；
按周取观察不等于用周线计算均线。真实资料中的周期完成标记还须符合来源日历。

## 2026-10-03：原策略语义与多种有效性验证（新任务显式采用）

用户已认可的目标是：把原始LEI交易判断拆成有金融含义的可计算对象，发掘有依据的候选，检验它们相对已有信息是否提供稳定帮助。最终交付包含定义、效果、增量、反例和适用边界；因子数量和程序通过数量不作为业务验收。规范索引、原登记、旧冻结合同与权限保持，本节是主控和执行agent的操作说明，**未新增自动验收器或软件能力**。

### 一轮研究的实际顺序

1. **核分工与旧证据。** 先读取最新coordination/lei及相关任务，再查对象ID、同公式别名、用途、家族尝试与数据接触史。读过的资料和旧负结果保留，未登记活动不视为空闲。新问题的范围成功同步后再修改可能冲突的文件。
2. **逐项保留原文条件。** 绑定桌面两文档实际SHA与章节，记录原判断、机制假设、排列/阶段前提、信号、失效、频率与行动条件。将“原义的准确实现”“原义的局部研究代理”“文献启发的新假设”分别标明。遗漏条件写明影响；原文变更仍需用户确认。均线不等于投资者真实持仓成本，合理解释不等于机制已证实。
3. **固定一个有用途的定义。** 明确公式、参数、单位、严格/非严格比较、缺失/预热、价格尺度与当时可知时间；手算正例、反例和边界。状态、数值、变化事件与条件组合是不同对象，不把当天绿黑、首次变色、持续天数混为同一信号。新参数是研究选择，不能冒充原作者唯一口径。
4. **针对缺口学习方法。** 先复用文献库paper_id与实际已读章节，再补作者/期刊/机构原文或官方工具文档。方法卡写原市场、资料、成本、验证及反证，本地可用/不可用部分。摘要不能算全文；工具安装不等于验证完成；已有外部方法负责人范围需避让。
5. **结果前固定有限验证组合。** 在既有合同里指定主要用途、目标、简单对手、已有信息、候选、完整对象日期、有限辅助检查、预算与停止条件。保留常数/每资产成熟历史平均等合理简单参照；旧模型若输简单对手必须披露。因子单独、已有信息、两者合用在适用时比较，未运行项明说；不能只凭复杂模型中的一项改善授予有效标签。
6. **先资料资格，再执行。** 沿本页workflow草案→合成演练→冻结→真实执行路径。资料时点、行动、缺失、成熟、共同支持不足时降低结论范围或阻塞对应部分，不用缩池/删差年份解决。看新结果后增补的方法标探索，并计入原家族。
7. **核数与裁决。** 从保存结果独立核关键原值、差值、数量和单位，检查不确定性、反例与简单对手。允许用途限定的负结果或证据不足。只有证据支持，才将候选建议进入另行定义的策略研究；统计关系不直接等于资金或线上收益。
8. **归档供下一agent接续。** 使用原报告模板、registry、家族ledger及manifest；报告附验证覆盖表，每项关联实际路径/版本，标已执行、复用、未执行、不适用或资料边界。更新自己的阶段和协调记录，保留失败预算和重开条件。

### 方法怎样按问题选择

| 对象/用途 | 优先证据 | 不能强套的做法 |
|---|---|---|
| 绿/黑/灰等分类状态 | 各状态收益与风险分布、单线/分歧、条件支持、相对已有信息的比较 | 任意把颜色编码成大小，再切前10%/20% |
| 距离、斜率、持续比例等数值 | 预定分组、曲线形状、排名关系、简单及条件对照 | 默认越大越好；只交表现最好的阈值 |
| 同一日多资产排名 | 同日排名与随后表现的关系、分组差额、并列处理 | 四ETF硬分十组，或将跨日期排名当同日选优 |
| 同一资产不同日期 | 历史水平分组、只用过去设边界、连续日期关联及时期检查 | 将每日相邻观察当独立事件；从未来全集反推分位边界 |
| 变色/突破等事件 | 信号当时可知、事件数量/重叠、对照日期、收益与风险路径 | 用后续走势确认当时信号，或擅改趋势身份重置 |
| 风险用途 | 大跌比例、途中下探、风险预测质量及同时少赚/错过多少 | 只看平均收益，或将途中跌幅等同账户回撤 |
| 条件组合 | 各组成部分、组合与共同可比对象；检验是否只是重复表达 | 把两个通过的因素相乘就称新增信息；借交互越界情绪研究 |

“模型内增量”只回答固定方法的表达帮助。简单线性方法遗漏曲线或交互的可能性要保留；增加复杂方法必须事先说明它解决哪个具体缺口、限制尝试并与简单对手比较。没有方法可以一次证明永久有效。

### 防止假改善的必要检查

- 时间：信号只用当时资料，训练只用当时已成熟结果；重复使用的历史不能叫真正未见验证。
- 重复：新公式若是已有输入的确定变换，先写清它可能只改善表达，不是新的原始信息。
- 基准：对同一对象/日期比较，既看相对已有方法，也看合理简单办法；没有共同支持不能硬算条件增量。
- 依赖：连续状态、重叠未来窗口和同日资产相关须在不确定性处理中保留；几千行不等于几千次独立机会。
- 选择：所有参数、期限、方法、失败保留；大量尝试需要考虑偶然找到正值的风险。旧19/20/21/22邻域证据先复用，不为表格再次扫参。
- 反例：按预先指定年份/资产及集中度检查保留相反结果；不能删它们后升级结论。
- 强度：同时给实际量级和允许改善/恶化的范围。没有预先业务依据，不临时发明最低过关数值。
- 可执行性：交易成本、换手、现金和成交限制需要策略合同；未测写未测，不将因子收益分组冒称完整策略收益。

## 执行者最短调用路径

合同样例和实际两次演示在
`docs/experiments/raw/research-workflow-engineering-2026-09-29/demos-final/`。
最初版本的`demos/`原样保留；最终版本补齐了计算前拒绝尝试的耗时入账，沿用原家族预算。
实验库的报告是生成稿的副本；复现合同、数字和回执保存在实际运行目录，最终演示为
`demos-final/<案例>/run/`。生成稿中的“同目录”指这个运行目录；登记表的
`workflow_receipt`也记录真实回执位置。

```bash
PYTHONPATH=src python3 scripts/run_factor_lab.py --workflow-draft DRAFT.json --out NEW_FREEZE_DIR
PYTHONPATH=src python3 scripts/run_factor_lab.py --workflow-contract NEW_FREEZE_DIR/contract.json --out NEW_RUN_DIR
```

主控核对最终结论后，将相同定义/方法的新合同指向新报告路径，重新冻结；再执行：

```bash
PYTHONPATH=src python3 scripts/run_factor_lab.py --workflow-contract NEW_FREEZE_DIR/contract.json --out NEW_ACCEPTED_DIR --reuse-predictions PREVIOUS_RUN_DIR --register-report
```

只改说明文字不重新拟合；只改汇总比重可重用预测，重算汇总和验收。改特征、标签、
数据、抽样频率、期限切分或评价器会使对应预测缓存失效。改后看过结果须记探索。
家族日志在 `docs/experiments/raw/research-workflow-ledgers-2026-09-29/<family-hash>/`，
它是Experiment Ledger的运行记录，不是第二份因子登记表。同一家族只允许一个
活动运行；改任务名不重置次数、预算或已见资料。日志记录演练、失败、重试及耗时。
计算前拒绝的尝试也消耗同一家族时间预算，但不计为新的科学假设。

## 覆盖边界（不要把入口接入说成全系统已接入）

| 入口/用途 | 当前能力 |
|---|---|
| 新 `--workflow-draft` / `--workflow-contract` | 已接实际计算前检查、合成演练、冻结、两种评价器与覆盖链 |
| 新分支 `--register-report` | 已接实际发布验收；缺凭据、漏基准、改数字/单位、少交预测均不能完整登记 |
| 旧 `--protocol` | 保留自身原有合成协议检查，未迁移到六阶段新合同 |
| 旧 `--benchmark-protocol` | 保留自身原有基准研究检查和登记，未声称受新发布验收约束 |
| 历史 raw脚本、其他独立研究脚本 | 未统一接入；旧快照不改，不由本入口追溯认证 |
| 真实报价 | 先调用原input_preflight，再绑定实际日历、价格、缺价与经济变换；原始名义价加手填action_known不能过关 |
| 经济价格 | 只接受从指纹绑定的名义OHLC及行动清单用现有economic_index函数逐值重算；没有行动记录不证明行动历史完整，完整性未证实只作有限结果 |
| 可操作真实开盘、完整账户政策 | 当前明确不支持；不能用open_actionable=true替代证据，不计算或登记投资收益 |
| 未见资料 | 可检测本入口日志中的同内容/重叠已评价标签；历史未接入脚本的接触史还需主控读取真实交接，不能自动保证所有过去资料未见 |
| 任意程序/操作系统 | 没有禁止任意脚本的权限沙箱；本入口不承担恶意重写代码、凭据和日志的安全认证 |

技术分支拒绝情绪、宽度、宏观和生产用途；公共数学工具的存在不授权本负责人运行这些研究。

## 2026-10-04：连续方向与相邻变色的已实施示例

实际实例见 `docs/experiments/technical-persistence-and-color-transition-2026-10-04.md`，D1/D2/D5不另造登记表。新适配器 `technical_persistence_information.py` 支持准确对象 `research.trend.ema_direction_persistence20@1.0.0` 和 `research.signal.bull_green_adjacent_black20@1.0.0`；只走各自固定四ETF、252连续暖启动、20交易间隔合同。连续因子用固定值组与排序补充模型比较；变色类别不强行排序。资格支持不足时止于qualification_only，不能把背景日当事件数。

`alphalens_component.component_analysis(frame)` 是窄研究组件：传入项目已经合资格的 `(date,asset)` 面板及 `factor/factor_quantile/20D`；20D代表20交易间隔、不是20自然日。上游固定源码SHA先核验，分组提前固定；未知、并列、常数日期不随意删。仅复用原排名和原分组均值，独立观察假设的误差范围不用于金融推断。完整Alphalens包未安装，没有收益构造/资金组合/生产入口。

同日ETF排名与同一ETF随时间排名不是同一用途；本例2026上半年两者相反，必须同时说明。训练误差变好、某组收益高、某种排名正数，均不能代替相同对象日期的新增信息检验；已有模型还须并列简单历史参照。报告中样本稀少、固定方法未支持、弱背景及未知失败原因分别保留，不一律解释为信息重复。真正未来观察缺合法取得时间与历史接触记录时标blocked，不填一个猜测的新观察起日、不自动收样本。
