# C 子合同：自进化 M2——方法变化闭环（self-evolution-m2）

定位：M1 是台账（记录），M2 是**闭环**（提出→对照→审查→裁决→沉淀）；
仍不是自动改进系统。

## C1 before/after 流程化＋失败分类（glm-high，1 主派发＋≤1 返修）

- **before/after 模板 v2**（升级 M1 模板）：原方法/新方法/为什么改/改了
  什么/是否改变规则＋**必须保留旧方法结果**。
- **失败模式人工标签体系**（先不上模型聚类）：输入问题/时间问题/样本
  问题/工程问题/解释问题五类；对 M1 台账 11 条回溯打标。
- **审批流程状态机**：proposed→reviewed→approved/rejected→observed
  （与 M1 schema 的 status 对齐扩展，不造新词）。
- **三项新风险的防线**：成功偏置→必须统计 rejected 比例；偷改尺子→
  自动检查 trading-spec/评估器是否变化（git 层面可核）；历史结果驱动
  修改→before/after 缺旧结果即不合格。
- 验收：模板 v2＋11 条回溯打标＋状态机落地；rejected 比例出现在台账
  统计里；防线检查可执行。

## 边界

不自动采纳/部署任何方法；不进 replay；不改评估标准；与因子证据不联动
（不出现"因子表现→自动改方法"）。
