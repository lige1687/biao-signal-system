## 为什么仅挪两处日期不够

旧生成器`prepare_data.py::build_csi300_memberships`每20个交易日查询一次供应商名单。端点不同才搜索第一次集合变化，再把这次查询结果向后铺开；输出键叫`detected_effective_dates`。程序并未核官方公告生效时间，也未把原始成员回应及其`updateDate`保存进该审计JSON。不能仅凭现存集合反推出延迟具体出在提供方历史覆盖、回应日期含义还是其他环节。

两端相同会漏掉区间内先移出再纳入；一个区间内多次变化也没有逐事件穷尽保证。因此12处候选差异只是查证队列，不是官方全部事件目录。每天恰好300只、连续区间无缺行、另一个端点名单相同，都不能单独证明中间没有遗漏。

本轮可立即整理的最小修正是**新的证据描述**：保留原候选检测日；另外记录报道生效时点、日期精度、来源等级、下一交易日状态和尚未核实的代码关系。原候选表和原`detected_effective_dates`封存不覆盖；此方案没有实际修改任何输入表，也没有发布“已修复300股”的替代名单。

完整起点指某个明确历史日期有效的全部指数成员，至少要有沪深300身份（000300及其正式名称）、完整代码、交易所、有效日期、原文件来源及hash。
