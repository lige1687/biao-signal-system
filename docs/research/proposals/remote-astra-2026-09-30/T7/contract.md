# T7 合同草案：A3 “底部构造必备”与“任一即可”的同回撤比较（draft / not approved / not evaluated）

对应 T2 [next-question.md](../T2/next-question.md)。本合同只定方法；生命周期开关须先由主负责人批准。

| 项 | 固定内容 |
|---|---|
| 问题 | 在同一次回撤上，要求底部构造（B）相对“构造或 EMA20 收复任一即可”（A），推迟或放弃了哪些进入，结果差多少 |
| 机会形成 | `lifecycle_ref` 推荐读法；触碰日前的所有状态（趋势段、武装、触碰）两规则共享；身份＝标的｜趋势段｜均线组｜触碰日 |
| 身份追踪 | 两规则取并集；每个身份标 `same_entry / delayed / dropped / added`；放弃记 0，不删除；不许只看两规则都入场的回撤 |
| 当时可知的价格 | 信号日收盘生成；成交为下一允许开盘（不可成交按 T6 合同）；C＝各规则自己到入场日为止的回撤最低价；B 目标与盈亏比只记录不过滤（T1 待定） |
| 退出 | 两规则相同：收盘跌破 C，或收盘同时低于 EMA20 与 20 日抵扣价，下一允许开盘退出 |
| 简单对照 | ① 规则 A 本身；② “有差别的回撤全部不做”——用来区分“判断更准”和“少做一笔” |
| 主结果 | 每个有差别回撤的配对差 Δ＝结果_B − 结果_A（扣费，按投入资金百分比）；分列买入价差、C 差、持有天数差、每笔风险倍数 |
| 时间分组 | 窗口＝[触碰日, 较晚信号日＋20 个交易日]；跨标的、跨均线组按日历重叠合并为簇；簇差＝簇内 Δ 的平均 |
| 必报 | 簇数 G、簇大小分布（最小/中位/最大）、正负簇数、簇差中位数与均值、去掉每一簇后的均值范围、最大簇占全部绝对差比例、按年份的簇；全部逐簇表 |
| 证据充分性（看结果前判定） | 事先写下想排除巧合到什么程度（例如“比 1/20 更不像巧合”）；若 1/2^G 达不到该程度，只做 `describe_only`。若最大簇占比超过一半或去掉一簇方向翻转，结论写“方向取决于单个时期”。不设通用最少样本数 |
| 资金层（另报） | 完整账户（T6 核过的引擎）A、B 两版，账户差拆成“逐次配对差之和”与“资金复用及其余”，两部分不重复相加 |
| 不足时怎样报告 | 交逐簇案例表与“证据不足”的范围说明，不写有效或无效，不据此改原文 |
| 停止 | 交出逐簇表＋所选模式结果即结案；不追加第三种 A3、不改窗口长度、不加标的来凑簇；失败与修改理由记入家族账本 |

## 第 0 步实际计数（已执行，未读任何收益）

`docs/experiments/raw/remote-astra-T7-2026-09-30/qualification_count.py` → `qualification-count.json`：GitHub 两只 ETF 上有差别的回撤 30 次（510300 推迟 8、放弃 7；159915 推迟 10、放弃 5；没有新增），合并为 13 个时间簇（大小分布：1 个的 6 簇、2 个的 4 簇、4、5、7 个各 1 簇；3 簇横跨两只 ETF）；开始年份 2015:1、2017:1、2018:2、2020:9、2021:7、2025:2、2026:8；1 次窗口被资料末端截断。

判断：13 簇在“都同方向”时理论上可达很小的巧合比例，但最大簇含 7 次、2020—2021 与 2026 三年占 24/30，任何一簇都可能主导均值。**推荐模式 `describe_only`＋逐簇表**；若主负责人在看结果前另定更宽松的关注程度，可做有限估计，但必须同时报去掉最大簇后的结果。资料来源须按 T8 先确认（两只 ETF 名义价、行动覆盖未证明完整）。
