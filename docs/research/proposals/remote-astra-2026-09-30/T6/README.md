# T6：完整资金的独立核算（离线核验，不是收益实验）

## 一句话结论（大白话）

这次检查的是“账有没有记对”，不是“方法好不好”。我挑了12个最容易把赚亏算歪的记账时点（例如分红哪天归谁、停牌那天怎么估值、拆分那天份数和价格是否同时变），各编小例子手算标准答案，再交给当时封存、之后不再修改的两套记账程序跑一遍；又从已保存的账户里抽了4个，按原始行情重新算了22个日子的现金、持仓和分红。

结果：**已经保存的48个技术账户和首12账户里，抽查的数字与独立重算完全对得上（最大差不到0.000001元），12个时点在真实记录里都没有算错的地方，原报告的结论不需要改。** 但小例子也找到三处程序在“当前资料里没遇到、换别的产品就会出错”的问题，以及几处旧合同本身与真实交易规则不同的地方，其中一处已经影响了保存的数字：

- 首12账户那套程序，如果除息日或拆分日恰好停牌没有报价，当天账户金额会多算（一拆五时接近多算成5倍）。现有两只ETF从没遇到过这种日子，所以已保存结果不受影响；以后接入纳指ETF（它的拆分日就停牌）或其他产品时必须先修。
- 48账户那套程序在“现金正好够买整数手”时，因为小数精度会少买一手；496笔真实买入一次都没碰上。
- 旧合同规定开盘碰到涨跌停一律不成交。2024-10-08沪深300和创业板开盘涨停，首12的4个宽度账户想卖却被挡住，第二天才以低7%—10%的价格卖出。粗略看，两只ETF宽度账户（0.1%费用档）的期末金额因此少记了约8.5%和11%。这不是算错，是旧合同的保守假设；它只会让已有的“宽度方法”看起来比实际略差，不改变原报告里“创业板简单道路方法赚得多但跌得深、沪深300它少赚”的比较方向。
- 另外再提醒一个容易误读的地方：A/C/D 名义上“每次只拿1%的钱冒险”，但46笔买入里有26笔其实是现金先用光，几乎满仓（投入占账户99%以上）。真正卖出时的亏损是计划风险金额的1.1—10.5倍，占账户1.1%—4.9%。

## 先解释几个词

- **冻结程序**：当时为这批研究写好并封存的记账程序。这次只在临时副本里调用，原文件一个字节没动。
- **失效位**：买入时就定好的“跌破就卖”的价格。
- **1%计划风险**：A/C/D 买多少份的规则——前一天账户总额的1%，除以“开盘价−失效位”，再按100份取整，同时不能超过现金能买的数量。它只算价格距离，不含手续费和跳空。
- **应收分红**：已经确定归你、但还没到账的分红。算在账户总额里，但不能拿来买东西。
- **登记日 / 除息日 / 到账日**：登记日收盘时持有多少份，决定能分多少钱；除息日价格扣掉分红、同时记一笔应收；到账日应收变成可用现金。
- **研究假设局限**：程序符合旧合同，但旧合同本身的假设和真实交易规则不一样，或者两份旧合同对同一件事说法不同。

## 发现（按对解释的实际影响排序）

1. **旧合同“开盘涨跌停一律不成交”已经影响了首12宽度账户的保存数字（研究假设局限）。** 2024-10-08，510300前收4.233、开盘4.656，159915前收2.232、开盘2.678，都正好是涨停价。4个宽度账户（两只ETF×两档费用）当天目标是全部卖出，却被挡住，次日分别以4.285和2.41卖出。仅这一笔，当天少拿现金约18,939元（510300，0.1%费用）和33,815元（159915），相当于当时账户的8.5%和11.1%。宽度方法按目标比例调仓，之后路径大致按同比例缩放，粗估期末金额约为265,871元（原245,024.65）和438,963元（原395,056.03）。这只是估量级，**没有重跑**，也不计取整和后续费用差。按交易常识，开盘涨停时卖出一方通常更容易成交，但本地日线没有盘口资料，不能证明当天一定卖得出去。反方向的2015-07-08（首12的159915简单60日突破账户，开盘跌停时卖出被挡），挡住反而让账户多了约841元，也更接近真实情况（跌停时卖单难成交）。48个技术账户没有一次开盘受限，不受影响。
2. **首12记账程序：除息日或拆分日没有报价时，账户金额多算（不一致）。** 位置：`first12/run_accounts.py` 第253—262行。除息时只加应收、不把旧估值价扣掉分红；拆分时只把份数乘倍数、不把旧估值价除倍数；要等下一个有报价的日子才恢复。小例子里除息日账户多出4,950元（应收被算了两次），一拆五当天账户变成5倍。这会造成一天的假高点和随后的假回撤。现有两只ETF研究期内除息日都有报价、没有拆分，已保存结果不受影响。直接复用这段 `simulate` 的 `research-broad-etf-multimethod-2026-09-08/execution/account_adapter.py`，以及抄写了同样写法的 `research-dividend-reinvestment-2026-09-09/execution/run_accounts.py`（第254—259行），也都只用这两只ETF（只读了配置，没有运行）。**以后接入513100（拆分日停牌）或其他有拆分的产品之前必须先修**。48账户程序在这两种情况下是对的（C06d_T、C08a）。
3. **48账户程序：现金正好够买整数手时会少买一手（不一致）。** 位置：`execution/engine.py` 第207行。“现金÷(开盘价×(1+费率))÷100”用二进制小数计算，结果比整数略小，向下取整就少一手；第208行的风险份数那一路加了 `+1e-12` 保护，现金那一路没有。496笔真实买入用十进制重算全部一致，没有碰上。
4. **禁止估值日的保护只在运行入口（一致，提醒复用者）。** 引擎本身不认识“禁止收盘估值”这类限制，有报价就会估值并据此卖出（C05b：当天账户按这根报价算成95,017元，随后据此安排卖出）。冻结入口 `run_accounts.py` 第36行用断言保证2021-02-08不在行情里。复用引擎的人必须保留同样的检查。
5. **拆分只能“开盘前生效”、零碎份额照旧保留（研究假设局限）。** 日终才折算的产品（原报告§6提到的510500 2022年拆分就是日终）必须把生效日录成首个新单位报价日，否则当天持仓市值被按5倍计算，小例子里账户从100,297元变成233,617元（C08b）。零碎份额怎么处理要看基金公告，本快照没有这类资料。
6. **两份旧合同对“拆分后还没新报价就除息”的说法不同（研究假设局限）。** 48账户程序按“旧收盘÷拆分倍数”推导参照价继续换算；价格换算器的补充合同（`research-eighth-2026-09-08/product-qualification/price-helper/protocol-amendment-1.md` 第2条）要求停下来，不做这种推导。现有资料没有触发。
7. **解释提醒（不是记账错误）。** ①A/C/D 的“1%”是计划风险，不是仓位：46笔里26笔现金先用光，投入99%以上；例如期末赚钱的 A20E 那笔，计划风险只有0.405%，但几乎满仓。②A/C/D 只在跌破失效位时卖出，所以已结束的持仓必然是止损卖出——42段全亏是规则决定的，不能拿来评价入场好坏；实际亏损是计划风险金额的1.1—10.5倍、占前一天账户的1.1%—4.9%，原因是费用、跳空和失效位后来按分红换算。③入场时要求的“目标空间至少是风险的3倍”是事前计划比，不是能成交的盈亏比，已结束的持仓没有一笔达到目标（这批规则本来也不在目标价卖出）。
8. **输入文件换行符（复现提醒）。** 本快照里4份行情CSV的指纹和收益前锁不同；把LF换回CRLF后指纹完全一致，说明只有换行符变了，数值没变。其余23个锁定文件指纹一致。旧入口自带“已有输出就拒绝运行”和按原机器绝对路径核指纹的检查，本任务没有运行、也没有绕过它们。
