## 记录接口（`observation_ledger.py`）

每条记录：`kind`、`object_ref`（对象@版本）、`recorded_at`（实际写入时刻，带时区）、`market_date`、`payload`、`seq`、`prev_hash`、`hash`。`kind` 取 `protocol_frozen / input_snapshot / opportunity / outcome / input_revision / definition_version / pause / resume / review`。规则：

1. 只追加；任何旧记录被改都会使后续哈希链断开。
2. `opportunity.market_date` 必须晚于该版本的 `observe_after`；`outcome` 的写入日期不得早于成熟日。
3. 修订不覆盖原结果：`input_revision` 只登记新快照指纹与差异，原结果仍按首次记录值统计，修订影响另列敏感性。
4. 新定义版本开一条新流；旧流关闭但保留，两流的结果不合并。
5. 当前状态全部由记录推导，不另存。

## 五个合成状态（演练结果）

| 情形 | 记录 | 推导出的状态 |
|---|---|---|
| S1 等待结果 | 冻结→快照→1 次首次触碰 | waiting 1；不足以比较 |
| S2 结果成熟 | 再加 1 次后续触碰与两条成熟结果 | 首次 +1.2%、后续 −0.4%，只能描述 |
| S3 输入被修订 | 某日最低价修订、触碰仍成立 | 原结果保留，修订计数 1 |
| S4 定义新版本 | 1.0.0→1.1.0 | 旧流关闭（含 2 条结果），新流从改版日重新开始（0 条） |
| S5 预算中断 | pause，保存恢复点 | 观察流 paused，未成熟机会 1 条保留 |
