# T10：移交最小资料后，别人怎样真正复查同一个实验？（架构决策，draft）

## 一句话结论（大白话）

**推荐：每次移交只多带一份“移交清单”（handoff-manifest），原来的冻结合同和锁文件一个字节都不改；清单里写清每个文件的指纹、换行符、能否公开、旧路径怎么对到新路径、用的是哪版代码，复查方先跑一个小校验器，结果是“完整 / 缺文件 / 内容被改 / 代码版本不对 / 只差换行符”五种之一，前四种之外都不能开始复查。** 校验器用 5 个合成情形实际跑通，并给 GitHub 上已有的宽基技术实验生成了一份真实清单。只读审查还发现两件已经影响这台电脑的事：**旧锁里的行情 CSV 在 GitHub 副本中换行符变了（内容相同、指纹不同），以及定义登记表引用的 56 个证据文件没同步，导致登记表在这台电脑上直接无法加载。**

## 1. 先分清三种“复查”

| 用途 | 需要的资料 | 需要的权限 | 不能说成 |
|---|---|---|---|
| A 旧报告数字核对 | 报告、保存的账户/结果文件及其指纹 | 读权限即可 | 不等于重新算过 |
| B 按冻结旧代码复现 | A ＋ 冻结代码逐文件（git blob 一致）＋ 全部输入原件 ＋ 依赖版本 | 输入原件的移交授权（部分行情许可不明） | 用当前代码跑通不等于 B |
| C 新协议、当前代码重算 | 新合同、当前提交、合格输入 | 新研究授权 | 结果不是旧实验的复现，只能“历史对照” |

## 2. 两种移交办法

| | P1 公开仓库内小包＋移交清单（推荐默认） | P2 授权后单独传资料 |
|---|---|---|
| 适合 | A 全部；B 中可公开的部分（代码、协议、锁、抽取的事实、结果） | B 中许可不明或私有的部分（行情原件、公告原件、账户库导出） |
| 风险 | 公开了不该公开的原件；换行符等平台差异 | 传输后无人核指纹；链条断在私下传输 |
| 做法 | 清单 `public=true` 的文件入库；`public=false` 只记指纹与获取方式 | 同一份清单，复查方收到后先跑校验器 |

决定：**P1 为默认，P2 只补清单里标 `public=false` 的文件，两者用同一份清单与同一个校验器。** 不另建调度系统；`workflow.py` 的冻结合同与回执、`data_snapshot.py` 的快照指纹继续是原件，清单只引用它们。

## 4. 已有包只读审查结果

| 发现 | 证据 | 影响 | 建议 |
|---|---|---|---|
| 行情 CSV 换行符变化 | 宽基技术、风险仓位、语义组合、退出贡献 4 份锁中，各 2 个行情 CSV 的指纹只在把 LF 换回 CRLF 后才一致（git 记录为 `i/lf`） | 在这台电脑上按原锁核验会报失败；内容未变 | 清单增加 `eol` 字段，校验结果单列 `eol_only`；不改原锁、不改原文件 |
| 旧锁写死原电脑绝对路径 | 宽基技术、风险仓位、第十批等 4 份锁全部是 `/Users/yongbiaoli/...` 绝对路径；另 4 份为相对路径，但基准目录不统一（2 份相对仓库根、2 份相对锁所在目录） | 不能原样在别的电脑运行入口；README 已警告不要就地运行 | 清单 `path_map` 只做映射，不重写锁 |
| 被锁的规范文件后来改过 | `research-breadth-price50-decision-2026-09-09/chinext-scope` 锁中的 `experiment-backtest-principles.md`、`definition-standard.md` 已与当时指纹不同 | 用当前规范复查那批实验会核到另一版本 | B 类复查须取当时版本（git 历史或 `before/` 快照） |
| 定义登记表无法加载 | 178 条 lifecycle 依据中 56 条指向未同步 raw（如 a01/a02/a03、b3b—b14 目录）；`load_registry()` 报 `lifecycle basis path missing`；登记表与研究工作流相关的 6 个单元测试文件在本克隆 64 个失败、72 个通过，其中 50 个因登记表无法加载，14 个因引用的其他 raw 文件不存在 | 这台电脑上依赖登记表的研究入口全部不能运行 | 移交包必须包含“登记表引用闭包”：要么同步这些 raw，要么在清单中列为缺项；不能为让它通过而改登记表 |

## 5. 应进公开仓库与需单独授权的内容

- 入公开仓库：冻结协议、原锁、冻结代码、移交清单、抽取后的行动事实（日期、金额、来源链接、原件指纹）、汇总结果、合成夹具。
- 单独授权：行情原件（来源许可未记录）、交易所/基金公告原件的大批转存（上交所声明限制以牟利为目的的转载，深交所声明未找到，见 T8）、账户库导出、主电脑本机数据库。
- 永不入包：密钥与令牌、私人聊天、登录后才能取得的资料、来源许可不明的原文全文。

## 6. 证据限制

只核了 GitHub 克隆里已有的文件；主电脑上的最新 raw、9-27 六 ETF 账户、84/84 行动补证都看不到，没有声称核过。合成演练只证明校验器按约定工作。
