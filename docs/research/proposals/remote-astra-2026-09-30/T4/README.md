# T4：日线、周线与小时确认的真实时点（字段合同与合成测试，draft）

## 一句话结论（大白话）

**一个“确认”最早什么时候算知道，取决于它用到的最后那根 K 线什么时候真正走完、数据什么时候真正拿到；两者取较晚的那个，然后才谈什么时候能下单。** 按这个规则：日线信号最早当天收盘后可决定、下一交易日开盘执行；周线只在“这一周最后一个交易日”收盘后才算完成，必须用交易所日历判断，不能默认星期五；原文要的“小时级别多头”在仓库里**完全没有资料**，只能记“未接入”，现有的日线代理（盘中刺穿后收回、反转 K 线）不能当成小时转强。我写了一个时点计算参考实现和 12 个合成时间戳测试（普通周、节假日短周、整周休市、周内未完成、收盘后修订、午休、末根小时未完、小时确认晚到、资料缺失、日历未覆盖、周末操作节奏），全部按人工答案通过；另用生产函数核出 3 处时点风险。

## 2. 字段合同

机器可读：[field-contract.json](field-contract.json)。要点：

| 字段 | 含义 | 规则 |
|---|---|---|
| `item` / `timeframe` | 价格条目及其周期（60m/1d/1w/1M） | 每个确认条件列出它依赖的全部条目 |
| `bar_start` / `bar_end` | 交易所时区的起止（带 UTC 偏移） | A 股 60 分 K 线结束于 10:30、11:30、14:00、15:00；不得用机器本地时区 |
| `complete_at` | 该 K 线所属时段确实结束的时刻 | 日线＝当日收盘；周线＝日历中“本周最后交易日”收盘；整周休市则该周无周线；日历未覆盖→unknown |
| `source_available_at` | 数据实际到达研究系统的时刻 | 历史上多数未记录→只能给“不早于 complete_at”的下界，标 `lower_bound_only` |
| `known_at` | max(complete_at, source_available_at) | 修订另记 `revision_id`；在某观察时刻只能用当时已有的版本 |
| `decidable_at` | 一个决定所需全部条目 `known_at` 的最大值 | 任一条目 unknown→整个决定 unknown，不是“条件不成立” |
| `earliest_execution_at` | 按执行节奏取 decidable_at 之后第一个允许成交时刻 | 日线参考＝下一交易日开盘；午休、收盘后、休市不可成交 |
| `calendar_ref` / `exchange_session_ref` | 所用交易所日历与时段配置的版本和指纹 | 作为输入注入，不内置、不猜 |

## 3. 合成测试（`docs/experiments/raw/remote-astra-T4-2026-09-30/timing_cases.py`，12/12 通过）

合成日历覆盖 2026-09-28—10-18，人工设定 10-01—10-09 休市（不代表真实安排），从而得到三天短周、整周休市周和普通周。结果见 `cases-output.json`：普通周 15:30 可决定、14:59 不可；短周周三收盘完成；整周休市无周线；周三看不到本周周线；16:00 用首发版本、19:00 用修订版本；11:30 小时线午休中可决定但 13:00 才能成交；14:30 看不到 15:00 那根；日线信号＋次日 10:30 小时确认 → 决定时刻 10:31，比日线参考的 09:30 开盘晚；小时资料未接入→unknown；日历未覆盖→unknown；周末节奏下周二信号要到周五收盘复核、下一开盘超出日历覆盖时记 unknown 而不猜周一。

## 4. 生产函数时点对照（只调用，不改源码）

| 编号 | 现象 | 影响 | 归属 |
|---|---|---|---|
| P1 | `aggregate_weekly` 默认日历只认周一至周五：节假日短周在周三收盘后**不**承认周线完成，要等下一根日线；注入日历才当天完成 | 偏保守（晚一到数天），不会提前；但模块 A 的周线环境 `weekly_context.py:54` 不接收注入日历（T5 已列为已知 K2） | T5 已记录 |

| P3 | `classify_a_share_bar` 把不带时区的观测时刻当作上海时间 | 调用方若传入不带时区的 UTC 时间（如 07:30＝上海 15:30），会把已收盘判成盘中；方向保守，但会让收盘后任务误拒绝 | 新：建议观测时刻强制带时区，缺时区直接报错 |

## 5. 周末 / 月末才能操作的执行节奏（合同草案）

见 field-contract.json `execution_cadence`。与原文日线参考的区别：原文是“t 收盘信号、t+1 开盘执行”；周末节奏是“只在本周最后交易日收盘复核一次，用当时已知资料**重新判断条件是否仍成立**，下一交易日开盘执行”——不是把周二的信号拖到下周一照做。月末同理。本任务不估计延迟操作的实际收益；那属于另立的比较（同一回撤、两种节奏），可直接套用 T7 的同机会比较方法。

## 6. 证据限制

没有任何真实小时行情，也不发明供应商；真实交易所休市安排未用于本测试（仓库有深交所 2019-09—2026-06 月历，上交所未独立验收，见 T8）。参考实现不是生产代码。
