# T2：把完整 A 回调逻辑接回研究（提案，draft / not approved / not evaluated）

## 一句话结论（大白话）

现有“均线距离”“第一次触碰”研究只测了原回调规则里的“位置”一环；原文完整的一次回调买入，还要经过“趋势成立→回撤到均线组且均线不拐头→出现底部构造和小级别转强→站回 EMA20 买入→按结构低点止损→按原逻辑退出”六步，其中小级别（小时）确认至今没有资料，只能标“未知”。更重要的是，我用 9 个人工小例子实际运行了现有模块 A 代码，发现它和原文读法有几处不一致：**价格只是贴着均线走、根本没有回撤也会被记成一次触碰；回撤中收盘创新低就把这次回撤作废、再重新算作“非首次”并把止损抬高；日线一转黑就把趋势重新开一段，使后面的回撤又变成“首次”；已经被破坏的底部构造仍被拿来当买入依据。** 在两只 ETF 的真实日线上，现有代码约四分之三的回调入场属于第一种情况。所以已有研究里的“首次/后续”标签、止损价和机会数，不能直接当成原文意义上的“第一次回撤”和“结构低点”。这些是研究口径问题，本任务没有改生产代码。

## 回答任务书的两个问题

1. **局部研究离原文完整规则缺哪几步？** 等待环节缺“回撤期间均线方向每日保持”和“小级别多头”（后者无资料）；进入环节缺“底部构造与小级别同时具备”的原文读法（实现只要求四选一，代码只实装了两种），目标 B 缺首选的“上方均线密集区”（T1 待定）；失效环节缺原文“跌回抵扣价方框下方”的止损定义（代码用触碰以来最低价代理）；退出环节 A6② 在宽基研究中未测。逐项见 [condition-map.md](condition-map.md)。
2. **怎样比较一个条件的作用而不把另一批机会冒充同一批？** 回调“位置”（触碰日）同时决定了结构查找起点、EMA20 收复的计数起点、止损价 C、首次计数和候选结束条件；入场日一变，C 与盈亏比也跟着变。所以比较必须以“同一趋势段里的同一次回撤”为身份，逐次记录两种规则各自的进入日、C、B 和结果，不能只删一个字段、其余照旧。见 [lifecycle.md](lifecycle.md) 的依赖图和 T7 的比较方法。

## 推荐与备选

- **推荐**：新研究使用 `lifecycle_ref.RECOMMENDED` 读法（研究代理，未批准）：趋势段只在均线排列破坏或收盘跌破 SMA120 时结束；回撤中创新低不作废，止损取到入场日为止的最低价；每天核对该均线组 SMA 方向，方向拐下即取消；底部构造每天按当日是否仍有效重核；须先离开触碰带才可能出现回撤；缺价打断后“首次”记未知。依据：体系 §4.4 第 2 步明说“价格经常击穿均线，只要当前价仍高于抵扣价，MA 就还在往上走”；§7.4“构造被破坏了就找下一个”；A03 已封存研究的趋势段口径也不因转黑结束。
- **备选**：保留生产读法作为“历史对照”，用于解释已封存的模块 A 资金研究；两者的逐次映射作为下一研究的第 0 步资格表。
- **放弃**：直接修改生产代码或重算旧账户——超出本任务权限，也会覆盖封存结果；修复建议另见 [production-fix-notes.md](production-fix-notes.md)，交主负责人决定。

## 需要用户确认的最多三件事

1. **A3 结构条件的读法**（体系 §4.4 与实现 A3 冲突）：原文体系写“底部构造 + 低一级别多头趋势，即可进入”，实现文档写“四种结构至少一种”，代码只实装了“严格底部构造”和“EMA20 收复”两种。推荐：研究两条都保留——“至少一种”为现行对照，“底部构造必备、小级别未知”为原文分支；在用户确认前不把任何一条称为原规则。
2. **“一波趋势”在什么情况下算结束**（决定“第一次回撤”的计数范围）：推荐只有均线多头排列破坏或收盘跌破 SMA120 才结束，LEI 日线转黑不结束；生产代码转黑即结束。
3. **目标 B**：维持 T1 待定，T2 不替 T1 作决定；B 不可得时机会保留、盈亏比记“未知”，不删除。
