## 1. 目标与范围

- 仅 **510300**（华泰柏瑞沪深 300 ETF，上交所；腾讯代码 `sh510300`）。
- 拟评价期 **2019-10-08 — 2025-12-31**；输入必须覆盖：
  - 预热：已核日历内评价起点前恰好 20 个交易日，即 **2019-09-02 — 2019-09-30**；
  - 目标尾部：至 **2026-02-03**（2025-12-31 后第 22 个交易日）。
  - 即价格序列须完整覆盖 **2019-09-02 — 2026-02-03** 的每一个已核交易日。
- 日历身份：`docs/experiments/raw/research-calendar-completion-2026-09-10/calendar-merged/calendar.json`，
  SHA-256 `aa43736b67bbcee04fc21eedf8d510b184b764adf138456c8bce93a3155eb6c1`
  （深交所官方来源，1652 个交易日，2019-09-02—2026-06-30）。执行前逐项核对哈希，
  不符即中止。
- 价格口径：供应商前复权日线（腾讯 `qfqday`），锚定抓取日；声明
  `adjusted=true, adjustment=vendor_qfq, anchor=fetch_date`。**不接受** `day`
  （不复权）回退——响应缺 `qfqday` 即判失败，不降级口径。

## 2. 请求规格（名义 3 次，路径甲）

端点：`GET https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`；
请求头 `User-Agent: Mozilla/5.0`、`Referer: https://gu.qq.com/`；超时 10 秒。
参数形式 `param=sh510300,day,{start},{end},640,qfq`：

| 窗口 | start | end | 说明 |
|---|---|---|---|
| W1 | 2019-08-19 | 2021-12-31 | 起点早于首个所需交易日 2019-09-02，留余量 |
| W2 | 2021-12-15 | 2023-12-29 | 与 W1 重叠约 2 周，供拼接一致性核对 |
| W3 | 2023-12-15 | 2026-02-10 | 与 W2 重叠；终点晚于尾部 2026-02-03，留余量 |

窗口沿第三轮（research-third-2026-09-08）同标的先例：单窗 count=640、
相邻窗口约 2 周重叠。count>640 可靠性无文档依据，不使用大窗口。

每次请求的响应验收：HTTP 200 → JSON 顶层 `code==0` →
`data.sh510300.qfqday` 为非空数组 → 每行至少 6 字段且数值可解析。
任一不满足即该次尝试失败（进入重试预算），**不**改用 `day` 字段。

## 3. 请求计数与重试（硬上限 8 次）

- 计数规则：每一次实际发出的 HTTP 请求计 1 次，含 3 次名义请求与**所有**失败
  重试；驱动脚本内单一计数器，发出前检查，达 8 即拒绝再发并中止。
- 重试策略：仅对网络错误 / 非 200 / JSON 解析失败 / `code!=0` 重试**同一 URL**，
  退避 2 秒、4 秒；全程共享重试预算 5 次（3 名义 + 5 重试 = 8 上限）。
- **可约束性声明**：驱动使用 `urllib` 直连，每个请求由驱动显式发出，无任何库
  内隐藏请求（不使用 akshare/yfinance/requests 会话），因此计数可可靠约束。
  若主控改用 akshare 封装：已读 v1.18.49 源码，正常路径 1 次请求，但库升级
  可改变内部行为且旧脚本带新浪自动回退——本规格不推荐，若采用须钉版本并
  重写计数声明。
- 超限或预算耗尽：中止，状态记 `fetch_failed`，已得原始响应保留为证据但
  **快照不成立**，不拼装、不采用。

## 4. 禁止事项

- 禁止自动回退供应商（不得转东财/新浪/akshare/yfinance 或任何其他源）。
- 禁止覆盖、移动、改名任何既有文件，包括但不限于：
  `~/.lei_signal_lab/cache/**`、`tests/510300.SS.bars.parquet(.meta.json)`、
  `docs/experiments/raw/**` 内一切冻结件。输出目录必须事先不存在。
- 禁止登录、取密钥、安装依赖、请求行情以外的接口。
- 禁止把 `fetched_at` 写成历史行的 `available_at`；逐行可得时间保持未知。
- 禁止在协议冻结前用新快照计算任何状态/目标/收益。

## 5. 拼装与验收检查（全部本地、无网络）

1. 三窗口原始 JSON 逐字归档并各自 SHA-256；按日期拼接，重叠日逐值核对——
   有任何不一致即失败，不静默择一。
2. 拼接序列与已核日历对齐：2019-09-02—2026-02-03 每个已核交易日必须存在；
   缺日逐日列出即失败；多出的非交易日行列出并剔除（记录，不静默）。
3. 行数 sanity：覆盖区间交易日约 1550 行（以日历为准，非估计值验收）。
4. 价格口径声明写入 manifest；`available_at=null`、`available_at_source` 不写
   （未知保持未知）。
5. 输出：新目录下 `sh510300-qfq-snapshot.parquet`（或主控指定格式）+
   `fetch-manifest.json`（格式沿第三轮先例，见下）+ 原始响应文件。
6. 不做：与旧缓存/旧快照的数值对账、涨跌统计、任何因子或收益计算——
   这些属后续授权步骤；重叠一致性观察如主控需要，另行批准后单独记录。

## 6. fetch-manifest.json 最低字段

运行级：驱动脚本路径与 SHA-256、Python/pandas 版本、平台、日历文件路径与
SHA-256、计数器终值（实际请求总数）、开始/结束时刻（带时区）、状态
（`ok` / `fetch_failed` / `stitch_failed` / `calendar_mismatch`）、
价格口径声明、输出文件 SHA-256、`fetched_at`（真实抓取时刻，带时区）。

每请求级（沿第三轮格式）：symbol、窗口 start/end、完整 URL、`requested_at`、
`responded_at`、HTTP 状态、原始响应文件名与 SHA-256、解析字段（应为
`qfqday`）、行数、首/末日期、错误描述（无则 null）、第几次尝试（attempt 序号）。

## 7. 失败处理

任何失败：保留全部已发请求与原始响应记录，状态显式标记，不拼装、不采用、
不重试超预算、不换源；向主控交回失败现场，由主控决定后续。部分窗口成功
不构成部分快照。
