## 一分钟说明（大白话）

这次只做了三件事，都是"查资料、对边界"，没有算任何新数字：

1. **统计库能不能省事**：statsmodels 里那个"考虑相邻日期互相影响"的回归误差
   函数（cov_hac）和 arch 里"按历史片段重新抽样估不确定性"的工具
   （StationaryBootstrap + optimal_block_length），查清了准确函数名、参数默认值
   和前提。结论：名字和默认值都查实了，但**这两个库解决的是两个不同问题**
   （一个管"回归系数的误差有多大"，一个管"整个统计量换个历史抽法会不会变"），
   不能互相替代，也不能混着报告成同一种检验。
2. **Alphalens 会不会偷偷改含义**：逐条核了它清洗与打分函数的默认开关
   （详见 capability-reuse.csv）。最重要的三个坑：默认会把"未来收益里离群太远的
   日子"直接删掉（这用了未来信息，必须显式关掉）、分组收益默认做"减去当天
   平均"（等于偷偷构造多空对比，本地单标的场景必须显式关掉）、日历和时区由
   工具自己猜。适配方案是"薄适配 + 手算小例"，**尚未安装、尚未验证**。
3. **外部"标准因子"和我们的对象不是一个东西**：French 的市场超额收益
   （全体美股按市值加权减国债利率）和动量因子（美股内高动量组减低动量组）
   是"一篮子股票的收益序列"，我们登记表里的 mixed.momentum.raw 是"给每只
   ETF 打的一个分数"。分数不是收益，回归暴露不是因子本体；美国股票多空收益
   不能直接解释人民币混合 ETF。同名"动量"必须分开登记。

**能省什么**：不重写 HAC 协方差、不重写块自助法、不重写 IC/分组分析数值核心。
**必须自己留什么**：问题定义、输入资格与时点、日历、币种/单位/无风险口径、
分组数与去均值开关、结论语言与授权。
**下轮只建议做什么**：最多一项——见 next-pilot-proposal.md（在合成输入上隔离
核验 alphalens-reloaded 固定版本的三个默认开关）。statsmodels/arch 与外部因子
定义对照本轮**全部暂缓**，理由见各文件。
