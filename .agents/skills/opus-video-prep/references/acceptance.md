# 开工与收尾检查清单

逐项保留结论和准确证据路径；不把这个勾选表当自动执行器。本Skill提供流程与格式，不声称内含已经测量过的工程或媒体。

## 开工包

- [ ] CONTENT_OUTLINE保存与用户讨论好的内容、重点、大致顺序及确认状态，没有越界写镜头或最终文稿。
- [ ] BRIEF只含本期有效要求，长交接已归一；事实必须/可选/禁用、缺口与授权范围清楚。
- [ ] 没有Codex新写的文稿、分镜、逐镜素材选择或本期主题图表/动效；既有用户稿原样引用。
- [ ] 原数据/取得时间/指纹齐备；facts算法、窗口、单位、恢复状态、等待年月及核算证据可用。
- [ ] 外部数字附短摘录、准确页码与截图；表格转成文字，脚注/日期/单位逐项核对。
- [ ] 音频SHA一致；节拍/鼓点/分界、每秒能量、LUFS与dBTP有实测记录；不确定项和听审状态明确。
- [ ] 每条实拍有每秒带时间码联系表、内容、区间、规格、作者、许可、链接、指纹；没有预先绑定镜头。
- [ ] 工程来源/通用接口/脚本功能已核；依赖与浏览器已准备，typecheck与实际短渲染通过。
- [ ] 三种字体由真实工程导出，结果可供Opus判断；fallback/缺字已核。
- [ ] 数据和素材在包内，相对路径可加载；交付包无._文件，无绝对外盘资源依赖，无指回旧工程的资源链接。
- [ ] 新父目录实际重建通过；只写测试覆盖平台，不把路径迁移当跨系统验证。
- [ ] READY分别列ready/partial、各项状态与恢复条件；manifest逐文件读回，原始资料保留。

### 给Opus的最短启动指令

```text
请从BRIEF.md、CONTENT_OUTLINE.md和READY.md开始。Codex已把事实、音乐测量、候选素材及可用工程归一，按索引读取相关结论即可；只有发现冲突时追溯原始证据。沿用我们与用户讨论确定的内容及大致结构，你负责具体文稿、分镜、每镜素材选择、图表与动态设计、看渲染结果后的审美调整。遵守本期事实锁定/禁用/授权，不把候选素材全部用上。沿用已能运行的通用底座，按创作需要修改实现，避免无目的重写。按当前阶段先交真实工程风格帧，确认后交中间难点15秒，再经确认扩片；已有明确批准按BRIEF沿用。技术缺口标具体文件、预期结果与失败位置交回Codex。
```

## 成片后Codex机械收尾

- [ ] 先确认唯一指定最终片及源码版本；保留旧版，不通过猜文件名选交付。
- [ ] 全片完整解码、视频规格/时长/音轨、黑帧/静音异常按本片设计核对，异常不直接删镜。
- [ ] 最终混音重新测整合响度/真峰值；没有平台或用户目标就只报告结果，不自设阈值强制归一。
- [ ] SRT若存在：编码、编号、时间格式、start<end、顺序、是否越过片长及重叠原因；抽核文字/时间。无字幕的设计可not_applicable；不因工具需要而另写字幕文案。
- [ ] 逐项更新授权台账、必需署名与未知项；公开传播状态单独明确。
- [ ] 成片、字幕、工程/锁文件、来源和交付描述进入指纹清单，读回大小与SHA一致。
- [ ] 在隔离副本按交付步骤实际重建指定最终目标，记录输入/命令/耗时/日志/结果。仅重建短测试不能称全片重建通过；编码元数据差异可说明比较方法，不虚称文件SHA必然一致。
- [ ] 报告技术通过/失败与未运行项；审美由Opus和用户判断。技术失败或事实冲突交回具体证据，不擅自改创意方案。

实际执行所需大文件与日志仍走核验外盘；备料/收尾不授权自动发布。用户只要求其中部分检查时尊重范围，未做项明确标记。
