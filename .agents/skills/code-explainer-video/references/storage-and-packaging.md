# 视频目录与配套文档

用户2026-10-09要求：“产生的视频都搞到外部磁盘，创建合适的目录层级，每个视频都要产生对应的描述文件，和对应的文稿，定位啥的。”适用于本工作流全部后续视频及改版，不能只归档最终MP4。

## 位置与版本

先读项目运行存储管理与实验大结果存储说明，运行storage核固定UUID、挂载与容量；按既有输出预检绑定真实路径。规则不是自动覆盖所有第三方工具的硬限制，逐项检查素材生成、渲染、音频处理、临时目录和日志的实际输出。错盘、无盘或容量不足停止新增媒体，不回退内盘。普通源码、运行依赖及小索引沿用本机安排。仅文稿准备不称作外盘归档完成。

在已批准外盘的视频任务根目录组织“视频库/主题/日期-视频短名/版本”。主题保持少量稳定分类；视频ID在改标题时不变；版本有独立文稿和清单，不能覆盖旧版。

```text
视频库/
  趋势交易/
    20261009-趋势交易简史/
      视频索引.md
      v14/
        00-定位与描述.md
        01-文稿.md
        02-分镜与声音.json
        03-来源与授权.md
        04-文件清单.json
        成片/
        封面与预览/
        素材/画面/
        素材/声音/
        制作记录/
```

目录是逻辑交付结构，实际绝对位置必须由当次预检和archive-plan记录。运行器已绑定的result路径不改写；可在视频库建小索引，指向原result里的交付包及现有媒体，避免为了美化目录搬旧片或重复复制大文件。新片在绑定result下直接生成交付包，视频库只做可读导航。外盘只有一份大文件亦可，清单注明“引用既有文件”及相对/绝对路径。跨设备盘符不同按设备UUID和盘内相对路径恢复。

## 必备内容

- **定位与描述**：视频ID、标题、版本、主题、目标观众、观众看完应理解什么、内容范围、计划平台与已适配平台、时长比例、风格、旁白/配乐选择、发布简介、关键词、当前批准/发布状态。未确认的平台或定位写建议，不能冒称用户确认。
- **对应文稿**：与本版成片一致的章节、起止时间、标题、屏幕文字；有旁白时另列实际旁白文字和字幕。无旁白时明确“屏幕文稿”，不可把提纲充作完整稿。额外口播改写稿须独立标草稿，不能说已入片。
- **分镜与声音**：复用实际时间表，记录关键动作、配乐段落、音效事件及素材ID，不手抄一份易失配时间轴。
- **来源与授权**：史实出处、使用范围、图片/音乐许可、所需署名、AI素材标识、未核实内容；沿用已有来源映射并保留边界。
- **文件清单**：成片和重要素材的真实路径、字节数、SHA256、媒体参数、对应文稿版本、制作源位置/commit、验收状态。未知填null并说明；不能拿旧版SHA充新版。只在实际读回后写“已归档”。
- **制作记录**：用户确认节点、修改原因、媒体检查、播放检查、未通过项、额度记录。共享账号额度变化不得算作单片精确费用。

## 交付核对

核对成片、文稿、时间表的版本和时长；读取归档文件并核SHA，打开成片检查实际播放。定位/发布简介延续无品牌要求。用户审美待确认与文件检查通过分开写。盘断开则保留小恢复记录，标待落盘；历史片补档逐条核原文件，不删除、改名或重复生成旧片。小样也有独立版本和描述，可引用同视频的共同来源，但注明采用哪些内容。
