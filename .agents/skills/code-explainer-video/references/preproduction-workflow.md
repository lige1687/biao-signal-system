# 前置材料与工作流

## 用户最少给什么

一句主题即可启动；最好再给希望谁看、看完记住什么，以及参考链接。已有文稿、照片、音乐可以直接提供，不是启动前必须交齐的作业。时长、画幅和旁白选择沿用本次已明确要求；只有确实影响方案且无法推断的关键缺口才询问。固定默认：公开内容无自有系统品牌，先图、再10—15秒、最后成片；文件放核验外盘。

## 先准备内容，再做精细动作

以下是本项目的文件交接约定。小片可以把几部分放同一个文档；名称可不同，制作索引指向实际路径即可。AI负责查找已有材料、补缺和版本同步，用户负责表达意图与既定视觉确认。

| 阶段 | AI读取什么 | AI产生什么 | 进入下一步前核什么 |
|---|---|---|---|
| 接需求 | 用户主题、现有回复、参考 | `brief.md`定位与制作说明 | 观众、要讲清的一件事、长度/画幅/声音、禁用内容、当前阶段 |
| 准备内容 | 原始资料、已有核实出处 | `sources.md`事实及来源；`script.md`观众文稿 | 人名日期数字有依据；删套话；旁白与制作备注分开 |
| 设计 | 文稿、参考片、已批风格 | `style.md`视觉约定；`storyboard.md`逐镜头设计；`assets.json`素材清单 | 每段信息对应可见变化；需要何种图片/档案/示意图明确 |
| 先给图 | 关键镜头设计、可用素材 | 正式样式帧和批准记录 | 沿用用户“先看图”的顺序，未确认不做动态样片 |
| 固定时间 | 已确定是否旁白 | 实际声音时间或阅读时间；`cues.json`共用时间表 | 无旁白按阅读与动作安排；有旁白按实测音频安排 |
| 动态小样 | 批准风格、文稿、素材、时间表 | 10—15秒样片与检查记录 | 至少一个解释动作和一次转场；使用预期声音；用户认可 |
| 完整片 | 已认可样片和完整镜头表 | 分段制作、成片、文稿/来源/验收包 | 导出可读可播、音画对应、外盘归档读回；审美单列 |

`script.md`可有两列：朗读的正文、屏幕上的短句。无旁白版直接用屏幕稿；来源、AI素材说明、内部审核记录留来源文档或必要图注。文稿编写时用humanizer-zh，仍按natural-narration保留事实含义。

可复制[逐镜头设计模板](storyboard-template.md)。分镜至少记录：镜头ID、对应文稿段ID、观众要理解什么、画面类型、开始状态→有效变化→落定结果、下一镜怎么接、所需素材、声音事件。有效变化应增加信息，如突破边界或两方案对照；背景漂浮不算。草案可先按段排，精确秒数后补，不为了假精确填造音频时间。

## 有旁白时的顺序

文稿完成口语编辑 → 核声音可用条件 → 用同段短稿试听 → 用户已认可的音色沿用 → 生成或取得完整录音 → 测实际时长并做文字与声音对齐 → 按实际语义停顿细化镜头和字幕 → 10—15秒动态样片 → 完整片。

静态风格图可先做，不依赖完整录音；正式动态样片必须用将要采用的声音。当前用户尚未要求录制，新稿仅候选，不自动恢复TTS。

选连续表达的合成方式作为候选；如果工具有长度上限，按完整语义段处理并逐接缝听审，不能声称一次合成必然自然。录音漏字、重复或说错专名时先修声音，不能只把识别文本改成脚本而假装音文一致。时间允许真实停顿，不能强行把所有时间间隔填满。时间轴应记录音频与文稿的指纹、短语起止及人工核对状态。

修改一处正文，检查对应声音、时间轴、字幕和分镜是否失效；只改配乐则复用已核画面。当前无旁白影片的秒数不能直接用于新旁白稿。

## 素材与工具接续

优先用本地已做出的镜头：纸带变曲线、区间突破、流程执行等，按表达关系检索；修改文稿前核模板是否仍能准确解释。它们目前是V12/V14具体组件，尚不是可直接套用所有主题的通用库，不能宣称已有自动选镜。

素材清单为每项写ID、作用、实际路径/来源、许可和署名、尺寸或时长、状态（已有/待生成/待用户提供）。缺真实截图就标缺口；选择概念图时明确用途，不能伪造证据。人物角色需要多镜头复用时才建立外形与笔触约定，此期不硬加IP主持人。

文稿 → humanizer-zh；情境图 → 已有imagegen；精确图形/文字与动画 → 已用Remotion；混音和校验 → 已有FFmpeg工作流；前置缺件 → 本Skill检查器。各工具仍须实际可用，不因为写了箭头就声称已自动调用。

外部可选参考：作者[xilo-opus-video](https://github.com/Kianzzz/xilo-opus-video)用于学习制作说明和逐镜检查；[video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft)是按镜头查构图/动效的候选；[HyperFrames官方例库](https://github.com/heygen-com/hyperframes-launches)用于阅读可复用构成。后两者仅核仓库说明、未运行，实际采用前再核具体代码与资产许可。官方例库明确代码许可不覆盖所有媒体与商标，不整库下载资产。现有Remotion能够实现时继续复用。

## 最小制作索引

复制同目录的`production-template.json`到本次制作记录，路径按索引文件所在目录解析。已有文件直接引用。索引本身只是小记录，本机保留；媒体路径必须指向本次核验外盘。资料缺项填null或空字符串，不能用无关文件冒充完成。

- `content`检查：定位、事实来源、文稿存在。
- `sample`检查：再核风格、分镜、素材清单、时间表，以及静态风格批准记录。文稿编辑已完成；有旁白须核真实音频和对齐记录。
- `full`检查：再核用户动态小样认可记录。

检查器只核明确结构和路径；不检测艺术质量、不证明用户真的批准、不检查磁盘身份或媒体内容。操作者先读批准原话，媒体工作前仍调用项目storage预检。没有自动改写旧渲染器，也没有自动安装外部工具。需要缺件就补对应材料，涉及用户审美确认才停在既定确认点。

## 一句话启动

“用code-explainer-video做【主题】，给【观众】看，希望看完理解【一句话】。参考【链接/已有版本】。先复用现有材料，帮我准备自然文稿、分镜和素材清单；先给风格图，再给10—15秒，确认后做全片。声音【沿用/无旁白/希望试听】，全部媒体写已核外盘。”

此提示是本项目原创工作约定，不是文章原prompt。已给的信息不再要求用户填第二遍。

## 声音时间记录示例

`alignment.json`结构如下，单位秒；指纹须从实际文件计算。示例里的空指纹不能通过检查。0.8—1.2秒的停顿是允许的。

```json
{"audio_sha256":"", "script_sha256":"", "segments":[
  {"start":0.0,"end":0.8,"text":"第一句。"},
  {"start":1.2,"end":2.5,"text":"第二句。"}
]}
```

制作索引的`voice.duration_seconds`填实际音频时长；逐句听审后才将`alignment_reviewed`设为true。文件检查只检时间结构与指纹，并不自动完成转写和听审。
