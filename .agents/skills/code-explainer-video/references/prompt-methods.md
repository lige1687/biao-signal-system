## 两篇组合后的实际流程

1. **文稿独立定稿**：先有观众问题、事实及自然表达，用户无需自己准备整套文件；AI整理现有材料，缺关键取舍才问。
2. **导演预编排**：按语义写逐镜内容、A/B角色、时间依据和承接，建立素材需求，不先套模板再塞文稿。
3. **按需求找素材并回填表**：候选与采用分开；某镜选不到合适材料，就改表达或保留缺口，不伪造史料。开始/结束/时长明确到同一时间基准。
4. **确定实际视觉**：角色需要时准备身份/场景/笔触参考；用正式工程、拟入片素材和可编辑图文出代表性静帧；确认后做中间最难15秒。
5. **按表逐段实现**：前景/主体/背景和文字时间独立，保持关注点，动作有准备、发展和停稳。生成角色/实拍/图形可以混用，按内容选择能力。
6. **整片复核**：章节连贯、后半段不退回统一卡片；关键帧、连续播放与声音各自留真实记录，局部改动只重做受影响部分。

## 原文工具与表现能力的分工

T1列出的七类路线也保留为按需选择表；这是能力分类，不是要求每部片全部安装，也不是框架优劣测评。

| 原文路线 | 适用画面 | 本项目选择方式 |
|---|---|---|
| Canvas 2D | 像素、程序化二维图形 | 需要逐点控制时用，清晰文字与坐标单独核 |
| HTML/CSS/SVG | 可编辑排版、曲线、界面变形 | 能在现有工程完成就复用，不依赖真实时间CSS动画 |
| WebGL着色器 | 特定材质、光场或CRT效果 | 先用小段核视觉增量与渲染成本，不全片套滤镜 |
| Three.js | 确实需要空间关系、遮挡与绕行 | 先确认二维是否足够；复杂实物需合适模型与许可 |
| p5.js/p5.brush | 手绘笔触、角色表演 | 参照ClaudeAnimationBase，别牺牲图表精度 |
| Remotion/HyperFrames | 编排、预览和输出 | 现有Remotion优先；读外库不要求切换框架 |
| Manim | 几何、公式及其变换 | 当前无此缺口，不预装；需要时再小样评估 |

T1还提到Playwright、FFmpeg、numpy/scipy以及视频模型人物与代码合成的配合；工程渲染沿用可用能力，用户浏览器操作仍走当前允许的工具。Grok/Flova是原文案例的服务说法，未在本机验证接口或账户。T2提到豆包语音、voxCPM/Voicebox、ChatCut等；仅登记为作者提及的候选，本轮未核其当前价格、接口、可用音色或安装，不因为教程提到而启用旁白。默认配乐继续使用现有登记音源。

## 不直接照搬的参数和流程

| 作者示例/建议 | 本项目处理及理由 |
|---|---|
| 强制三套方案、先一分钟样片 | 已定风格不重开选型；遵守图→难点15秒→全片 |
| 任何镜头都不用外部素材 | 需要实际史料/对象时找可用素材，代码负责精确信息 |
| 固定2.5秒阅读、2—4秒变化、每拍一个动作 | 按实际字数、视觉动作与听读结果安排，静止可有意义 |
| 生成后按固定响度数字处理 | 测量可辅助；音色、混音与手机实际听感仍单独核验 |
| 自评分数达到8就交付 | 改为具体问题与时间点、修复证据和用户认可 |
| 静音不能有空隙、语音文字强行改成原稿 | 保留自然停顿；漏词、错读要核听或重录，不能用字幕遮掩 |
| 波形没有削顶就算声音好 | 只能证明部分技术指标；没听就明确没听 |
| requestAnimationFrame累积推进 | 离线输出须能从指定时间独立复现；累计模拟要预计算或可重建 |
| 每个对象都弹、每镜都运动 | 依材质/意义选择；阅读、对照、结论可以稳定停留 |

## 可直接交给agent的改写Prompt

下面P0—P7按阶段选用，不每次全部跑。所有输出放本期已核外盘目录，源码和必要运行环境按已有规定；继承无品牌、默认配乐、无旁白和用户确认状态。这里提供的是项目制作指令，不扩大安装、付费、发布或跨项目权限。

### P0 制作说明
```text
先读取本期已确认文稿、素材清单、参考链接和批准记录。把已知内容整理为一份制作说明：观众与核心问题、具体规格、保留的视觉特征、拟采用的表现手法、声音模式与素材路径、阶段状态、真正缺少的信息。把事实出处与创作设想分开。对齐已有决定，不重新询问已经明确的内容。指定本期最容易失败的镜头类型，并说明如何用中间15秒检验它。暂不越过当前确认阶段制作。
```

### P1 导演视觉编排
```text
你负责把已定文稿转成镜头。先读完整篇，解释叙事如何推进，再按storyboard-template.md填写全片节奏图与逐镜表。每镜绑定文稿原文和段ID，说明观众此刻需要看到什么、A/B角色及原因、起止和时长、画面主体/景别/构图、具体动作次序、最后停在哪个结果、前后如何承接、素材缺口与声音事件。
无旁白按阅读和动作估时并注明待样片校准；有实际录音时以其时间为准。按完整语义分镜，不按标点切；同类型镜头也要按内容变化。找出没有新增认识的动作、重复版式和读不完的文字，先修正表。只输出本期表与真实缺口，不生成媒体。
```

### P2 为指定镜头挑素材/动效
```text
输入是视觉编排表中的[S镜头]和已核本期素材目录。先把这段话要表达的关系写成一句话，例如从多项筛到少项、两个方法分化、局部变成整体。按library-catalog.md，先查本地已批素材/组件；缺少时只查匹配的案例或镜头卡。
给出少量可比较候选：精确来源及版本、预览或原帖、镜头卡及实现路径、它如何表达该关系、需要改的对象/构图/文字/节奏、依赖与许可状态。不要只报库名，也不要整库搬运。选定后把采用项回填本期素材清单和镜头表；发现没有合适的卡时自己设计，不牺牲文意凑模板。新增媒体等静帧及样例阶段再按批准范围做。
```

### P3 角色与情境（按需）
```text
依据[获批角色参考]与[S镜头]建立必要参考包：角色比例/特征清单，正侧背视图，线条材质细节，场景层次。先判定角色是否真的帮助讲清这段话，没有帮助就不用。
本镜指定一个有理由的视角：角色行动、他人反应、第一人称观察等。写清眼神先看哪、主体做什么、道具怎样响应和下一镜如何接。角色身份和画风稳定，构图随语义变化。历史人物不得编造台词或把生成画面标成史料。生成图只能作素材；正式风格预览仍由视频工程导出，并保持文字/图表可编辑。
```

### P4 连续动作与构图变化
```text
对[S镜头及相邻镜头]设计可以看见的变化，而不是加装饰。写出主体初态、注意力引导、主动作、结果、阅读停留和接力物件；解释各段镜头移动的目的。要连续变形时列出前后轮廓/位置/尺寸/内容映射，安排新旧文字独立退入，避免重叠。需要循环才核首尾位置与速度。
按主体重量和情绪安排起势与停稳；不同层错开反应，避免全体同一曲线同时移动。像素/手绘可让角色姿态较低频变化而镜头平滑，前提是本期风格需要。列出一个更克制的替代方案用于自检：如果删掉该效果仍能表达同样意思，决定它是否有必要。
```

### P5 实现与预检
```text
按获批视觉编排选择现有渲染能力；普通清晰图形优先现有工程，需要空间/手绘/着色器再补对应层，先说明镜头缺口。将时间、字体、随机种子、素材尺寸绑定到本期工程；任意指定时间重复渲染应一致。核所选镜头实现的依赖和坐标系，不把30fps参数直接搬到60fps。
每镜先检查起始/主动作/落定的实际静帧，核中文字体、对象边界和手机可读性。仅在已批准的动态阶段渲染短段，检查运动、转场、音画和素材长度；随后才按阶段许可扩展。只重做受改动影响的片段，记录耗时和失败，不报未经测量的省时比例。
```

### P6 导演验收与局部返修
```text
依据本期制作说明和镜头表，列出实际影片中的最严重问题并给时间范围、可见证据、影响及局部改法。先检查：是否在讲文稿而非换卡片；注意中心是否清楚；中后段版式和速度是否单一；转场是否有前后关系；文字能否读完；素材是否真实且放对地方；声音是否帮助动作。
关键帧用于看布局，正常速度连续片段用于看运动，实际听审用于看声音。哪项未完成就标未完成，不以波形或自评分数代替。修正后核对应段及接点，用户确认仍按原流程，不为追求分数无限循环。
```

### P7 旁白与对齐（用户重新选择旁白才启用）
```text
先用自然口语审稿，再使用已获授权的声音服务制作短试听。记录音色、语速、专名读法和停顿，认可后按服务长度限制选择连续段合成，并核段间一致性。用实际音频建立短语时间轴，核漏词、重复、读错和句尾语气；识别结果与文稿冲突时核真实录音，不能只改字幕掩盖漏读。保留呼吸及有意空白，把真实时间交回导演编排表。服务不可用时说明，不自动付费或安装大型模型。
```
