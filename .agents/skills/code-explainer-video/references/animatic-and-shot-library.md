# 整片节奏、镜头实例与连续审片

当用户认可局部画风，但整片容易拖慢、重复、假收尾，或“动画都有、卡点看不出”时使用。复用当前文稿、分镜、时间表和批准记录；不增加新的用户审批关卡，不替换事实/素材/风格图→15秒→完整片的原约定。

## 结构：先定信息和时长，再复用镜头，最后调动作

**整片层**回答每段新增什么、何时读、何时动、音乐何时收束。完整片已获准制作后，精修前用已批分镜、短句和拟用音乐做低成本连续粗剪（静帧停留加必要占位动作即可），一次从头播放到尾。记录实际位置的拖慢、重复解释、提前收束和来不及阅读，先改段落时长或顺序，再细化运动。仅获准15秒时做本段连续粗剪，并检查其前后文衔接，不提前精修或导出整片；已有获批镜头可直接复用，不重做粗剪。

**镜头层**保存可运行实例，按解释关系检索，而非按“高级、丝滑”等形容词检索。每个实例至少能定位：要解释的关系、所需数据/素材、源码/成片及指纹、进入/阅读停留/退出的时间、镜头锚点和安全区域、声音事件、用户具体认可范围。状态分“候选”“该片已认可”“已知失败”；播放成功不自动转为认可。可复用组件不是把一种构图套所有内容。

**动作层**把镜头移动与主体变化分开：聚焦开始→到位→解释停留→回到总览；数值和比例共用真实进度，装饰可独立缓动。文本在镜头到位后稳定阅读，避免相机、数字、光标同时抢注意。只抽出实际重复使用或本次明确需要的函数，不为一个镜头先搭通用框架。

## 一次连续审片，再定位修复

先在目标平台的实际显示尺寸（可用390 CSS像素宽作为手机预检，不当通用字号标准）正常速度播放导出MP4，不暂停、不靠时间提示识别落点。看能否跟住主对象、读完主张和数字、分清历史与假设；再合声看关键变化是否有可感知的停顿/加速/落定。窄屏仍看不清的必要标签要放大、缩短或改景别，不能只写“放大看”。来源附注可在详情补充，必要边界必须留在画面和正文。

首次连续播放记录具体失效位置，再抽前/中/后帧查碰撞。技术时长、帧数、音轨、零偏移只证明文件和时间，不证明好看、卡拍或叙事清楚。无听审条件明确留待用户判断；用户说未感知，就是该观感目标未通过，不能沿用旧“已完成”话术替代修复。
