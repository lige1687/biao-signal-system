# 代码科普视频

把知识变成能看懂的动作，交付可播放视频、共用时间表和来源。参考片用于提取方法；作品主题、声音和制作范围服从用户当前要求。

## 开工入口：把资料接到制作

先读[前置材料与工作流](references/preproduction-workflow.md)。用户只给主题也能启动，本Skill先补需求摘要、内容事实和自然文稿，再接分镜与制作；不要求用户先交齐文档。已有材料用制作索引引用，避免重写。正式动效前使用`scripts/check_preproduction.py <production.json> --stage sample`核材料，完整片改为`--stage full`；它只核文件与状态，不自动安装/调用配音服务，也不替代内容质量和用户确认。旧版已完成作品不因新检查重跑。

## 固定协作顺序（用户2026-10-08明确）

**需求探讨 → 参考样例拆解 → 静态风格图确认 → 10—15秒动态小样确认 → 完整成片。**

用户已经给过的信息直接沿用；只问尚缺的关键取舍。先交具体可看的产物再请用户评价，不能用计划或文字形容代替样例。用户明确说“先给图”时，本轮不得提前做动画或完整片；用户确认静态图后才进入动态小样，确认小样后才扩展全片。这里的停点来自用户明确要求，不能因技术检查通过自行越过，也不为历史已确认项重复索取确认。

静态图至少覆盖实际需要的主要画面类型（如开场、人物、原理图）；同一套风格应统一。小样包含完整解释动作与一次转场，用实际配乐/音效检验节奏。确认范围分别记录：选中的具体版本、用户原话、允许进入的下一阶段、保留部分和待改部分；一句对原始素材的“不错，继续”只认可该素材，不等于认可尚未展示的三张排版或最终视频。

流程示例、参考来源分级和可复用提示词见[分阶段制作与确认](references/staged-workflow.md)。只在用户另有明确新要求时调整顺序。

## 长期内容约束（用户 2026-10-08 明确）

所有后续视频、封面、字幕、旁白、片头片尾和播放页均不出现 LEI / LeiSignal 名称、标识、口号或隐含的品牌宣传。即使以后讲自有系统，也只讲方法，不透露系统名称。此期只讲趋势交易的来源、历史和编年，不插入自有系统介绍。旧导出保留为历史存档，不能当作符合新要求的交付。

无品牌检查同时看文字源与实际导出；源码内部路径不等于用户可见内容。可见文字集中到内容清单，并运行 `scripts/check_public_text.py`；该检查不能替代图像/声音人工核对。

## 每条视频的外盘归档（用户2026-10-09明确）

所有产生的视频、样片、封面、素材、声音、渲染临时文件和日志都写已核验外接盘；每条视频同时交付定位与描述文件、对应版本的完整文稿、来源及文件清单。按主题 → 视频 → 版本组织，不能只留一个MP4或靠聊天查找。开始制作、改版和交付时读[视频目录与配套文档](references/storage-and-packaging.md)。当前源码、运行环境和小位置索引仍留本机；断盘时停止媒体写入，不创建假挂载目录或回退内盘。已有固定成片路径保留，用目录索引关联；不自行移动或删除旧片。

## 先分清参考证据

读取视频详情、可用转写、关键帧与有关评论，记录时间位置。找原作者的工具或prompt声明，不把评论猜测当事实。自动转写会错认工具名；用画面文字或官方文档复核。只有抽帧或转写时，不能声称完整听看过。

同类效果可以由Remotion、HyperFrames、Canvas、SVG或其他逐帧绘制实现。不要看到动画就断言用了某个框架。已有渲染路径能实现目标时先复用；安装、账号、付费或声音接入不由本skill自动授权。

## 制作顺序

1. 从用户要求提取主题、观众、成片时长、比例、声音选择和交付位置。已有明确要求直接使用，不重复问。
2. 核对内容。给每个名字、日期、数字和历史关系绑定来源。历史发展图说明是思想线索还是实际师承；时代先后不能证明直接传承。金融科普不以历史声望或示意图声称收益。
3. 将内容拆成问题、解释、反差和收束。每个镜头写出观众应理解的一件事、画面主体、主体怎样变化、可读停留、音乐和音效事件。不要把文案逐段放进同一种卡片。
4. 挑符合主题的视觉语言，遵守上方用户指定的确认顺序。已有认可的风格沿用，换风格时重新给相关静态图；小样未解决的主要问题先修复，用户认可小样后再扩展全片。
5. 为画面和声音使用同一份时间表。有旁白时先测实际时长，无旁白时按文字阅读与动作设计时长。轻敲对应落点，纸声对应翻页，笔声对应描线；重要观点出现时给画面和声音留白。
6. 实际渲染、完整解码、查看导出关键帧、打开播放页。分别记录文件检查和用户观感；不能把脚本启动、工具success或图检通过叫作主观效果已解决。

参考学习的验收是动作与信息的对应，不是配色相似。V6 的纸张配色和固定卡片布局虽通过文件检查，仍被用户否定。抽取连续片段，标记主体、视角、信息落点实际怎样变化；不能把单张风格帧当成剪辑学习完成。历史人物优先核实可用档案照片，不以低细节卡通头像代替人物质感。

镜头移动时分别核查主体和标签：人物出画不应连带裁掉姓名；图表缩小让位时，坐标和解释不能被画框截断。V7 的姓名与图表标签裁切已修正；最终实帧还发现开头价格线压到说明文字，另做局部修复。三类问题都要求看实际导出，不能只读布局代码。示例源码在 `docs/ops/media/trend-trading-60s-20261008/v7/studio/src/`，交付状态查同目录上级的 `production-notes.md`。

## 让动作承担解释

- 描线：逐段显露有意义的轨迹，而非反复淡入标题。
- 连续性：同一物件换到下一镜头的新角色，例如报纸折成记录簿、记录簿展开为规则表；镜头变化后仍看得懂关系。
- 层次：前景标签、中景主体、背景时间线可有不同速度。先给观众视觉落点，再增加细节。
- 强调：用圈画、划线、局部移动或短暂放大指向关键部分，保留真实比例与语义。
- 人物：允许原创示意插画；不把它标成真实历史照片或复制他人角色。
- 图表：需要时直接绘制清晰矢量或原生高分辨率图形；用户取消真实案例时改用明确注明的概念示意。

Remotion动画由当前帧驱动，避免CSS时间动画导致离线渲染与预览不同；SVG组件按需要动的部分分组，二维解释足够时不为炫技引入3D。若用其他绘制器，同一时间点也应生成相同画面。

已认可风格后要提升连续叙事、素材表达或减少返工时，读[连续镜头与制作效率](references/continuity-and-efficiency.md)。该方法要求实际物件承接和分段核验，不把特效数量、工具名称或账号额度变化当作质量与效率证明。

## Prompt与时间表

用户反馈信息密度低时，使用[信息密度与编年史方法](references/density-and-chronology.md)：每站必须新增一个认识，用持续的主体变化解释它，再核对阅读时间。V8的结构增量有秒数与节点数记录，主观效果未因这些计数自动通过。

复用[references/prompts-and-cues.md](references/prompts-and-cues.md)里的可改写prompt和共用时间表示例。工具差异与教程证据看[references/tutorial-methods.md](references/tutorial-methods.md)。不要把模板中的主题、时长、无旁白或纸张风格当成所有视频的固定要求。

制作前与修改后运行`python3 scripts/check_cues.py <cue-plan.json>`核对帧数、镜头区间与声音落点。它只检查时间结构，不判断史实、艺术质量或版权。

## 旁白说人话（用户2026-10-09明确）

所有旁白稿在配音前做自然口语改写，优先用可用的humanizer-zh技能；具体方法和本期例子见[自然旁白](references/natural-narration.md)。旁白只讲观众要理解的内容，删掉“以下是文意概括”“此处仅作示意”“来源详见播放页”等制作/审核说明，以及反复免责、套话和提纲腔。来源、授权和制作备注留配套文档；必要素材标识放合适位置，不机械读出来。删掉说明后仍需保留事实成立所必需的条件，不能把概括说成原话、暗示直接师承或保证收益。先把稿子写得能自然讲出来，再处理音色；不能把旧无旁白片或未录制新稿说成已完成配音。

## 可读与声音核验

文字在目标播放尺寸下看得清，标签不挡主体。检查实际导出而非仅看源码图。若要4K，在4K绘制文字和线条，不能把低清素材放大后叫作高清；原图与有损预览明确区分。

音乐与素材保存来源和适用许可，交付所需署名及改动说明。正常使用现有许可录音；不因参考片用某首歌就默认有权复用。未听审原片时，音效位置可以建议，原片音色和配乐名称保持未确认。

文件验收优先用已安装探测工具；某个工具缺失可用完整解码和浏览器元数据替代并注明。记录失败、实际播放、输入与输出指纹、额度起止。账号额度是共享显示值，差值不能冒充单任务精确费用。
